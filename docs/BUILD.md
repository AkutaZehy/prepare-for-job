# 本仓库是如何构建的

回答三个问题：内容从哪来、页面怎么造、质量怎么保证。页面规格的细节在 [SPEC.md](SPEC.md)，一个真实的批量铺量 prompt 样例在 [PROMPT-SAMPLE.md](PROMPT-SAMPLE.md)。

## 构建模式：规格先行 + 样板锁定 + AI 批量铺量

本仓库由 AI 辅助批量构建：人负责定规格、写样板、做验收；AI 负责按规格批量产出页面。整个流程分四步：

1. **立规格**：先写清页面结构、标题约定、判分交互、代码语言规则、题目来源原则（见 [SPEC.md](SPEC.md)），所有后续产出都以它为唯一标准。
2. **样板先行**：每类先人工打磨 7 个金标准页（如 TCP 三次握手、两数之和 ACM 样板、Self-Attention），把风格、密度、交互细节全部锁定。样板的价值是让后续批量产出"照着抄"而不是"自由发挥"。
3. **批量铺量**：按大类分批推进，每批 12~18 页。产出方式是「两个并行 AI 子代理 + 人工同步书写」：给每个子代理的 prompt 包含金标准样板路径、硬规则清单和逐页大纲，要求逐字复制样式与判分脚本、只新建指定文件、汇报时列出所有自由裁量点。
4. **校验闭环**：每批收口前做四道检查——结构校验（grep 标题格式、判分 DOM 配对、来源白名单）、算法样例实跑（每个 ACM 程序的样例输入输出实际运行核对）、浏览器交互巡检（判分/公式/图渲染/链接）、公开前泄漏扫描（绝对路径、用户名、会话信息等 grep 清单）。

几个量化事实（2026-09-30 全量完工）：112 页中 7 页为人工样板、约六成由 AI 子代理产出、约三成半人工同步书写；全站站内链接 184 条全部可达；算法/手撕/Python 输出题的样例 100% 实跑核对后落盘。

## 参照的项目

动工前调研过一批"交互式学习"类仓库，最终吸收的主要有：

- **[hello-algo](https://github.com/krahets/hello-algo)**（《Hello 算法》）：图解优先的排版思路——知识点能画图就不堆文字，以及"一页一主题"的信息密度控制。本站的 Mermaid 图 + ASCII 回退双保险，动机与它一致。
- **[developer-roadmap](https://github.com/kamranahmedse/developer-roadmap)**（roadmap.sh）：按岗位组织考点路线、按高频排序铺量的思路。本站的四大类划分与 PAGES.md 底账管理受它启发。
- **[d2l-ai](https://github.com/d2l-ai/d2l-zh)**（《动手学深度学习》）：讲原理必配可运行代码的风格。深度学习与手撕编程题两个子夹的"公式 + 代码 + 可判题样例"三件套由此而来。

判分交互、页面模板、进度系统为本仓库自研（无框架，见下）；LeetCode / 牛客的 ACM 输入输出约定、408 统考的题型分布则作为出题格式参考。

## 技术选型：为什么是纯静态 HTML

- **零依赖、双击即用**：不用任何框架和构建链，`file://` 协议直接可用。清单数据通过 `<script src="checklist.js">` 加载而非 fetch，避开 file:// 下的 CORS 限制。
- **内容即文件**：一个知识点一个 HTML 文件，天然适合批量生成、逐文件 diff 校验、按文件夹组织分类，也方便按需增删。
- **手写判分脚本**：全站共用一段 40 行的原生 JS（从金标准页逐字复制到每一页），不用现成 Quiz 库——样式完全可控，且避免引入构建步骤。
- **CDN 标准件 + 降级**：MathJax 3 与 Mermaid 11 走 CDN，均有断网降级方案（公式显示原文；图回退 ASCII，两份内容成对写入、按渲染成败二选一保留），保证离线可读。

## 想复现这套流程

按顺序读 [SPEC.md](SPEC.md) → [PROMPT-SAMPLE.md](PROMPT-SAMPLE.md)，核心经验有三条：规格和样板越死，批量产出越稳；给 AI 的 prompt 必须包含"逐字复制的部分"和"自由裁量的部分"两栏，并要求汇报裁量点；AI 产出的每道题样例都要实际运行核对，结构检查代替不了实跑。
