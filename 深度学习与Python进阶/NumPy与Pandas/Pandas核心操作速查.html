Pandas 核心操作速查

适用岗位：AI 开发、数据分析、测开(Python) ｜ 形态：速查 + 输出判断 + 工程坑（数据岗笔试主力） ｜ 更新：2026-09-30
要点速记：loc 按标签、iloc 按位置——标签切片含右端、位置切片不含；运算按索引对齐，对不齐出 NaN；groupby = split-apply-combine；merge 是按键连接（SQL 式）、concat 是沿轴堆叠；缺失值算术向 NaN 传播、聚合默认 skipna；链式赋值 df[cond][col] = x 不生效（老版本警告 SettingWithCopyWarning，CoW 时代是 ChainedAssignmentError）——写回一律 df.loc[mask, col] = …。

一、知识点梳理

Series / DataFrame 与索引对齐

  • Series = 带标签的一维数组（构建于 NumPy，见 NumPy广播索引与向量化）；DataFrame = 共用行索引的列集合。
  • 两个 Series 运算按索引对齐而不是按位置，对不齐的位置填 NaN——本机实跑：{'a': nan, 'b': 12.0, 'c': 23.0, 'd': nan}。
  • dict 传入构造时，键顺序即 Series 顺序（dict 保序自 Python 3.7 起写入语言规范）。

loc vs iloc：标签 vs 位置

Python 
df = pd.DataFrame({"v": [10, 20, 30, 40]}, index=["a", "b", "c", "d"])

df.loc["a":"c", "v"]    # 10 20 30 —— 标签切片【含】右端 c
df.iloc[0:2, 0]         # 10 20    —— 位置切片【不含】下标 2
  • loc 接标签、布尔掩码；iloc 只接整数位置。取"前 n 行"这类位置语义用 iloc，按行列名取用 loc。

布尔过滤与 query

Python 
df[df["v"] > 10]                       # 布尔掩码
df[(df["v"] > 10) & (df["dept"] == "A")]   # 多条件必须加括号
df.query("v > 10 and dept == 'A'")     # 字符串写法，长条件更可读

groupby：split-apply-combine

  • split 按键切开 → apply 聚合/变换 → combine 拼回结果。本机实跑：
Python 
df = pd.DataFrame({"dept": ["A", "B", "A", "B", "A"],
                   "pay":  [10, 20, 30, 40, 50]})

g = df.groupby("dept")["pay"].sum()
print(g)
# dept
# A    90        # 10+30+50
# B    60        # 20+40
# Name: pay, dtype: int64
print(g.index.tolist())    # ['A', 'B'] —— 默认 sort=True 按组键排序

print(df.groupby("dept")["pay"].agg(["sum", "mean"]))
#       sum  mean
# dept
# A      90  30.0
# B      60  30.0
  • 常用聚合：count/size/sum/mean/max/min/nunique；transform 输出与原表同形（组内标准化用）。

merge / join / concat：键连接 vs 轴拼接

Python 
df1 = pd.DataFrame({"k": ["a", "b"], "x": [1, 2]})
df2 = pd.DataFrame({"k": ["a", "c"], "y": [3, 4]})

pd.merge(df1, df2, on="k")          # 按键做 SQL 式连接，how 默认 inner
#    k  x  y           →  只有 a 匹配上，shape (1, 3)
# 0  a  1  3

pd.concat([df1, df2], axis=1)       # 沿轴 1 左右拼，shape (2, 4)
pd.concat([df1, df2], axis=0, ignore_index=True)
# 上下堆 4 行：列取并集，对不上的格子填 NaN（默认 outer）
  • merge：按键（列或索引）连接，how = inner/left/right/outer；join 是"按索引 merge"的快捷方式；concat：沿轴堆叠，axis=0 上下、axis=1 左右。

缺失值：传播与 skipna

  • 算术运算向 NaN 传播（10 + NaN = NaN）；聚合默认 skipna=True 跳过缺失——本机实跑：Series([1, nan, 3]).sum() = 4.0，isna().sum() = 1。
  • 工具：isna/notna 检测、fillna(0)/ffill/bfill 填充、dropna() 丢弃。先 isna().sum() 摸清缺口再决定填法，别拿 0 盲填。

apply vs 向量化：apply 慢，优先内置

  • apply 是 Python 层逐行/逐元素回调，带函数调用开销，比内置向量化慢一到两个量级。
  • 优先级：数值列直接整列运算 → np.where/map(dict) 替换 → str/dt 访问器（df["s"].str.upper()）→ 实在无法向量化的复杂行逻辑才 apply。

经典坑（本机 pandas 3.0.5 实测）

Python 
dfc = pd.DataFrame({"a": [1, 2, 3], "b": [0, 0, 0]})

dfc[dfc["a"] > 1]["b"] = 9      # 链式赋值：第一步返回的是临时副本
# 告警 ChainedAssignmentError，且赋值【不生效】—— b 保持 [0, 0, 0]
# （pandas 3.0 起默认 Copy-on-Write；老版本这里的告警名是 SettingWithCopyWarning）

dfc.loc[dfc["a"] > 1, "b"] = 9   # 正确姿势：一次索引写回 → [0, 9, 9]
  • 低基数字符串列 astype("category") 省内存：20 万行两值字符串实测 1600132 字节 → 200148 字节（约 8 倍），groupby/排序也更快。
  • 索引对齐坑：两表相加按索引对齐，索引没 reset 会"叉乘"出一堆 NaN，算前先想清楚索引状态。

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

import pandas as pd

df = pd.DataFrame({
    "dept": ["A", "B", "A", "B", "A"],
    "pay":  [10, 20, 30, 40, 50],
})
g = df.groupby("dept")["pay"].sum()
print(g["B"])
print(g.index.tolist())
A. 60 和 ['A', 'B']
B. 90 和 ['A', 'B']
C. 60 和 ['B', 'A']（按组键出现顺序）
D. 抛出 KeyError
答案 A。split-apply-combine：A 组 10+30+50=90，B 组 20+40=60，g["B"]=60；groupby 默认 sort=True 按组键排序，索引是 ['A', 'B']。本机 pandas 3.0.5 实跑核对。来源：牛客经典题。

单选2. 关于 loc 与 iloc 的切片行为，正确的是（  ）

A. df.loc["a":"c"] 含右端标签 c；df.iloc[0:2] 不含右端位置——标签闭区间、位置左闭右开
B. loc 与 iloc 的切片都是左闭右开
C. df.iloc[0:2] 取的是标签为 0 和 2 的两行
D. loc 只能接布尔数组，不能接标签切片
答案 A。本机实跑：索引 ['a','b','c','d'] 的表，loc["a":"c"] 得 [10, 20, 30]（3 行），iloc[0:2] 得 [10, 20]（2 行）。C 错：iloc 是纯位置语义与标签无关；D 错：loc 的主业就是标签（外加布尔掩码）。来源：面试高频改编。

单选3. 以下代码输出（  ）

s = pd.Series([1, np.nan, 3])
print(s.sum())
print(s.isna().sum())
A. 4.0 和 1 —— 聚合默认 skipna=True；isna 得到布尔序列，求和即缺失个数
B. nan 和 1 —— sum 也向 NaN 传播
C. 4.0 和 0
D. 抛出 ValueError
答案 A。算术运算向 NaN 传播，但 sum/mean 等聚合默认 skipna=True 跳过缺失（1+3=4.0）；要保留 NaN 语义需显式 skipna=False。数缺失个数的惯用法就是 isna().sum()（True 求和）。本机 pandas 3.0.5 实跑核对。来源：牛客经典题。

多选4. 关于 merge 与 concat，正确的有（  ）

A. merge 按键（列或索引）做 SQL 式连接，how 默认 inner
B. concat 沿轴堆叠：axis=0 上下接、axis=1 左右接，默认保留所有索引（outer）
C. merge 后的行数一定等于两表行数之和
D. concat(axis=1) 对不上的索引位置填 NaN
答案 ABD。C 错：merge 行数由键匹配方式（how）决定，与两表行数之和无关。本机实跑：df1(k,x) 与 df2(k,y) 在 on="k" 下 inner 连接得 (1,3) 只剩 a；concat(axis=1) 得 (2,4)；concat(axis=0) 上下堆 4 行、列并集补 NaN。来源：面试高频改编。

面试口述5. 拿到一个 1GB 的 CSV 要读进 pandas 处理，第一步做什么？怎么让后续处理不吃满内存？

参考回答第一步永远是"先看再算"：不要直接 read_csv 全量读。先用 nrows=1000（或 usecols 挑几列）读个样本，看 dtypes、列含义和 memory_usage(deep=True)，心里有谱再定策略。
瘦身的常规四招：① 指定 dtype——低基数枚举列转 category（20 万行两值字符串实测省 8 倍），数字列能 float32/int32 就降档；② usecols 只读真正要用的列；③ 日期列 parse_dates 现场解析，别留字符串；④ 真的大就 chunksize 分块流式读、逐块聚合，或一次性转 Parquet，之后按列存读取又快又省。
加分点：engine="pyarrow" 解析更快；千万行级先问"该不该进数据库/列存"而不是硬读；读完后 isna().sum() 和 describe 各跑一遍再动手。来源：AI 岗笔试高频。

四、易错点小结

① 链式赋值 df[cond][col]=x 不生效，写回一律 df.loc[mask, col]=… 一次索引到底（CoW 时代告警 ChainedAssignmentError，老版本是 SettingWithCopyWarning）。② loc 标签闭区间、iloc 左闭右开，前 n 行用 iloc。③ 运算按索引对齐、聚合默认 skipna——sum 结果"少数"先查 NaN。④ merge 键连接 vs concat 轴拼接，merge 默认 inner、concat 默认 outer。⑤ apply 慢一到两个量级，先想整列运算/np.where/str 访问器。⑥ 低基数列 astype("category")，groupby 前先 reset_index 想清楚索引状态。
