魔法方法与内存管理

适用岗位：AI 开发、测开(Python)、通用软开 ｜ 形态：概念 + 输出判断（__new__/__init__ 与 str/repr 是高频坑） ｜ 更新：2026-09-30
要点速记：__new__ 造实例、__init__ 只负责初始化（单例重写 __new__）；print 走 __str__，容器里的元素走 __repr__（没定义 __str__ 时 print 也回退 __repr__）；with 靠 __enter__/__exit__；内存 = 引用计数为主（归零立即回收）+ 分代 GC 兜循环引用（三代）；__slots__ 砍掉实例 __dict__ 省内存；del 只是删名字减引用，不保证对象立刻释放——循环引用要等 GC（本机实跑 gc.collect() 返回 2）。

一、知识点梳理

构造与析构：__new__ vs __init__

  • __new__(cls)：静态地创建实例并返回；返回的不是本类实例，__init__ 就不会被调用。
  • __init__(self)：在已创建的实例上初始化，只准返回 None。顺序：先 __new__ 后 __init__。
  • __del__：引用归零时被调，但时机不保证（解释器退出阶段甚至可能不调）——关键资源释放用 with，别押在析构上。
Python 
class Single:
    _instance = None
    def __new__(cls):
        if cls._instance is None:                 # 第一次才真正创建
            cls._instance = super().__new__(cls)
        return cls._instance                      # 之后永远返回缓存实例

print(Single() is Single())   # True（本机实跑）—— 单例的标准姿势

字符串化：__repr__ vs __str__

方法给谁看谁触发
__str__用户，要求可读print()、str()；未定义时回退 __repr__
__repr__开发者，要求无歧义（约定能还原）交互式回显、容器内的元素、调试器
Python 
class P:
    def __new__(cls):
        print("new")
        return super().__new__(cls)
    def __init__(self):
        print("init")
    def __str__(self):
        return "str!"
    def __repr__(self):
        return "repr!"

p = P()        # new → init（先创建后初始化）
print(p)       # str!     —— print 走 __str__
print([p])     # [repr!]  —— 容器里的元素一律走 __repr__

属性：__getattr__ vs __getattribute__

  • __getattribute__：一切属性访问都要经过它（默认 C 实现），Python 层重写等于每次访问都交税，且极易递归死循环（内部必须 super() 兜底）。
  • __getattr__：只在常规查找失败后兜底调用——懒加载、代理、Mock 对象的标配，安全得多。

上下文管理与可调用

  • with obj as x: → 先 x = obj.__enter__()，块结束（含异常）必调 __exit__(exc_type, exc, tb)；open、Lock、事务都靠它保证"一定收尾"。
  • __call__：定义了它的实例可以像函数一样 obj(...)——类装饰器、带状态回调的标准实现（见 作用域闭包与装饰器）。

运算符重载举例

Python 
class Vec:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __add__(self, other):          # 使 v1 + v2 合法
        return Vec(self.x + other.x, self.y + other.y)
    def __repr__(self):
        return f"Vec({self.x}, {self.y})"

print(Vec(1, 2) + Vec(3, 4))   # Vec(4, 6)
  • 同族：__eq__(==)、__len__(len())、__getitem__(下标/切片)、__iter__(for 遍历，见 迭代器与生成器)。

内存管理：引用计数为主，分代 GC 兜底

  • 引用计数：每个对象记录"有多少引用指着我"，减到 0 立即回收。所以 del a 的语义是"删名字、减引用"——还有别人指着，对象就活着；这就是 del ≠ 立即 free。
  • 循环引用：两个对象互相引用，外部名字全删光后彼此计数仍是 1，引用计数束手无策。分代 GC（三代 0/1/2）定期扫描容器对象的可达性，把不可达的环整体回收：新对象在 0 代，扛过收集次数就晋升下一代。
Python 
import gc

class Node: pass

gc.collect()                 # 先清场，保证下面的数字只反映本次实验
a, b = Node(), Node()
a.ref, b.ref = b, a          # 互相引用成环
del a, b
print(gc.collect())          # 2 —— 循环引用对象此刻才被分代 GC 回收

c1, c2 = Node(), Node()
del c1, c2
print(gc.collect())          # 0 —— 无环对象早被引用计数收走了
  • __slots__ 省内存原理：类里声明 __slots__ = ("x", "y") 后，实例不再有 __dict__（每个实例一个 dict 很占地），属性放进固定槽位——百万级小对象能省一半以上内存；代价：不能动态加属性，需要 weakref 时要显式加 "__weakref__"。
  • weakref 一句：弱引用不增加引用计数，对象死了拿到 None——缓存、观察者模式用它防内存泄漏。
  • 对象在"共享引用"下的行为细节见 可变不可变与深浅拷贝。

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

class P:
    def __new__(cls):
        print("new")
        return super().__new__(cls)
    def __init__(self):
        print("init")
    def __str__(self):
        return "str!"
    def __repr__(self):
        return "repr!"

p = P()
print(p)
print([p])
A. new、init、str!、[repr!]
B. init、new、str!、[str!]
C. new、init、repr!、[repr!]
D. new、init、str!、[str!]
答案 A。创建顺序是先 __new__（造实例）后 __init__（初始化）；print(p) 走 __str__，但容器里的元素一律用 __repr__。只有当 __str__ 未定义时，print 才回退到 __repr__。本机 Python 3.12.9 实跑输出 new / init / str! / [repr!]。来源：面试高频改编。

单选2. 要实现单例模式（一个类全程只有一个实例），应该（  ）

A. 重写 __init__，在里面检查 self 是否已存在
B. 重写 __new__，第一次创建后缓存到类属性 _instance 并永远返回它
C. 重写 __del__ 阻止实例被销毁
D. 用一个 global 变量保存实例即可，无需重写任何方法
答案 B。__new__ 才是"造实例"的那一步，只有在这里控制返回缓存的 _instance 才拦得住新实例；__init__ 在每个新实例上都会被调用，拦不住创建。裸 global 也拦不住 P() 继续造新对象。本机实跑 Single() is Single() → True。来源：面试高频改编。

单选3. 一个类只定义了 __repr__（返回 "repr!"），没有定义 __str__。print(obj) 输出（  ）

A. 报错：print 必须要求类实现 __str__
B. 默认地址，形如 <__main__.P object at 0x…>
C. repr!：__str__ 缺省时回退调用 __repr__
D. 空字符串
答案 C。__str__ 未定义时 print/str 回退到 __repr__。反过来只定义 __str__：容器里的元素仍显示默认地址——所以调试场景的最佳实践是至少定义 __repr__。来源：牛客经典题。

多选4. 关于魔法方法，正确的有（  ）

A. with 语句要求对象实现 __enter__ 与 __exit__
B. len(obj) 实际调用 obj.__len__
C. __getattr__ 在每次属性访问时都会被调用
D. 定义了 __call__ 的实例可以像函数一样被调用
答案 ABD。C 错：每次访问都经过的是 __getattribute__；__getattr__ 只在常规查找失败后兜底，常用于懒加载/代理，且不易递归、开销小。D 正是类装饰器（带状态的装饰器）的实现基础。来源：牛客经典题。

面试口述5. Python 是怎么处理循环引用的？为什么 del 之后对象可能还占着内存？

参考回答主力机制是引用计数：每个对象记录指向它的引用数，减到 0 立即回收——所以绝大多数对象 del 掉名字就释放了，del 的语义只是"删名字、减引用"，不是 free()。
循环引用是引用计数的盲区：两个对象互相引用，外部名字删光后彼此计数仍是 1，永远到不了 0。兜底是 CPython 的分代 GC（三代 0/1/2）：把容器对象按存活时间分代，周期性做可达性扫描，把不可达的环整体回收；新对象在 0 代，扛过收集次数晋升下一代，扫描频率递减。
本机实跑（Python 3.12.9）：两个互相引用的 Node，del 后 gc.collect() 返回 2（此刻才被回收）；无循环的对照组同样操作返回 0（早被引用计数收走）。
加分点：低基数大量小对象用 __slots__ 去掉实例 __dict__ 省内存；缓存/观察者用 weakref 弱引用防泄漏；gc.disable() 的服务要特别小心环；真正持有限资源的场景用 with 而不是指望 __del__。来源：AI 岗笔试高频。

四、易错点小结

① __new__ 返回什么，__init__ 就在什么上初始化；返回非本类实例时 __init__ 根本不执行。② print 走 __str__、容器元素走 __repr__、str 缺省回退 repr——背成"外 str 内 repr"。③ 重写 __getattribute__ = 每次属性访问交税还容易死循环，兜底需求用 __getattr__。④ del 只删名字减引用，循环引用要等分代 GC，关键资源释放靠 with。⑤ __slots__ 省内存但有代价：不能动态加属性、要用 weakref 得显式留槽。⑥ 单例、工厂、不可变对象定制，动手处都在 __new__。
