迭代器与生成器

适用岗位：AI 开发、测开(Python)、通用软开 ｜ 形态：概念 + 输出判断（yield 执行顺序是笔试常客） ｜ 更新：2026-09-30
要点速记：Iterable 有 __iter__，Iterator 还要有 __next__；for 循环本质 = iter() 拿迭代器 + 反复 next() + 捕获 StopIteration；生成器函数被调用时函数体一行不跑，第一个 next 才执行到第一个 yield 暂停；生成器惰性、省内存、一次性——耗尽后再取是空；本机实测：10⁶ 元素生成器表达式对象 200 字节，同规模 list 仅外壳就 8448728 字节。

一、知识点梳理

Iterable vs Iterator：两层协议

角色协议要求例子
可迭代 Iterable实现 __iter__（返回一个迭代器）list、tuple、str、dict、set、文件对象
迭代器 Iterator实现 __iter__ + __next__（取下一个，没了抛 StopIteration）iter([...]) 的返回值、生成器、zip/enumerate/map/filter 的返回值
  • iter(obj) 就是去调 obj.__iter__()；迭代器自己的 __iter__ 返回自身，所以迭代器既是 Iterable 也是 Iterator。
  • list 本身没有 __next__，for 之所以能遍历它，是因为 for 先用 iter() 把它包成迭代器。
Python 
from collections.abc import Iterable, Iterator

print(isinstance([1, 2], Iterable))        # True
print(isinstance([1, 2], Iterator))        # False：list 没有 __next__
print(isinstance(iter([1, 2]), Iterator))  # True：iter() 才拿到迭代器

# for x in obj 的本质等价展开：
it = iter(obj)              # ① 拿迭代器
while True:
    try:
        x = next(it)        # ② 逐个取
    except StopIteration:   # ③ 取完收工，for 正常结束
        break

生成器函数：yield 暂停与恢复

  • 函数体里出现 yield，它就成了生成器函数：调用它不执行函数体，只返回一个生成器对象。
  • 每次 next(g)：从上次暂停处继续执行，到下一个 yield 处暂停并交出值；函数自然结束（或 return）→ 抛 StopIteration。
Python 
def f():
    print("A")
    yield 1
    print("B")
    yield 2

g = f()          # 函数体一行不跑，只拿到生成器
print("start")
print(next(g))   # 打印 A，输出 1 —— 执行到第一个 yield 暂停
print(next(g))   # 打印 B，输出 2 —— 从暂停处恢复
next(g)          # 函数结束，抛 StopIteration

生成器表达式 vs 列表推导：惰性省内存

  • 语法差一个括号：[x*x for x in data] 列表推导（立刻算完、占内存）；(x*x for x in data) 生成器表达式（返回生成器、用到才算）。
  • 内存实测（本机 Python 3.12.9）：(i*i for i in range(10**6)) 的生成器对象 sys.getsizeof = 200 字节；同规模列表推导 = 8448728 字节（约 8.4MB，仅外壳，不含每个 int 对象的 ~28 字节）。
  • 选型：只遍历一遍的大流水线 → 生成器；要反复遍历、len()、切片、随机访问 → list。

一次性消费坑：迭代器耗尽后是空的

Python 
it = iter([1, 2, 3])
print(sum(it))   # 6
print(sum(it))   # 0 —— 迭代器已耗尽，sum 对空序列返回 0
print(list(it))  # []

z = zip([1, 2], "ab")     # zip/enumerate/map/filter 返回的都是一次性迭代器
print(list(z))            # [(1, 'a'), (2, 'b')]
print(list(z))            # []
  • 典型翻车：把迭代器当参数传给两个函数、或存进实例属性被两处遍历——第二次遍历拿到空气。复用前先 list() 落地，或每次重新 iter()。

扩展一句：g.send(v) 向当前暂停点喂值（y = yield x 的 y 接住）；g.close() 在暂停点抛 GeneratorExit 提前收尾；yield from 子生成器 委托遍历并自动透传 send/异常（PEP 380，Python 3.3 起）。enumerate(lst)、zip(a, b) 是"惰性版"工具：不复制序列、边走边发 (下标, 元素) / (对, 对)。协程一脉的演化与适用场景见 GIL与并发模型选型；生成器函数也是函数对象，闭包与绑定机制见 作用域闭包与装饰器。

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

def f():
    print("A")
    yield 1
    print("B")
    yield 2

g = f()
print("start")
print(next(g))
A. A、start、1 —— 调用 f() 时函数体先执行到 yield 1
B. start、A、1 —— 调用 f() 只创建生成器，print("start") 先输出，next 才启动函数体
C. start、A、B、1 —— next 一次会把函数体跑完
D. start、1、A —— yield 先交值再执行 print
答案 B。有 yield 的函数是生成器函数：调用它不执行函数体，只返回生成器对象；next(g) 把函数体从开头执行到第一个 yield 处暂停并交出 1，所以顺序是 start → A → 1。继续 next 两次：先 B、2，再 StopIteration。本机 Python 3.12.9 实跑核对。来源：牛客经典题。

单选2. for x in obj 能正常工作，obj 至少要提供（  ）

A. __next__ 方法
B. __iter__ 方法返回一个迭代器（迭代器自身还需实现 __next__）
C. __getitem__ 方法
D. __len__ 方法
答案 B。for 的第一步是 iter(obj)（即 obj.__iter__()）拿迭代器，随后反复 next 直到 StopIteration。list/dict 自己没有 __next__，靠 iter() 被包成迭代器。__getitem__ 的老式序列协议也能被 for 兼容，但标准答案是 __iter__ + __next__ 两件套。来源：面试高频改编。

单选3. 以下代码输出（  ）

it = iter([1, 2, 3])
print(sum(it))
print(sum(it))
A. 6 和 6
B. 6 和 0
C. 0 和 0
D. 第二次 sum 抛出 StopIteration
答案 B。迭代器是一次性的：第一次 sum 消费完，第二次拿到已耗尽的迭代器，sum 对空序列返回 0（StopIteration 被 sum 内部消化）。zip/enumerate/map/filter 的返回值同样一次性——复用前先 list() 落地。本机实跑核对。来源：牛客经典题。

多选4. 关于惰性求值与生成器，正确的有（  ）

A. 生成器表达式 (x*x for x in range(10**7)) 创建时几乎不占内存，元素用到才计算
B. zip()、enumerate()、map() 返回的都是惰性迭代器
C. 生成器可以反复遍历，每次从头开始
D. 生成器函数被调用时，函数体立即执行到第一个 yield
答案 AB。C 错：生成器一次性，耗尽即空；D 错：调用生成器函数只返回生成器对象，函数体到第一个 next 才执行。本机实测 10⁶ 元素：生成器表达式对象 200 字节 vs 列表推导外壳 8448728 字节。来源：面试高频改编。

面试口述5. 生成器为什么省内存？什么场景该用，什么场景不该用？

参考回答省内存的原因：生成器同一时刻只持有"一个当前元素 + 执行状态（局部变量、指令位置）"，不像 list 要把全部元素立刻算出来并装箱进内存——本机实测 10⁶ 元素，生成器表达式对象 200 字节，列表推导仅外壳就 8.4MB（还不含元素本身）。
该用：① 大文件逐行处理（open 默认就是惰性按行迭代）；② 多段数据流水线（读 → 清洗 → 聚合，用生成器串起来，全程只有一个元素在流动）；③ 无限/未知长度的序列（实时数据流）；④ 只遍历一次的大批量任务。
不该用：要反复遍历、len()、切片、随机访问、或要把结果交给多个消费方 → 用 list 先落地；结果本身很小时，省内存收益为零，可读性优先。
加分点：yield from 组合多级流水线；生成器是协程的底层来源（async/await 的前身），被 next 驱动、可在 yield 处暂停恢复——与 GIL 页 asyncio 一脉相承。来源：AI 岗笔试高频。

四、易错点小结

① 生成器函数调用 ≠ 执行：函数体到第一个 next 才跑。② 迭代器一次性：zip/enumerate/map/filter 的返回值同理，二次遍历拿到空——复用先 list()。③ Iterable（__iter__）与 Iterator（__iter__ + __next__）是两层：list 是 Iterable 不是 Iterator。④ 生成器表达式圆括号、列表推导方括号；只遍历一遍选前者。⑤ next(g, default) 可以兜住 StopIteration；⑥ 判断类型用 collections.abc 的 Iterable/Iterator，别用 abc.Iterable（旧路径已弃用）。
