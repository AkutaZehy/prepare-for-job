作用域、闭包与装饰器

适用岗位：AI 开发、测开(Python)、通用软开 ｜ 形态：概念 + 输出判断 + 面试手写装饰器 ｜ 更新：2026-09-30
要点速记：变量查找按 LEGB（Local → Enclosing → Global → Built-in）顺藤摸瓜；在函数里给名字赋值它就是 local，改外层要 nonlocal、改模块要 global；闭包 = 内函数引用外层变量，且外层函数已返回——变量活在 cell 对象里；循环里建的 lambda 全部晚绑定同一个变量，返回后调用得 [2, 2, 2]，用默认参数 i=i 固化；装饰器 = @ 语法糖等价 f = deco(f)，functools.wraps 保元信息，带参装饰器三层嵌套：收参数 → 收函数 → 收调用参数。

一、知识点梳理

LEGB：变量查找的四站顺序

层级全称含义
LLocal当前函数内部（含参数）
EEnclosing外层（嵌套）函数的作用域
GGlobal模块（文件）级名字
BBuilt-in内置名（print、len…），最后一站
  • 赋值即本地：函数内对名字赋值（没有 global/nonlocal 声明），这个名字就是 local——哪怕赋值语句在 print 之后，也会报 UnboundLocalError 而不是去外层找。
  • global x：函数内赋值写进模块级；nonlocal x：写进上一层函数的变量（Python 3 引入的关键字，Python 2 只有 global）。
Python 
x = 1
def f():
    x = 2                 # f 的局部变量，与模块级 x 无关
    def g():
        print(x)          # g 只读：按 LEGB 找到 Enclosing（f 的 x = 2）
    g()

f()        # 2
print(x)   # 1 —— 模块级 x 从未被改动

def outer():
    n = 0
    def step():
        nonlocal n        # 声明：改的是 outer 的 n
        n += 1
        return n
    return step

c = outer()
c(); c()
print(c())   # 3 —— 闭包计数器：n 一直活在 cell 里

闭包（closure）

  • 定义：内层函数引用了外层作用域的变量，并且外层函数已经返回——变量没有死，而是被装进 cell 对象，随返回的函数对象一起活下来（fn.__closure__ 可见）。
  • 价值：把"状态"挂在函数上而不必写成类，计数器、缓存、装饰器都靠它。
  • 本质与"变量绑定"同源，传参、共享可变对象的坑见 可变不可变与深浅拷贝 一页。

late binding 坑：闭包绑定的是变量，不是取值那一刻

Python 
funcs = []
for i in range(3):
    funcs.append(lambda: i)     # 三个 lambda 引用的是【同一个】变量 i

print([f() for f in funcs])     # [2, 2, 2] —— 循环结束后 i = 2，调用时才去取

funcs_fix = [lambda i=i: i for i in range(3)]   # 默认参数在 def 时求值，当场固化
print([f() for f in funcs_fix]) # [0, 1, 2]
  • 三个 lambda 的 __closure__ 里是同一个 cell，循环结束时 i=2，谁被调用谁去 cell 里现取——这叫晚绑定（late binding），与 Python 版本无关。
  • 修复思路：在绑定时就把值固定下来，最惯用的是默认参数 i=i（默认值在 def 时求值一次，原理见 可变不可变与深浅拷贝 的默认参数一节）。

装饰器：函数是对象，@ 是语法糖

  • Python 里函数是一等对象：可以赋值给变量、当参数传、当返回值——这是装饰器的全部地基。
  • @deco 上面放 def f()，等价于 f = deco(f)：包装发生在 def/import 时，只执行一次；之后每次调用 f() 走的都是包装后的函数。
  • 堆叠 @a @b：自下而上包装、自上而下执行——@a @b def f 等价 f = a(b(f))。本机实跑：def 时打印 B、A；调用时打印 a-in、b-in。
Python 
def d_a(fn):
    print("A")
    def wa():
        print("a-in")
        fn()
    return wa

def d_b(fn):
    print("B")
    def wb():
        print("b-in")
        fn()
    return wb

@d_a
@d_b
def hi():
    print("hi")
# def 时刻立刻打印：B、A（b 先包装，a 再包 b 的结果）

hi()   # 调用时刻打印：a-in、b-in、hi（外层包装先执行）
  • functools.wraps 保元信息：不加的话包装函数的 __name__、__doc__ 全变成 wrapper——调试、文档、按函数名注册路由（Flask/FastAPI）、多进程 pickle 函数都会出问题。写装饰器必带。
Python 
import functools, time

def timed(unit="ms"):
    def deco(fn):                       # 第二层：接住被装饰函数
        @functools.wraps(fn)            # 保住 __name__/__doc__ 等元信息
        def wrapper(*args, **kwargs):   # 第三层：接住调用参数
            t0 = time.perf_counter()
            try:
                return fn(*args, **kwargs)
            finally:
                cost = (time.perf_counter() - t0) * (1000 if unit == "ms" else 1)
                print(f"{fn.__name__} 耗时 {cost:.1f}{unit}")
        return wrapper
    return deco                          # 第一层：接住装饰器参数

@timed(unit="ms")
def work(n):
    return sum(range(n))

work(10**6)            # work 耗时 21.3ms（数值随机）
print(work.__name__)   # work —— wraps 生效，不是 wrapper
  • 带参装饰器 = 三层嵌套：@timed(unit="ms") 先执行 timed(unit="ms") 返回真正的装饰器 deco，再由 @ 包装函数。三层职责口诀：外层收参数、中层收函数、内层收调用参数。
  • 类装饰器一句：实现 __init__(self, fn) 与 __call__ 的类实例也能当装饰器用，需要跨调用保存状态（如限流、重试计数）时首选。

二、考点说明

笔试选择输出判断面试手写

  • 输出判断：循环闭包 late binding、global/nonlocal 改的是哪一层、装饰器打印顺序。
  • 概念选择：LEGB 顺序、@ 的等价变换、闭包变量存活机制、wraps 的作用。
  • 面试手写：计时/日志/重试装饰器，带参版三层嵌套是必背题；追问点在 wraps 和装饰时机。

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

funcs = []
for i in range(3):
    funcs.append(lambda: i)

print([f() for f in funcs])
A. [0, 1, 2]，每个 lambda 记住了自己当时的 i
B. [2, 2, 2]，三个 lambda 晚绑定同一个变量 i，循环结束时 i=2
C. [3, 3, 3]，range(3) 最后 i 停在 3
D. [0, 0, 0]，lambda 未调用前 i 不可见
答案 B。闭包绑定的是变量 i 本身而不是取值那一刻（late binding）：三个 lambda 的 __closure__ 里是同一个 cell，循环结束后 i=2，调用时才去取。固化写法：lambda i=i: i（默认参数在 def 时求值，见 可变不可变与深浅拷贝）。本机 Python 3.12.9 实跑输出 [2, 2, 2]。来源：面试高频改编。

单选2. @a 叠在 @b 上面装饰 def f（即 @a @b def f），等价于下列哪种变换？（  ）

A. f = a(b(f))：b 先包装 f，a 再包装 b 的结果
B. f = b(a(f))：a 先包装 f
C. f 被 a 和 b 各自独立包一次，互不影响
D. @ 只是注释，运行时没有任何效果
答案 A。装饰器自下而上包装、调用时自上而下穿过。带打印的实测（见知识点）：def 时刻输出 B、A，调用 f() 时输出 a-in、b-in。提醒：包装发生在 def/import 时只执行一次，不是每次调用都重新装饰。来源：AI 岗笔试高频。

单选3. 以下代码输出（  ）

x = 1
def f():
    x = 2
    def g():
        print(x)
    g()

f()
print(x)
A. 2 和 1
B. 2 和 2
C. 1 和 1
D. UnboundLocalError
答案 A。g 里对 x 只有"读"，按 LEGB 在 Enclosing（f 的局部）找到 2；f 的赋值 x = 2 造的是 f 的局部变量，与模块级 x 无关，最后一行输出 1。要让 f 改模块级 x 需声明 global x；要改上一层函数的 x 需 nonlocal x（Python 3 起）。来源：牛客经典题。

多选4. 关于作用域与闭包，正确的有（  ）

A. 函数内对变量赋值，该变量默认成为局部变量，除非声明 global/nonlocal
B. nonlocal 声明的变量在 Enclosing（外层函数）作用域查找
C. 闭包引用的外层变量在外层函数返回后仍存活，存在 cell 对象中
D. global x 声明后，对 x 的赋值写进的是 builtins 模块
答案 ABC。D 错：global 对应 LEGB 的 G（模块级），Built-in 只是查找的最后一站、与 global 无关。C 是闭包的定义：变量装进 cell 随函数对象存活，fn.__closure__ 可查看。来源：牛客经典题。

面试口述5. 手写一个带参计时装饰器 timed(unit="ms")：打印被装饰函数的耗时，要求函数元信息（__name__ 等）不变，并说明三层嵌套各自接住什么。

参考回答核心是三层嵌套：外层收装饰器参数、中层收被装饰函数、内层收调用参数，用 functools.wraps 保元信息。
Python 
import functools, time

def timed(unit="ms"):
    def deco(fn):                       # 第二层：接住被装饰函数
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):   # 第三层：接住调用参数
            t0 = time.perf_counter()
            try:
                return fn(*args, **kwargs)
            finally:
                cost = (time.perf_counter() - t0) * (1000 if unit == "ms" else 1)
                print(f"{fn.__name__} 耗时 {cost:.1f}{unit}")
        return wrapper
    return deco                          # 第一层：接住装饰器参数

@timed(unit="ms")
def work(n):
    return sum(range(n))
讲解顺序：@timed(unit="ms") 先执行 timed 拿到 deco（第一层），@deco 再包装 work（第二层），调用 work(...) 时进入 wrapper（第三层）。加分点：perf_counter 是单调高精度时钟，比 time.time 适合测耗时；try/finally 保证函数抛异常也打印；漏掉 wraps 会丢 __name__/__doc__，路由注册、序列化都会踩坑；装饰在 def 时执行一次，每次调用走的是 wrapper。来源：面试高频改编。

四、易错点小结

① 循环里造闭包默认晚绑定，要固化用 i=i 默认参数。② 函数内赋值即 local，"先读后赋值"报 UnboundLocalError；改外层 nonlocal、改模块 global，别混。③ 装饰器忘 functools.wraps 是最常见的手写扣分点。④ 带参装饰器是三层不是两层：收参数 → 收函数 → 收调用参数。⑤ 装饰发生在 def/import 时、只执行一次；堆叠时自下而上包装、自上而下执行。⑥ 闭包变量活在 cell 里，多次调用工厂函数得到的是各自独立的 cell（闭包计数器互不串台）。
