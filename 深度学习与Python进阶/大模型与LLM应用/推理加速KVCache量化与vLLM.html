推理加速：KV Cache/量化/vLLM

适用岗位：AI/Agent 开发（推理部署方向） ｜ 形态：显存算式 + 机制拆解 + 对比表 ｜ 更新：2026-09-30
要点速记：因果注意力让历史 K/V 永不变 → KV cache 每步只算增量；显存 = 2×层数×KV头×head_dim×seq×batch×字节（7B/fp16/4096 上下文 ≈ 2GB，GQA 8 组降到 512MB）；MQA 全部 Q 共享 1 组 KV、GQA 分组共享；量化三层面：权重量化（INT8/INT4，算法记 GPTQ/AWQ 各一句）+ KV cache 量化；vLLM 两大件：PagedAttention 分页管 KV 显存防碎片 + continuous batching 迭代级调度提吞吐（均 2023）；投机解码 = 小模型起草、大模型验证，不改输出分布。

一、知识点梳理

KV cache 为什么能成立：因果注意力下，位置 i 的 K/V 只由 ≤i 的前缀决定——token 一旦生成，它的 K/V 永不再变。于是把历史 K/V 全部缓存，每步只算新 token 的 Q/K/V 并与缓存拼接做注意力，单步从"重算整段前缀"降为"只算增量"（注意力机制细节见 Self-Attention 与 Transformer）。双向结构做不到这一点——这也是 decoder-only 的推理红利。

显存估算式（笔试计算题模板）：

$$M_{\text{KV}} = 2 \times L \times H_{\text{kv}} \times d_{\text{head}} \times s \times b \times c$$

2 = K 与 V 两份；L 层数；H_kv KV 头数；d_head 每头维度；s 序列长度；b batch；c 每元素字节数（fp16=2、INT8=1）。7B 数字例（LLaMA-7B 规格：32 层、32 头、head_dim=128，fp16，单条 b=1，4096 上下文）：每 token 约 512KB，整条 4096 上下文约 2GB；换成 GQA（8 组 KV 头）降到约 512MB。上下文越长 KV 越大——它直接决定单卡能塞多少并发、能拼多少检索片段（RAG 链路见 RAG 从原理到落地）。

# KV 显存（字节）= 2 * 层数 * kv头数 * head_dim * 序列长 * batch * 每元素字节
L, Hkv, dh, s, bz, c = 32, 32, 128, 4096, 1, 2   # LLaMA-7B fp16 MHA
kv = 2 * L * Hkv * dh * s * bz * c
print(kv / 2**30)      # 2.0 GiB —— 约 512 KB/token
print(kv / 4 / 2**30)  # 0.5 GiB —— GQA 8 组 KV 头，缩到 1/4

MQA / GQA：省 KV 的头：

方案KV 头数KV cache 大小质量与使用
MHA（标准多头）= Q 头数基准质量基准，cache 最大
GQA（分组查询，2023）分成若干组共享（如 8 组）按组数等比缩小质量接近 MHA，主流大模型标配（LLaMA-2 70B、LLaMA-3）
MQA（多查询，2019）全部 Q 共享 1 组最省质量损失最明显

量化三层面：

层面做法代表 / 说明
权重量化权重存成 INT8/INT4，降显存也降访存PTQ 训练后量化免重训；配合反量化算子推理
量化算法逐层压量化误差GPTQ：基于 Hessian 的逐层误差补偿；AWQ：激活感知，保护少数重要通道
KV cache 量化KV 存成 INT8/FP8长上下文时 KV 是显存大头，直接砍半到四分之一；注意 KV 数值分布不稳的精度问题

此外还有激活量化（W8A8 等）与"权重+激活同量化"的组合，思路同源：拿数值精度换显存与带宽。

vLLM 两大件（2023）：

  • PagedAttention：传统实现按"最大长度"给每条请求预分配连续 KV 显存 → 内部碎片（预留没用满）+ 外部碎片（释放后零散难复用）+ 无法共享。借鉴操作系统虚拟内存分页：KV 切成固定大小 block，逻辑连续、物理离散，按需分配 + 页表映射；相同前缀还能共享物理块（prefix sharing）。显存利用率和吞吐大幅提升。
  • continuous batching：传统 static batching 要一批全部生成完才换下一批，短请求干等长请求、GPU 空转；continuous batching 做迭代级调度——完成的请求即时退出、排队的新请求随时插入，GPU 始终满载，吞吐显著提升。
  • 投机解码（speculative decoding，2023）一句：小模型（draft）快速起草若干候选 token，大模型一次前向并行验证，按接受/拒绝采样修正——输出分布与大模型单独解码一致，是"抽查"不是"换答案"。

二、考点说明

面试必问计算题推理部署

  • KV cache 为什么能缓存——答"因果性"才算懂；给模型规格会算显存。
  • MQA/GQA 在省什么、代价是什么、哪些模型在用。
  • 量化三层面别混：权重量化 / 量化算法（GPTQ、AWQ 各一句）/ KV cache 量化。
  • vLLM 两大件各自解决什么：PagedAttention 管显存碎片、continuous batching 管吞吐。
  • 追问：投机解码为什么加速却不改输出分布；PagedAttention 为什么还能帮 beam search/并行采样省显存（前缀共享物理块）。

三、示例题目（点击选项即时判分）

单选1. 自回归生成时可以把历史 token 的 K、V 缓存复用，其根本原因是（  ）

A. 注意力得分矩阵是对称矩阵，可存一半算一半
B. 因果注意力下，位置 i 的 K/V 只由前缀决定，前缀生成完就不再变化
C. 推理阶段模型参数固定不变，所有中间结果都可复用
D. softmax 归一化之后不需要再计算
答案 B。causal mask 保证每个位置的表示只依赖自己与左侧；token 一旦生成，它的 K/V 永久不变 → 每步只需算新 token 的 Q/K/V 并与缓存拼接。A 错（注意力矩阵不要求对称）；C 的参数不变与"中间结果能复用"是两回事。来源：面试高频改编。

单选2. GQA（分组查询注意力）的做法与收益是（  ）

A. 多个 Q 头共享一组 K/V 头，KV cache 与访存显著变小，效果介于 MHA 与 MQA 之间
B. 把 Q 头分成多组，各组用不同的模型分别计算再融合
C. 只缓存 Q 不缓存 K/V，从而省下大部分显存
D. 用分组卷积替代注意力计算
答案 A。MHA 的 KV 头数 = Q 头数、cache 最大；MQA 全部 Q 共享 1 组 KV、省到极致但质量有损；GQA 折中，是 LLaMA-2 70B / LLaMA-3 等主流模型的标配。注意 Q 头数不变、变的是 KV 头数。来源：AI 岗笔试高频。

多选3. 关于 LLM 推理加速手段，正确的有（  ）

A. PagedAttention 用分页方式管理 KV 显存，减少碎片、提高显存利用率
B. continuous batching 按迭代级调度请求，完成即退、新请求随时插入，提高吞吐
C. 权重量化（INT8/INT4）降低权重显存与访存开销
D. 投机解码会改变模型的输出分布，上线前需要重新校准
答案 ABC。D 错——投机解码是"小模型起草、大模型并行验证"，通过接受/拒绝采样保证输出分布与大模型单独解码一致，加速不改分布。A、B 是 vLLM 两大件（管显存 vs 管调度），C 是量化家族。来源：面试高频改编。

计算4. 某模型规格：32 层、32 个 KV 头、head_dim=128、fp16。单条请求（batch=1）、上下文 4096 时，KV cache 占多少显存？若改用 GQA 只保留 8 组 KV 头呢？

先自己算，再展开对答案每 token 每层 KV = 2×32×128×2字节 = 16,384 B；全模型 = ×32 层 = 524,288 B/token（512 KB）；×4096 token = 2 GiB。GQA 8 组：KV 头数缩到 1/4 → 128 KB/token → 512 MiB。检查方法：公式里"2"（K/V 两份）和"×32 层"最容易漏，单位先统一成字节最后再换 GiB。来源：牛客经典题。

面试口述5. PagedAttention 解决什么问题？一句话讲清它的机制。

参考回答解决 KV cache 显存的管理问题：传统实现按最大长度给每条请求预分配连续显存，产生内部碎片（预留没用满）和外部碎片（释放后零散块难复用），批量服务时利用率很低。机制（vLLM，2023）：借操作系统虚拟内存分页——KV 切成固定大小的 block，逻辑上连续、物理上离散，按需分配、页表映射，还能让相同前缀的请求共享物理块（prefix sharing）。它与 continuous batching 互补：一个管显存、一个管调度，共同把吞吐打上去。来源：面试高频改编。

四、易错点小结

① KV 显存公式里的"2"是 K/V 两份、还要"×层数"，两头最容易漏；单位先算字节再换 GiB；② GQA 省的是 KV 头数，Q 头数不变——别答成"减少注意力头"；③ 量化省显存也省带宽，但精度损失要按任务敏感度评估，不是无脑 INT4；④ PagedAttention 是"管理方式"的革命：不减少 KV 总量，而是减少浪费；⑤ continuous batching（调度）与 PagedAttention（显存）是两件事，答成一件会露怯；⑥ 投机解码的价值主张是"分布不变地变快"，说它改输出分布直接错。
