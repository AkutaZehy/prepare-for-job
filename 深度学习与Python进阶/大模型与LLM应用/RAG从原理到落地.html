RAG 从原理到落地

适用岗位：AI/Agent 开发（面试必问 + 场景选择题） ｜ 形态：架构图 + 全链路拆解 + 选型对比 ｜ 更新：2026-09-30
要点速记：RAG = 检索增强生成——先从知识库检索相关片段，再让 LLM基于片段作答；对症五个痛点：幻觉、知识截止、私有知识、可溯源、比微调省；链路背顺序：加载清洗→切块→Embedding→向量库→召回 Top-K→重排→拼 Prompt→生成；双塔快而糙、cross-encoder 准而慢，所以先召回后重排；知识常更新/要溯源选 RAG，改风格与领域行为选微调，两者可叠加。

一、知识点梳理

为什么需要 RAG（五个痛点逐条对）：① 幻觉——模型自由生成会编造事实，限定"仅依据检索到的资料回答"显著缓解；② 知识截止——训练数据有截止日期，而知识库可随时增删、即时生效；③ 私有知识不可见——企业内部文档不在训练语料里，也没必要为它重训；④ 答案可溯源——答案能标注"引用了哪几个片段"，可人工核查（企业落地硬需求）；⑤ 比微调便宜——不用 GPU 训练和数据标注，知识更新 = 更新库。

离线建库：文档 → 切块(chunk+overlap) → Embedding → 入向量库
在线生成：query → 召回 Top-K → 重排 Rerank → 拼 Prompt → LLM 生成 → 答案（可溯源）
（向量库由离线侧写入，在线侧只从库中召回）

  • ①② 离线：加载清洗与切块：文档（PDF/Word/网页）解析成纯文本并清洗（去页眉页脚乱码，清洗不干净后面全白搭）；切块 chunking——块太小丢上下文（召回回来的片段模型看不懂），块太大稀释相关度（一段里有效内容占比低，向量被平均冲淡，还挤占 Prompt 窗口）；按语义/标题层级切优于定长切，相邻块留 overlap 防句子被切断。
  • ③④ 离线：Embedding 与向量库：Embedding 模型把文本映射为高维向量，语义越近向量距离越近；入库时相似度用余弦或内积（向量归一化后两者等价——实现细节）；索引常用 HNSW：图结构的近似最近邻（ANN）索引，用一点点召回率换数量级检索提速（实现细节）。
  • ⑤⑥ 在线：召回与重排（本页核心考点）：召回用双塔 bi-encoder——query 与文档各自独立编码，文档向量可离线预计算，快，但两段文本互不见面、精度有限；重排用 cross-encoder——把 query 和文档拼在一起联合编码打分，准但慢得多，只能对召回的小集合（几十条）做。生产链路固定是"快模型大海捞针，慢模型精挑细选"。
  • ⑦⑧ 在线：拼 Prompt 与生成：系统指令 + 检索片段 + 用户问题拼成 Prompt，通常要求"仅依据资料作答并标注引用编号"；LLM 生成带引用的答案。
  • 进阶优化三件套：混合检索——BM25 关键词一路 + 向量一路，各取 Top-K 再融合排序（向量路管同义改写，关键词路兜住专有名词/型号/编号——这些恰是 Embedding 弱项）；query 改写——口语化、省主语、带指代的问题先改写成适合检索的形式；评估——检索侧看命中率 / Recall@K（需要的片段进没进 Top-K），生成侧看忠实度（答案是否忠于检索片段）。排查顺序先检索后生成：检索不对，生成再好也是空中楼阁。

RAG vs 微调：

维度RAG微调
知识时效更新知识库即时生效需重新训练，周期长
可溯源答案可标注引用片段难以给出出处
成本建库 + 检索服务GPU 训练 + 标注 + 版本管理
擅长答事实、查资料、给依据改输出风格/格式、塑造领域行为

向量库选型一句话：FAISS（本地库，原型/单机）、Milvus（分布式，大规模生产）、PGVector（复用 Postgres，运维省心）——口径："按数据规模与运维成本选"。RAG 与微调不冲突：微调教"怎么答"，RAG 供"答什么"，可叠加。

Python 
# 极简 RAG 骨架（示意流程，不依赖任何具体框架）
docs   = load_files("knowledge/")                        # 1. 文档加载
texts  = [clean(d) for d in docs]                        #    清洗：去噪/去格式
chunks = []
for t in texts:
    chunks += split_by_heading(t, size=400, overlap=50)  # 2. 切块：语义/标题切 + 重叠

embedder = EmbeddingModel()                              # 3. Embedding 模型
store    = VectorDB(metric="cosine")                     # 4. 向量库（余弦相似度）
store.add(embedder.encode(chunks), chunks)               #    向量与原文一起入库

def ask(question):                                       # ---- 在线：每次提问 ----
    q_vec   = embedder.encode([question])[0]             # 5. 查询向量化
    top_k   = store.search(q_vec, k=10)                  #    召回 Top-K（粗筛）
    refined = cross_encoder.rerank(question, top_k)[:3]  # 6. 重排（精排取前 3）
    prompt  = PROMPT.format(context=join(refined),       # 7. 拼 Prompt
                            question=question)
    return llm.generate(prompt)                          # 8. 生成（要求带引用）

二、考点说明

面试必问场景选择题AI 岗笔试

  • 链路顺序默写级：八步链路给打乱步骤排顺序；"先召回还是先重排"不能答反。
  • 场景选择：给一段业务描述，判断用 RAG 还是微调——AI 岗面试高频开场题。
  • rerank 原理：双塔 vs cross-encoder 的编码方式与快慢取舍。
  • 典型面试追问清单：
    • 为什么不直接拿 cross-encoder 扫全库？——全库联合编码代价爆炸，召回负责把候选从百万级降到几十条。
    • chunk 大小怎么定？——没有万能值，按文档类型调参并用 Recall@K 验证。
    • 专有名词检索不准怎么办？——混合检索，BM25 那一路兜底。
    • RAG 效果怎么评估？——检索侧命中率 / Recall@K，生成侧忠实度。
    • 向量库怎么选？——FAISS 本地、Milvus 分布式、PGVector 复用 Postgres。
    • RAG 和微调二选一吗？——不冲突，常叠加使用。

三、示例题目（点击选项即时判分）

单选1. 企业内部知识库每天更新大量文档，且要求答案能标注出处供人工核查，最合适的方案是（  ）

A. 对 LLM 做微调，把内部知识训练进模型参数里
B. 搭建 RAG：文档切块入库，检索相关片段拼进 Prompt 再生成
C. 每天重新预训练一个小模型
D. 调高 temperature，让模型自由发挥补全知识
答案 B。知识每天更新 → 微调每次都要重训、无法即时生效；要求可溯源 → 只有 RAG 能标注引用片段，微调答不出出处。微调适合改风格与领域行为，不适合装"频繁更新的知识"。来源：面试高频改编。

单选2. 已有双塔模型做向量召回，为什么还需要重排（cross-encoder）？（  ）

A. 双塔把 query 与文档分别独立编码、互不交互，精度有限；cross-encoder 联合编码更准但慢，只适合对召回的小集合做
B. 双塔只能处理英文，cross-encoder 才支持中文
C. 重排能把向量库数据重新写盘，加快下次检索
D. cross-encoder 参数更多，重排顺便完成了大模型微调
答案 A。双塔快在"文档向量可离线预计算"，但 query 与文档编码时互不见面，只能算出粗粒度相似度；cross-encoder 把两者拼在一起过同一模型，交互充分、打分准，代价是每个 query-文档对都要现场算，扫全库不可行——所以固定"召回粗筛 + 重排精选"。来源：AI 岗笔试高频。

单选3. 下列步骤已打乱：①拼 Prompt ②Embedding ③切块 ④召回 Top-K ⑤文档加载与清洗 ⑥重排 ⑦生成 ⑧入向量库。正确顺序是（  ）

A. ⑤③②⑧④⑥①⑦
B. ⑤②③⑧④⑥①⑦
C. ⑤③②⑧⑥④①⑦
D. ⑤③⑧②④⑥①⑦
答案 A。⑤加载清洗 → ③切块 → ②Embedding → ⑧入向量库 → ④召回 Top-K → ⑥重排 → ①拼 Prompt → ⑦生成。B 错在先 Embedding 后切块（必须先切块再向量化，整篇文档一个向量会稀释语义）；C 错在重排跑到召回前面（没有召回结果可排）；D 错在先入库后向量化。来源：面试高频改编。

多选4. RAG 主要解决 / 改善哪些问题？（  ）

A. 缓解幻觉：限定模型基于检索到的片段作答
B. 知识截止：知识库可随时更新、即时生效
C. 私有知识不可见：内部文档入库即可被检索
D. 答案可溯源：答案可标注引用了哪些片段
E. 改变模型说话的风格与输出格式
答案 ABCD。E 是微调的活——RAG 只影响"模型看到什么资料"，不改模型本身的风格与格式偏好。记忆口径：RAG 管"答什么"，微调管"怎么答"。来源：AI 岗笔试高频。

面试口述5. 切块 chunk 的大小与 overlap 怎么权衡？为什么不建议纯定长切？

参考回答块太小：片段缺上下文，召回回来模型读不懂、答不全；块太大：块内有效内容占比被稀释，向量相似度变"钝"，还会挤占 Prompt 窗口。overlap 让跨块边界的句子在相邻两个块里各出现一次，防止语义被切断。切分策略上优先按语义边界（标题层级、段落、句子）切，纯定长切只做兜底；chunk 大小没有万能值，按文档类型调参、用检索侧 Recall@K 验证效果。来源：面试高频改编。

四、易错点小结

① 重排是"对召回结果精排"，不替代召回——顺序是先④召回后⑥重排，答反即错；② 双塔快在文档向量可离线预计算，cross-encoder 慢在每个 query-文档对都要现场联合编码——取舍记"快模型捞针、慢模型挑针"；③ chunk 不是越大越好也不是越小越好，两头的坏处要都能说出来；④ BM25 不是过时技术，专有名词/编号场景它比向量强，混合检索是标配答法；⑤ 评估先看检索侧 Recall@K——检索不行，生成无从谈起；⑥ 别拿微调硬刚"知识频繁更新"，那是 RAG 的主场；微调改的是风格与行为，不是知识时效。
