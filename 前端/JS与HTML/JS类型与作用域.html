JS 类型与 == 陷阱、作用域

适用岗位：前端（笔试选择 + 输出题必考） ｜ 形态：知识点 + 输出题实跑核对 ｜ 更新：2026-09-30
要点速记：类型 7+1——原始 7 种（number/string/boolean/undefined/null/symbol(ES6)/bigint(ES2020)）+ object；typeof null === "object" 是历史 bug 且永远不修；== 转换三连：null == undefined 为 true、NaN 与谁都不等（含自己）、[] == false 为 true 而 [] == [] 为 false；面试口径一律 ===；var 函数作用域 + 提升（undefined），let/const 块级作用域 + TDZ（声明前访问直接报错）；0.1+0.2 !== 0.3 是 IEEE 754 浮点误差。

一、知识点梳理

数据类型：7 种原始类型 + object：原始类型按值访问、值不可变；object 是引用类型（普通对象、数组、函数、Date 等），比较的是引用地址而非内容。

JavaScript 
console.log(typeof null);          // "object"  ← 历史坑
console.log(typeof undefined);     // "undefined"
console.log(typeof function(){});  // "function"
console.log(typeof 1, typeof 'a', typeof true, typeof Symbol(), typeof 10n);
// "number" "string" "boolean" "symbol" "bigint"

typeof 的历史坑：JS 第一版实现用数据底层表示的低位标记类型，对象的标记是 000，而 null 是全零指针，于是 typeof null 被误判为 "object"——为了兼容海量旧页面永远无法修复。反过来，判断 null 只能用 v === null。函数是唯一 typeof 返回 "function" 的类型，也是区分"可调用对象"的最可靠手段。

== 的隐式转换规则表（笔试坑王）：宽松相等在比较前会做类型转换，规则链长且反直觉，记住下面几行就够应付绝大多数题。

表达式结果原因
null == undefinedtrue规范特批：这一对互相相等，且各自只与对方（和自身）相等
null == 0 / null == falsefalsenull 不向数字/布尔转换，只认 undefined
NaN == NaNfalseNaN 与任何值都不等，包括自己；判断要用 Number.isNaN
[] == falsetrue双方转数字：[].toString() 是空串、Number('') 是 0；false 也是 0
'1' == 1true字符串转数字后比较
[] == []false引用类型比较地址，两个独立对象地址必不同

为什么面试让全用 ===：== 的转换规则复杂难记、结果反直觉，容易把 [] == false 这类"意外成立"埋进代码变成难查的 bug；=== 类型与值都相同才成立，语义明确。工程惯例的唯一例外：x == null 等价于 x === null || x === undefined，用于同时排除两种空值。

var 提升 vs let/const TDZ：var 是函数作用域，声明会被"提升"到函数顶部并初始化为 undefined；let/const 是块级作用域（{}），声明前的一段时间叫暂时性死区 TDZ——访问直接抛 ReferenceError，是"报错"而不是 undefined。

JavaScript 
console.log(a);  // undefined（var 提升，赋值不提升）
var a = 1;
console.log(b);  // ReferenceError: Cannot access 'b' before initialization
let b = 2;
const c = 3;     // const 声明时必须初始化；绑定不可重赋，对象内容仍可改

常考输出题：let 循环 vs var 循环（本机 node 实跑核对）：

JavaScript 
for (var i = 0; i < 3; i++) setTimeout(() => console.log('var', i));
for (let j = 0; j < 3; j++) setTimeout(() => console.log('let', j));
// 实跑输出：var 3 / var 3 / var 3 / let 0 / let 1 / let 2

原因：var 的 i 在整个函数级作用域里只有一份绑定，回调执行时循环早已结束；let 每轮迭代为 j 创建一个新绑定，回调捕获的是那一轮的值。

0.1 + 0.2 !== 0.3：IEEE 754 双精度用二进制表示小数，0.1 和 0.2 都是无限循环小数，相加后实际是 0.30000000000000004。正确比较用容差：Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON。

二、考点说明

笔试选择输出判断题面试必问

  • 笔试：typeof 返回值（null 坑）、== 转换真假判断、var/let 提升与 TDZ、浮点误差——输出判断题高频出镜。
  • 面试：为什么用 === 不用 ==、原始类型与引用类型存储差异、const 到底锁什么、let 循环为什么输出 0 1 2。
  • 追问储备：symbol/bigint 的用途（唯一键 / 大整数，ES2020）；Number.isNaN 与全局 isNaN 区别（后者先转数字，isNaN('a') 是 true）；0.1+0.2 的解决口径（EPSILON 容差或先乘 10 取整）。

三、示例题目（点击选项即时判分）

单选1. console.log(typeof null, typeof undefined, typeof function(){}); 的输出是（  ）

A. "null" "undefined" "function"
B. "object" "undefined" "function"
C. "object" "object" "function"
D. "object" "undefined" "object"
答案 B。typeof null 是 "object"——JS 第一版用低位标记类型，null 是全零指针被当成对象标记，为兼容旧页面永不修复（历史坑）；判断 null 只能 v === null。函数是唯一返回 "function" 的类型。来源：牛客经典题。

单选2. 下列表达式中结果为 true 的是（  ）

A. NaN == NaN
B. null == 0
C. [] == false
D. [] == []
答案 C。A：NaN 与任何值都不等，包括自己；B：null 只与 undefined（和自身）相等，不向数字转换；D：引用类型比较地址，两个独立对象必不相等。C：== 触发转数字——[].toString() 为空串、Number('') 为 0，false 也转 0，0 == 0 成立。来源：面试高频改编。

多选3. 关于 var 与 let/const，正确的有（  ）

A. var 存在提升，声明前访问得到 undefined
B. let 存在 TDZ，声明前访问直接抛 ReferenceError
C. const 声明的对象，其属性值不可修改
D. let 声明的 for 循环，每一轮迭代都会创建一个新的循环变量绑定
答案 ABD。const 锁的是"绑定不可重新赋值"，对象内容可以照常改（const arr = [1]; arr.push(2) 合法），C 错。D 正是 let 循环回调输出 0 1 2、var 输出 3 3 3 的原因。来源：面试高频改编。

输出判断4. 下面代码的输出是（  ）

JavaScript 
console.log(typeof null);
console.log([] == []);
console.log(0.1 + 0.2 === 0.3);
A. "object" / true / true
B. "object" / false / false
C. "null" / false / true
D. "object" / true / false
答案 B。本机 node 实跑：object、false、false。[] == [] 比较的是两个不同对象的地址；0.1+0.2 实际是 0.30000000000000004（IEEE 754 二进制无法精确表示 0.1/0.2），与 0.3 严格相等不成立，判断要用 Number.EPSILON 容差。来源：牛客经典题。

面试口述5. var 的提升和 let/const 的 TDZ 有什么区别？为什么 var 循环里的异步回调输出 3 3 3，let 循环却输出 0 1 2？

参考回答var 是函数作用域，声明提升到函数顶部并初始化为 undefined，所以声明前访问不报错；let/const 是块级作用域，声明前处于暂时性死区，访问直接抛 ReferenceError——语义更严格，能把笔误提前暴露。循环差异：var 的循环变量在整个作用域只有一份绑定，所有回调共享同一个 i，执行时循环已结束所以都是 3；let 每轮迭代创建一个新绑定，每个回调捕获各自那一轮的值，所以是 0 1 2。加分点：const 锁绑定不锁内容；== 转 === 是为了消灭隐式转换这类反直觉行为。来源：JavaGuide 收录题型。

四、易错点小结

① typeof null === "object" 不可修复，判 null 用 === null；② 判 NaN 用 Number.isNaN——全局 isNaN 会先把参数转数字，isNaN('a') 也是 true；③ [] == false 为 true 但 [] == [] 为 false：前者比转换后的数值、后者比引用地址，别混；④ TDZ 是"声明前访问报错"，不是返回 undefined——返回 undefined 的是 var 提升；⑤ const 锁的是重新赋值，对象属性照样可改；⑥ 0.1+0.2 !== 0.3：比较用 Math.abs(a-b) < Number.EPSILON，别直接写 0.3 字面量硬比。
