事件循环与异步

适用岗位：前端（笔试输出题 + 面试必问） ｜ 形态：知识点 + 输出题逐轮拆解 ｜ 更新：2026-09-30
要点速记：JS 单线程是为避免 DOM 操作竞争，异步靠"浏览器其他线程 + 任务队列 + 事件循环"；一轮循环 = 同步代码跑完 → 清空整个微任务队列 →（必要时渲染）→ 取一个宏任务 → 再清微任务；微任务：Promise.then/catch/finally、queueMicrotask、MutationObserver；宏任务：整段 script、setTimeout/setInterval、I/O；await 之后的代码 = then 回调 = 微任务；setTimeout(fn,0) 不是立即执行。

一、知识点梳理

为什么单线程：JS 的主要工作是操作 DOM。若两个线程同时改同一个节点（一个删、一个改），就得靠锁来协调，复杂度大增——所以设计成单线程执行（历史设计）。单线程 ≠ 不能异步：计时交给定时器线程、网络交给网络线程，完成后把回调放进任务队列，主线程空闲时由事件循环取出执行——执行 JS 代码的线程始终只有一个。

同步与异步任务：同步任务直接进主线程排队顺序执行；异步任务的实际处理交给浏览器其他线程，回调进入任务队列等待被取。

类别典型成员调度规则
宏任务整段 script、setTimeout / setInterval、I/O、UI 事件回调一轮循环只取一个
微任务Promise.then/catch/finally 回调、queueMicrotask、MutationObserver一轮循环清空整个队列
  • 一轮循环规则（所有输出题的钥匙）：执行完当前同步代码 → 清空整个微任务队列（清的过程中新产生的微任务也一并清掉）→（必要时渲染）→ 取一个宏任务执行 → 再清微任务 → 如此往复。口诀：宏任务一轮一个，微任务一轮清空。注：常和宏任务一起记的"UI 渲染"严格说是循环中独立的一步，不算宏任务（实现细节）。
  • async/await 是 Promise 的语法糖：async 函数返回 Promise；await 右边的表达式同步求值，await 之后的代码相当于放进 then 的回调（微任务）。所以 await 之前是同步代码，之后全是微任务。
  • Promise 三状态：pending → fulfilled / rejected，状态一旦改变不可逆；new Promise(fn) 的 fn 是同步、立即执行的，只有 then/catch/finally 注册的回调才是微任务。链式调用：每个 then 返回新 Promise，回调的返回值传给下一级。
  • setTimeout(fn, 0) 不是立即执行：即使传 0 也要等当前这轮循环（含全部微任务）跑完才轮到它，且浏览器规范把下限抬到最少约 4ms（实现细节）。
  • 浏览器 vs Node 一句话：Node 是阶段化循环（timers / poll / check 等阶段），微任务在每个阶段之间清空——同一段代码两端输出可能不同（实现细节）。
  • 输出题拆解方法（逐轮标注，别背结论）：① 先跑同步代码——整段 script、Promise 的 executor、await 右边；② 按入队顺序清空微任务（then 回调、await 后续）；③ 取第一个宏任务，宏任务内部再重复 ①②③（宏任务里也会产生新微任务）。

二、考点说明

笔试输出题面试必问

  • 笔试：同步 + Promise + setTimeout 混合的输出题，前端笔试出镜率极高——先标轮次再下笔，选项常做成不同输出序列。
  • 面试：宏/微任务区别与调度规则、为什么单线程还能异步、async/await 原理、Promise 状态与链式调用。
  • 追问储备：微任务为什么先于宏任务（当前任务一结束立即清空，同轮内更轻）；requestAnimationFrame 在渲染前执行（实现细节）；Node 里 process.nextTick 优先级最高（实现细节）。

三、示例题目（点击选项即时判分）

输出判断1. 下面代码的输出顺序是（  ）

JavaScript 
console.log('start');
setTimeout(() => console.log('timeout'), 0);
Promise.resolve().then(() => console.log('promise'));
console.log('end');
A. start → end → timeout → promise
B. start → end → promise → timeout
C. start → promise → end → timeout
D. start → timeout → promise → end
答案 B。逐轮拆：第一轮同步——start、end；同步跑完清微任务——promise；最后取宏任务——timeout。setTimeout(fn,0) 就算 0ms 也要排队：等微任务清空后才轮到它（且最少约 4ms，实现细节）。来源：牛客经典题。

输出判断2. 下面代码的输出顺序是（  ）

JavaScript 
setTimeout(() => console.log('A'), 0);
async function foo() {
  console.log('B');
  await null;              // await 之后的代码进微任务
  console.log('C');
}
foo();
Promise.resolve().then(() => console.log('D'));
console.log('E');
A. B → E → C → D → A
B. B → C → D → E → A
C. B → E → D → C → A
D. A → B → E → C → D
答案 A。同步轮：foo() 执行到 await 前输出 B，await 把"C"挂进微任务队尾；回到主脚本，then 注册 D，再输出 E——同步序列是 B、E。清微任务（按入队顺序）：先 C（await 恢复）后 D。最后取宏任务输出 A。整体 B → E → C → D → A。C 选项错在把两个微任务的先后记反——await 的续体先入队、then 后入队。来源：面试高频改编。

输出判断3. 下面代码的输出顺序是（  ）

JavaScript 
setTimeout(() => {
  console.log('A');
  Promise.resolve().then(() => console.log('B'));
}, 0);
setTimeout(() => console.log('C'), 0);
console.log('D');
A. D → A → B → C
B. D → A → C → B
C. D → C → A → B
D. A → C → B → D
答案 A。同步：D。取第一个宏任务输出 A，并在宏任务内部把 B 注册为微任务；宏任务跑完立即清微任务 → B；再取下一个宏任务 → C。B 选项错在"两个定时器背靠背跑完"——每执行完一个宏任务都要先清空微任务队列。来源：牛客经典题。

多选4. 下列属于微任务的有（  ）

A. Promise.then/catch/finally 注册的回调
B. setTimeout 的回调
C. queueMicrotask 传入的函数
D. 整段 script 代码
E. MutationObserver 回调
答案 ACE。setTimeout 回调与整段 script 是宏任务。记忆口径：微任务是"Promise 体系及同类细粒度回调"，宏任务是"一轮循环取一个的大块头"。来源：面试高频改编。

面试口述5. JS 只有单线程，为什么还能"异步"？

参考回答单线程是为了避免 DOM 操作竞争：两个线程同时改一个节点就得加锁，成本太高。异步靠分工：I/O、定时器这类耗时操作交给浏览器的其他线程 / 内核处理，完成后把回调放进任务队列；事件循环在主线程空闲时按"清空微任务 → 取一个宏任务"的规则调度回调执行。所以异步 ≠ 多线程执行 JS——是"浏览器多线程协作 + 任务队列 + 事件循环"，JS 代码本身始终单线程跑。加分点：微任务一轮清空、宏任务一轮一个；可补一句 Node 阶段化循环的差异。来源：面试高频改编。

四、易错点小结

① new Promise(fn) 的 fn 是同步执行的——Promise 里的 log 不是微任务，then/catch/finally 的回调才是；② "清空微任务"是清到空为止：执行微任务过程中新产生的微任务也在本轮清掉；③ 宏任务一轮只取一个、微任务一轮全清——输出题先逐轮标注再下笔；④ await 之前是同步、await 之后是微任务（相当于 then 回调）；⑤ setTimeout(fn,0) 不是立即执行：要排队等循环，且最少约 4ms（实现细节）；⑥ 同一段代码浏览器与 Node 输出可能不同——Node 阶段化循环、微任务在每个阶段之间清空（实现细节）。
