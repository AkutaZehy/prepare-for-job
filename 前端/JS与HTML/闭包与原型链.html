闭包与原型链

适用岗位：前端（面试必问 + 笔试输出题） ｜ 形态：知识点 + 原型链输出题实跑核对 ｜ 更新：2026-09-30
要点速记：闭包 = 函数 + 定义时的词法环境——内层函数引用外层变量、内层被返回，变量就活得比调用更久；应用：私有变量 / 柯里化 / 防抖节流；泄漏 = 闭包长期持有不再需要的大对象或 DOM。原型链：实例的 __proto__ 指向构造函数的 prototype，属性查找沿链到 Object.prototype 再到 null；instanceof = 右侧 prototype 是否在左侧的原型链上；class 是原型继承的语法糖（typeof 仍是 "function"）；new 四步：建空对象挂原型 → 绑 this 执行 → 按返回值决定结果。

一、知识点梳理

闭包的定义：函数与其词法环境的组合（MDN 口径）；面试口径——内层函数访问了外层函数作用域的变量，且内层函数被返回或传出，导致外层变量在外层函数返回后依然存活。形成三要素：函数嵌套 + 内层引用外层变量 + 内层被传出。

应用说明
私有变量计数器把 count 藏在闭包里，外部只能通过暴露的方法读写，无法直接改
柯里化add(1)(2) 的第一层参数靠闭包记住，返回的新函数继续消费它
防抖节流timer / last 时间戳存在闭包里，多次触发之间共享同一份计时状态

内存泄漏场景：闭包本身不是泄漏；泄漏是闭包长期存活（如挂在全局的事件回调）且持有不再需要的大对象 / DOM 引用，垃圾回收器无法回收它们。对策：不再使用时把引用置 null、及时解绑事件监听器。

原型链三件套：每个函数都有 prototype（显式原型）；每个对象都有 __proto__（隐式原型，标准取法 Object.getPrototypeOf）；关系恒成立：实例.__proto__ === 构造函数.prototype。构造函数的 prototype 上有 constructor 指回构造函数本身。

实例 a ──__proto__──→ A.prototype ──__proto__──→ Object.prototype ──__proto__──→ null
                        │ constructor 指回 A          （toString/hasOwnProperty 在这里）
属性查找：a 自身 → A.prototype → Object.prototype → null，找到即停，找不到 undefined

instanceof 原理：a instanceof B 沿 a.__proto__ 逐级向上，看 B.prototype 是否出现在 a 的原型链上。因此 constructor 可以被改写而 instanceof 不能被伪造——前者只是属性，后者查的是真实链条。

new 做了什么（四步）：① 创建一个空对象；② 把它的 __proto__ 指向构造函数的 prototype；③ 以该对象为 this 执行构造函数；④ 若构造函数显式返回一个对象则用它，否则返回第 ① 步的对象（返回原始值会被忽略）。

class 是语法糖：class 本质仍是"构造函数 + prototype"那套原型继承，写法上封装了方法挂载、继承（extends/super）等样板。typeof 类仍是 "function"（本机 node 实跑：typeof C → "function"，C.prototype.constructor === C 为 true）。

常考输出题：原型链查找（本机 node 实跑核对）：

JavaScript 
const base = { a: 1 };
const child = Object.create(base);  // child.__proto__ === base
child.a = 2;                        // 写入的是 child 的自有属性
console.log(child.a);               // 2（自身命中，查找停止）
delete child.a;
console.log(child.a);               // 1（自有属性没了，沿原型链找到 base.a）
console.log(child.hasOwnProperty('a')); // false（hasOwnProperty 只查自身）

二、考点说明

笔试输出题面试手写高频

  • 笔试：给对象链问属性值（自有 vs 原型）、delete 后的查找结果、new + 显式 return 的返回值。
  • 面试：闭包定义与应用、内存泄漏排查、__proto__ 与 prototype 关系、instanceof 手写原理、new 四步、class 与构造函数关系。
  • 追问储备：手写 instanceof（沿 __proto__ 循环比较）、Object.create 的本质（新建对象并把原型指向参数）、为什么箭头函数没有自己的 this（它继承定义处的 this，也和词法环境有关）。

三、示例题目（点击选项即时判分）

单选1. a instanceof B 的判断依据是（  ）

A. a 的 constructor 属性是否等于 B
B. B.prototype 是否出现在 a 的原型链（__proto__ 链）上
C. a.__proto__ 是否直接等于 B
D. 两者 Object.prototype.toString 输出相同
答案 B。instanceof 沿 a.__proto__ 逐级向上与 B.prototype 比较，B 处于链条任意一层都算 true，不只比第一层。constructor 是普通属性可以被改写，判断不可靠；A 是干扰项。来源：牛客经典题。

多选2. 关于闭包，正确的有（  ）

A. 闭包 = 函数 + 定义时的词法环境，变量因此活过外层函数的返回
B. 防抖函数把 timer 存在闭包里，多次触发共享同一份计时状态
C. 只要使用了闭包就一定会造成内存泄漏
D. 柯里化 add(1)(2) 依赖闭包记住第一层的参数
答案 ABD。泄漏的准确条件是"闭包长期存活且持有不再需要的大对象 / DOM 引用"——普通短生命周期闭包会被正常回收，C 过于绝对。来源：面试高频改编。

输出判断3. 下面代码的输出是（  ）

JavaScript 
const base = { a: 1 };
const child = Object.create(base);
child.a = 2;
console.log(child.a);
delete child.a;
console.log(child.a);
console.log(child.hasOwnProperty('a'));
A. 2 / 1 / true
B. 2 / 2 / true
C. 2 / 1 / false
D. 1 / 1 / false
答案 C。本机 node 实跑：2、1、false。child.a = 2 写入自有属性，读取时自身命中即停；delete 删掉自有属性后，查找沿 __proto__ 落到 base.a 输出 1；hasOwnProperty 只查自身不查原型链，返回 false。来源：JavaGuide 收录题型。

单选4. function Fn() { this.x = 1; return { custom: 2 }; }，执行 const r = new Fn() 后，r 是（  ）

A. { custom: 2 }
B. { x: 1 }（this 指向的新对象）
C. undefined
D. Fn 函数本身
答案 A。new 四步的最后一步：构造函数显式返回一个对象时，该对象覆盖默认的新建对象；若只返回原始值（return 1）则被忽略，仍返回新建对象。注意此时 { x: 1 } 白建了但没被返回。来源：面试高频改编。

面试口述5. 什么是闭包？举一个你用过的实际应用，并说明什么情况下会造成内存泄漏。

参考回答闭包是函数和它定义时词法环境的组合：内层函数引用外层函数的变量，且内层被返回/传出，这些变量就在外层函数返回后继续存活。应用：手写防抖——timer 存在闭包里，每次触发 clearTimeout 旧计时再 setTimeout 新计时，多次触发只保留最后一次；还有私有变量（外部只能通过暴露的方法读写）和柯里化。泄漏场景：把引用了大对象或 DOM 的回调长期挂在全局事件上，闭包链让这些对象始终可达、回收不掉——对策是用完置 null、及时 removeEventListener。加分点：闭包不是泄漏本身，"长期存活 + 持有无用大引用"才是；可补一句手写 new / instanceof。来源：牛客经典题。

四、易错点小结

① 实例只有 __proto__，函数才有 prototype——标准取法用 Object.getPrototypeOf(inst)；② 属性查找"找到即停"：自有属性会遮蔽原型同名属性，delete 自有属性后会"掉回"原型值；③ hasOwnProperty 只查自身，in 运算符会查整条链；④ class 的 typeof 仍是 "function"，别答成 "class"；⑤ new 显式返回对象才覆盖，返回原始值被忽略；⑥ 原型链尽头是 Object.prototype.__proto__ === null，别答成 undefined。
