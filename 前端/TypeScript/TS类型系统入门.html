TS 类型系统入门

适用岗位：前端（TS 笔试 + 面试必问） ｜ 形态：知识点 + 报错定位题（tsc 实跑核对） ｜ 更新：2026-09-30
要点速记：TS 是 JS 的超集，类型在编译期检查、编译后擦除；价值三连：编译期抓错 / 重构信心 / IDE 提示；interface 可声明合并，type 能表达联合/映射等复合类型——对象形状优先 interface、要组合就用 type；unknown 是安全的 any（用前必须收窄或断言），never 是底类型（任何值都赋不进去）；收窄三件套：typeof / in / 判等；枚举编译成双向映射对象，const enum 内联无运行时开销，新代码常用字面量联合替代。

一、知识点梳理

TS 的价值（面试口述三连）：① 编译期抓错——把"运行时才炸的 undefined"提前到写代码时标红；② 重构信心——改一个接口字段名，所有引用处立即报错，改完编译通过就是改完；③ IDE 提示——补全、跳转、参数签名全部可用。注意 类型擦除：TS 编译成 JS 后类型注解全部消失，运行时不存在类型信息（这也是它零运行时开销的原因）。

基础类型标注：变量 let n: number、数组 number[]、元组 [string, number]、对象形状、函数参数与返回值 (a: string): void；不标注且无法推断时落入隐式 any（建议开启 noImplicitAny 挡住它）。

TypeScript 
let name: string = 'A';              // 基础标注
let ids: number[] = [1, 2];
let pair: [string, number] = ['age', 18];
function greet(user: { name: string }): string { return `hi ${user.name}`; }

interface vs type（高频对比）：

维度interfacetype
同名声明可合并（声明合并，自动拼接成员）不可，重名直接报错
复合类型只描述对象形状联合 / 交叉 / 元组 / 映射等都能写（联合原子性：联合类型只能用 type 声明）
扩展方式extends，可被类 implements交叉 & 模拟继承
选择建议对象 / 类的形状优先用它需要联合、工具类型组合时用它

联合类型与字面量类型：string | number 表示二选一；字面量类型把取值域钉死——type Mode = 'light' | 'dark'，传 'blue' 直接编译报错，是替代枚举的轻量方案。

类型收窄：联合类型在使用处"缩小"到具体分支后才能访问对应成员。手段：typeof x === 'string'、'meow' in x（按成员存在性区分）、x === 固定值 判等、instanceof（TS 4.4+ 还可把 typeof 判断抽成变量复用，实现细节）。

TypeScript 
function speak(x: Cat | Dog) {
  if ('meow' in x) { x.meow(); } else { x.bark(); }  // in 收窄，两分支都拿到具体类型
}

any / unknown / never 三兄弟：

类型含义使用限制
any放弃类型检查可以随意赋值、随意调用成员，错误会被"传染"出去
unknown安全的 any什么值都能接，但用前必须收窄或显式断言，否则编译报错
never底类型：没有任何值用于"永不返回"的函数（抛错 / 死循环）与穷尽性检查

枚举一句与 const enum：enum 编译成真实对象（数字枚举有反向映射 obj[key]）；const enum 在编译期内联、不生成运行时对象，零开销；新代码更常用字面量联合类型替代枚举。

二、考点说明

笔试报错定位面试必问

  • 笔试：给代码问哪几行编译报错（赋值类型不符 / unknown 未收窄 / never 赋值）。
  • 面试：any/unknown/never 区别、interface 与 type 怎么选、TS 比 JS 好在哪、类型擦除是什么。
  • 追问储备：unknown 适合接 JSON.parse、接口返回等"来源不可信"的数据；穷尽性检查——switch 把所有分支处理完后 default 里赋 never，新增联合成员时编译器自动报错提醒（实现细节）。

三、示例题目（点击选项即时判分）

单选1. 下面代码的编译结果是（  ）

TypeScript 
let box: unknown = 'gift';
box.length;  // 行①
A. 编译通过，运行时输出 4
B. 编译报错：unknown 类型的值必须收窄或断言后才能使用
C. 编译通过，运行时 TypeError
D. box 被自动推断为 string，无任何提示
答案 B。tsc 5.5.4 strict 实跑：error TS18046: 'box' is of type 'unknown'。unknown 是"安全的 any"——接收不受限，但使用前必须收窄（typeof/in/判等）或显式断言；先 typeof box === 'string' 再访问 .length 就能编译通过。来源：面试高频改编。

单选2. 关于 interface 与 type，说法正确的是（  ）

A. interface 不能被类 implements
B. type 同名声明会自动合并
C. interface 支持声明合并，type 能表达联合类型等复合类型
D. 两者的类型信息都会保留到运行时
答案 C。interface 同名自动合并（第三方类型补丁就靠它），type 重名报错但能写联合/映射；interface 可被类 implements，A 错；TS 类型编译后擦除，D 错。来源：JavaGuide 收录题型。

多选3. 关于类型收窄与 any/unknown/never，正确的有（  ）

A. typeof x === 'number' 分支内，x 可安全调用 toFixed
B. 'meow' in x 可按成员是否存在区分联合类型的分支
C. never 可以接收任何类型的赋值
D. unknown 赋值给具体类型前必须收窄或显式断言
答案 ABD。never 是底类型——没有任何值属于它，所以是"任何类型都不能赋给 never"，C 恰好说反。typeof 与 in 都是标准收窄手段，收窄后联合类型获得具体分支的成员与方法。来源：面试高频改编。

报错定位4. 下面代码中哪几行编译报错？（  ）

TypeScript 
let price: number = 99;      // 行①
price = 'free';              // 行②
let box: unknown = 'gift';   // 行③
box.length;                  // 行④
let nothing: never;          // 行⑤
nothing = 1;                 // 行⑥
A. 仅行②
B. 行②④⑥
C. 行②③
D. 行④⑥
答案 B。tsc 5.5.4 strict 实跑核对：行② TS2322（string 不能赋给 number）；行④ TS18046（'box' is of type 'unknown'，未收窄不能访问属性）；行⑥ TS2322（number 不能赋给 never，任何类型都赋不进底类型）。行③ 和行⑤ 只是声明赋值，本身合法。来源：牛客经典题。

面试口述5. TS 相比 JS 带来了什么？"类型擦除"是什么意思，它带来什么后果？

参考回答三件价值：编译期抓错——把运行时才暴露的类型错误提前到写代码时；重构信心——改接口字段，所有引用处立即报错，编译通过即改完；IDE 提示——补全、跳转、参数签名全覆盖。类型擦除：TS 只在编译期做静态检查，编译产物是纯 JS，类型注解全部消失，运行时不存在类型信息。后果：不能在运行时拿类型做判断（需要类型守卫手写判断），好处是零运行时开销、产物与手写 JS 一致。加分点：enum 例外——数字枚举会编译成真实的双向映射对象；unknown 接不可信数据、never 做穷尽性检查。来源：JavaGuide 收录题型。

四、易错点小结

① any 会"传染"：any 类型的表达式参与运算后结果也是 any，检查形同虚设——新代码用 unknown + 收窄；② never 方向别背反：任何类型都不能赋给 never，never 可以赋给一切；③ TDZ 不存在但"先声明后使用"依然是 TS 纪律，unknown 访问成员前必须收窄；④ 声明合并是 interface 独有，同名 type 直接冲突；⑤ 枚举反向映射仅数字枚举有，字符串枚举没有；const enum 与 isolatedModules 有兼容限制（实现细节）；⑥ 字面量联合 type Mode = 'light' | 'dark' 多数场景可替代枚举。
