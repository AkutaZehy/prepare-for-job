JSX 与组件：类组件 vs 函数组件

适用岗位：前端、通用软开 ｜ 形态：概念对比 + 短路输出题 ｜ 更新：2026-09-30
要点速记：JSX 编译后是 React.createElement / jsx() 调用，产出描述 UI 的普通 JS 对象（React element），不是真实 DOM；条件渲染 && 短路有个 0 陷阱（count && <Badge/> 在 count=0 时渲染出数字 0）；props 只读、state 要走 setState——直接改不触发渲染；表单受控 = value+onChange，非受控 = defaultValue/ref；类组件死于 this 绑定与逻辑复用困难，React 16.8 引入 Hooks 后函数组件成绝对主流。

一、知识点梳理

JSX · 本质：编译产物是对象，不是 DOM 
const el = <h1 className="t">hi {name}</h1>;

// 编译为（React 16 及以前的经典转换，需 import React）
const el = React.createElement('h1', { className: 't' }, 'hi ', name);

// React 17+ 自动运行时（automatic runtime）：不用 import React，
// 编译器自动注入 import { jsx } from 'react/jsx-runtime'

// createElement / jsx 返回的是形如下面的普通对象（React element）：
// { $$typeof: Symbol(react.element), type: 'h1', props: {...} }
// 它只是"描述"，真正变成 DOM 是 React 后续 render/diff 的事
  • 花括号 {} 与条件渲染：{} 里写任意 JS 表达式（不能是语句）。条件渲染三板斧：cond && <A/>、cond ? <A/> : <B/>、list.map(...)。注意 && 左侧为 0 时会渲染出数字 0（0 虽 falsy，但 0 && x 的结果是 0 本身，React 对数字照渲染）；false/null/undefined 则什么都不渲染。
  • 列表与 key：list.map(item => <li key={item.id}>...</li>)，key 要稳定唯一，不用数组下标——插入/删除后状态错位，原理同 Vue（对照 computed/watch 与 diff 概览 页的复选框例子）。
  • props 单向数据流与不可变：props 只读，子组件不能改 props（要改数据就回调给父）；state 也不许直接赋值——类组件 this.state.x = 1 不触发重渲染，必须 setState；函数组件用 useState 的 setter。React 靠"引用变没变"判断要不要更新（不可变数据是整套机制的地基，见 响应式原理 页的 Vue 对照）。
JSX · 受控 vs 非受控 
// 受控组件：React state 是唯一数据源，输入框的值完全由 state 驱动
<input value={name} onChange={e => setName(e.target.value)} />
// 注意：只给 value 不给 onChange，输入框会"打不了字"并收到警告

// 非受控组件：DOM 自己管理值，需要时用 ref 去取
<input defaultValue="hi" ref={inputRef} />
inputRef.current.value   // 提交时才读
JS · 类组件 this 绑定问题（为什么被函数组件取代） 
class Old extends React.Component {
  constructor(props) {
    super(props);
    this.state = { n: 0 };
    // 坑：类方法默认不绑 this，传出去当回调 this 是 undefined
    this.handleClick = this.handleClick.bind(this);   // 解法1：构造器里 bind
  }
  handleClick() { this.setState({ n: this.state.n + 1 }) }
  // 解法2：类字段箭头函数 handleClick = () => {...}
}

// React 16.8（2019）引入 Hooks，函数组件全面胜出：
// ① 逻辑复用靠自定义 Hook，告别 HOC/render props 嵌套地狱
// ② 没有 this，心智负担消失
// ③ 相关逻辑可以聚在一起，而不是按生命周期拆散
// 组合优于继承：React 官方从未推荐组件继承，复用靠 children 组合 / render props / Hook

二、考点说明

笔试选择输出题面试必问

  • 笔试：JSX 编译产物是什么、&&/三元/map 条件渲染、受控非受控区分、setState 直接改 state 行不行。
  • 面试链路："JSX 是什么"→ createElement/自动运行时 → element vs DOM → 条件渲染陷阱 → key → props/state 不可变 → 类组件 this 问题 → 为什么 Hooks 赢。
  • 场景：表单联动校验选受控还是非受控；输入框打不了字排查（value 没配 onChange）。

三、示例题目（点击选项即时判分）

单选1. JSX 经编译后的产物本质上是（  ）

A. 真实的 DOM 节点
B. HTML 字符串
C. 描述 UI 结构的普通 JS 对象（React element），由 React 再渲染成真实 DOM
D. 浏览器内置的模板元素 template
答案 C。<h1>hi</h1> 编译为 React.createElement('h1', null, 'hi')（React 17+ 自动运行时走 jsx()），返回带 type/props 的对象。这层"描述与实现分离"正是虚拟 DOM diff 的前提。版本结论：React 17 起新 JSX 转换不再要求手动 import React。来源：面试高频改编。

单选2. 场景：写了 <input value={name} />（name 是 state），页面输入框却打不了字。原因与正确修法是（  ）

A. value 不能是变量，必须写死字面量
B. 只给 value 不给 onChange，这是"半受控"：state 不变输入永远被重置回 name；补上 onChange 更新 state 即可输入
C. 应该改成 this.state.name 直接赋值
D. input 组件坏了，换成 div contentEditable
答案 B。受控组件的约定：value 来自 state、每次输入经 onChange 回写 state。缺 onChange 时 state 不更新，React 重渲染把输入框拉回原值。确实不需要实时受控就用 defaultValue 走非受控。来源：牛客经典题。

多选3. 关于 React 的 props / state / key，正确的有（  ）

A. props 是只读的，子组件不应直接修改，数据变更应通过回调交回父组件（单向数据流）
B. 类组件直接给 this.state 赋值不会触发重渲染，必须用 setState
C. 列表用数组下标 index 当 key 是官方推荐，稳定可靠
D. state 更新要用不可变方式：数组用 [...arr, x]、对象用 {...obj}，而不是 push/直接改字段
答案 ABD。C 错：index 当 key 在插入/删除时会状态错位（复选框、输入框串值），与 Vue 同款结论。D 是因为 React 靠引用比较判断数据变没变，原地改引用不变就不会重渲染。来源：JavaGuide 收录题型。

输出题4. 组件里 const count = 0;，模板写 {count && <Badge />}。页面会渲染出什么？为什么？至少给出两种正确写法。

先自己想，再展开对答案页面会渲染出一个数字 0。count && x 当 count=0 时短路返回 0 本身——0 是 falsy，但它不是 false/null/undefined，React 对数字类型照常渲染成文本。写法修正：① {count > 0 && <Badge />} 把左侧变成布尔；② {count ? <Badge /> : null} 三元兜底 null；③ {!!count && <Badge />} 强转布尔。这个 0 陷阱是 React 面试与 code review 出镜率最高的表达式 bug。来源：面试高频改编。

面试口述5. "类组件和函数组件有什么区别？为什么现在都写函数组件？"按时间线 + 三个理由讲清楚。

参考回答时间线：React 16.8（2019）引入 Hooks 之前逻辑只能写在类组件里，之后函数组件通过 Hooks 获得完整能力，成为官方推荐默认。区别与胜出理由：① 逻辑复用——类组件靠 HOC/render props 层层嵌套（包装地狱），函数组件自定义 Hook 把状态逻辑抽成可组合的函数；② this——类组件要 bind 或箭头函数绑 this，忘绑就 undefined，函数组件没有 this；③ 内聚——类组件按生命周期把同一功能的代码拆散在各钩子里，函数组件一个 useEffect 就能把"订阅+清理"写在一处。加分点：函数组件每次渲染是全新闭包（引出闭包陷阱话题）；组合优于继承是 React 一贯立场，复用走 children/render props/Hook 而非继承。来源：牛客经典题。

四、易错点小结

① {count && <Badge/>} 的 0 陷阱：左侧保证是布尔再 &&；② 类组件忘 bind，回调里 this 是 undefined——报错 "Cannot read properties of undefined"；③ 直接 push 数组/改对象字段不重渲染：React 比的是引用；④ 列表 key 用 index，增删后输入框、勾选串值；⑤ 受控组件漏 onChange 打不了字、控制台有 value without onChange 警告——看警告别硬猜。
