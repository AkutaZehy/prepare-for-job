React vs Vue 对比

适用岗位：前端、通用软开 ｜ 形态：大对比表 + 选型口述 ｜ 更新：2026-09-30
要点速记：一句话分层背——模板 vs JSX（Vue 编译期能优化、React 表达力强）；响应式机制：Vue3 Proxy 精确追踪自动更新 vs React 不可变数据 + 显式 setState；更新粒度：Vue 依赖级（只更用到数据的组件）vs React 组件级（setState 的组件整棵子树重跑，靠 memo 手动掐）；diff：Vue3 最长递增子序列求最少移动 vs React 单向从左到右；React 18 并发：自动批处理 + startTransition 可中断渲染。

一、知识点梳理：大对比表

维度Vue3React
写法SFC 单文件 + 模板指令，受限但编译器可静态分析JSX = JS 表达式，图灵完备、表达力强，编译期几乎不做优化
响应式机制Proxy 精确追踪：读数据自动收集依赖、改数据自动触发（见 响应式原理 页）不可变数据 + 显式 setState：没有依赖追踪，靠"引用变没变" + 重跑组件函数
更新粒度依赖级：谁用这个数据谁更新，组件树其他部分不动组件级：setState 的组件连同其子树默认全部重渲染，子组件要 memo 手动挡
diff 策略同层比较 + 最长递增子序列求最少节点移动（双端思想）同层比较 + 单向从左到右遍历，key 标识复用
编译优化静态提升、patchFlag、块树（模板独享）基本没有，优化靠人写 memo/useMemo/useCallback
状态管理Pinia（官方出品，见 Router 与 Pinia 页）自由市场：Redux（含 RTK）/ Zustand / Jotai 自选
路由Vue Router 官方维护社区事实标准 React Router / Next.js 内置
逻辑复用Composition API（Vue3 起）Hooks（React 16.8 引入）
并发能力无同级概念，调度器按优先级更新队列React 18 并发特性：自动批处理、startTransition/useDeferredValue 让大更新可中断不卡输入
心智模型"框架替你追踪"，改数据即可，自动更新"UI = f(state)"，显式声明不可变更新，一切靠重跑
  • 模板 vs JSX 的本质：模板语法受限（不能随便写语句），换来的是编译器能静态标记哪些节点永远不变——Vue3 的性能优化全建立在这上面；JSX 自由，能写任意 JS，但编译器看不懂意图，优化责任转给开发者。
  • 更新粒度举例：一个大列表页改一个计数器，Vue3 里只有用到它的组件重渲染；React 里该组件 + 其子树默认全跑一遍 render 再 diff（子树大时要 memo/useMemo 兜）——这也是"React 写大页面更吃优化功力"的原因。
  • 概念对照表（迁移记忆用）：ref/reactive ≈ useState、computed ≈ useMemo、watch ≈ useEffect([deps])、provide/inject ≈ Context、组合式函数 ≈ 自定义 Hook。
  • 选型建议：① 团队技术栈与存量代码优先——迁移成本大于一切理论优劣；② 无偏好时：中后台、表单密集、快速交付、团队偏新手 → Vue 生态顺手；大型复杂交互、强 TS 工程化、跨端 RN、招人池 → React；③ 两者心智已趋同（Composition API vs Hooks），会一个另一个上手很快。

二、考点说明

面试必问选型口述跨框架对照

  • 高频原题："React 和 Vue 有什么区别？"——别只答语法，按"响应式机制 → 更新粒度 → diff → 生态 → 心智"五层讲。
  • 追问链：React 为什么没有依赖收集 → memo 为什么需要 → Vue3 编译优化为什么 JSX 没有 → React 18 并发是什么 → 新项目你选哪个。
  • 答案不封顶，但更新粒度与响应式机制两题是硬知识，答错直接出局。

三、示例题目（点击选项即时判分）

单选1. React 函数组件内调用一次 setState 后，默认（未做任何优化时）重新执行的是（  ）

A. 只重新渲染用到该 state 的那部分子组件
B. 该组件函数本身重新执行，其所有子组件也默认跟着重新渲染
C. 整个应用所有组件重新渲染
D. 什么都不重渲染，只做 DOM 属性修补
答案 B。React 没有"谁用了数据谁更新"的依赖级粒度——setState 所在组件整棵子树默认重跑 render 再 diff，大子树要靠 React.memo/useMemo/useCallback 手动掐断。对照：Vue3 是依赖级，Proxy 知道哪些组件读过这个数据。版本结论：React 18 的并发特性（transition）改变的是调度的可中断性，不改变这个默认粒度。来源：面试高频改编。

单选2. Vue3 修改数据后框架"自动知道"该更新谁，React 需要开发者显式 setState。这一差异的根源是（  ）

A. Vue3 性能更强，React 不想做这个功能
B. React 的组件不能是纯函数，所以无法自动追踪
C. Vue3 用了虚拟 DOM，React 没有用
D. Vue3 用 Proxy 代理数据，读写都被拦截所以能精确收集依赖；React 的 state 是普通值，没有拦截层，只能靠"显式通知 + 重跑函数"驱动更新
答案 D。双方都有虚拟 DOM，C 先排除。机制分层背：Vue3 = Proxy 拦截读写 → 自动 track/trigger → 依赖级更新；React = 不可变数据 + 显式 setState → 组件函数重跑 → 组件级更新 + memo 优化。两条路线没有绝对优劣，Vue 省心、React 心智更"显式"。来源：牛客经典题。

多选3. 关于两者生态与工程化，正确的有（  ）

A. Vue 的 Router/Pinia/Vite 均为官方团队维护，全家桶风格统一
B. React 生态自由度高：状态管理 Redux/Zustand/Jotai、数据请求 React Query 等自行组队
C. 两者都有成熟的 SSR/全栈方案：Nuxt 对应 Vue，Next.js 对应 React
D. React 官方内置了路由和状态管理，开箱即用
答案 ABC。D 错：React 是库不是全家桶，路由、状态管理全交给社区生态，自由但也意味着选型成本。选型口述时"官方统一 vs 社区自由"是必提的一对词。来源：JavaGuide 收录题型。

面试口述4. "如果让你启动一个新项目，你选 React 还是 Vue？为什么？"给出一套有立场的回答模板。

参考回答先亮立场再给判据，切忌"都行"。模板：① 团队与存量——团队熟悉谁、公司现有项目用什么，迁移成本大于理论优劣，这是第一判据；② 无偏好时按场景：中后台表单密集、要快速交付、团队新人多 → 选 Vue3，官方全家桶（Router/Pinia/Vite）风格统一、响应式自动追踪心智负担小；大型复杂交互、重度 TS 工程化、未来要跨端 RN、招聘池大 → 选 React，生态自由且 Next.js 全栈方案成熟；③ 兜底展示深度：两者心智已收敛——Composition API 与 Hooks 几乎同构，diff 上 Vue3 最长递增子序列编译期优化更省心、React 18 并发调度（自动批处理、transition）在超大列表交互上更有想象空间，最终选型是工程决策不是信仰问题。来源：面试高频改编。

四、易错点小结

① "React 有依赖收集/响应式"是硬伤级错误——它没有，靠显式 setState + 重跑；② memo 只做 props 浅比较，传对象/函数 props 不配合 useMemo/useCallback 等于白 memo；③ Vue 模板的"受限"正是编译优化的来源，别把它当缺点背；④ diff 差异别背反：Vue3 最长子序列求最少移动、React 单向从左到右；⑤ 概念对照表（ref≈useState、computed≈useMemo、watch≈useEffect、provide/inject≈Context）是跨框架面试的送分工具，背熟。
