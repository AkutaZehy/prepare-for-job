Hooks 核心：useState / useEffect

适用岗位：前端、通用软开 ｜ 形态：闭包陷阱输出题 + 规则多选 ｜ 更新：2026-09-30
要点速记：React 16.8 引入 Hooks。setState 触发重渲染、靠引用比较；函数式更新 setX(x => x + 1) 基于最新值，专治连续更新与闭包旧值；闭包陷阱：setInterval 的回调永远读到创建那一次渲染的旧 state，页面卡在 1——解法：函数式更新或 useRef。useEffect 依赖 [] 只跑一次、[a,b] 依赖变才跑、不传每次跑；清理函数在下一次 effect 前与卸载时执行。useRef 存跨渲染可变值、改 .current 不触发渲染。Hooks 两条铁律：只在顶层调用、只在函数组件/自定义 Hook 里调用。

一、知识点梳理

JSX · useState 与批处理 
const [count, setCount] = useState(0);

setCount(count + 1);        // 直接传值：用"这次渲染的 count"算
setCount(c => c + 1);       // 函数式更新：基于 React 手里最新的 prev 算
setCount(c => c + 1);       //   同一轮里连调三次也全生效（直接传值三次只加 1）

// 批处理：同一轮事件里的多次 setState 合并成一次重渲染
// 版本结论：React 18 起自动批处理覆盖到 promise/setTimeout/原生事件，
//          18 之前只有 React 事件处理器内才批处理。
JSX · 闭包陷阱：计数器永远停在 1（输出题母题） 
function Timer() {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1);   // ✗ count 是这次 effect 创建时的闭包值，永远是 0
    }, 1000);
    return () => clearInterval(id);
  }, []);                    // 依赖 []：effect 只跑一次，闭包被"冻"在第一帧
  return <p>{count}</p>;     // 页面永远显示 1（0+1，反复覆盖）
}

// 解法1：函数式更新，不依赖闭包里的 count
setCount(c => c + 1);        // ✓ 每秒 +1

// 解法2：useRef 存最新值，回调读 ref.current
const latest = useRef(0);
useEffect(() => { latest.current = count; }, [count]);
JSX · useEffect 三种依赖 + 清理函数 
useEffect(() => {
  const id = setInterval(tick, 1000);
  window.addEventListener('resize', onResize);
  return () => {                    // 清理函数执行时机：
    clearInterval(id);              //   ① 下一次 effect 执行之前（依赖变化）
    window.removeEventListener('resize', onResize);  //  ② 组件卸载时
  };
}, []);       // []：挂载后跑一次；[a, b]：挂载后 + a/b 变化后；不传：每次渲染后都跑

// 心智纠偏：useEffect 不是"生命周期"，而是
//   "渲染之后，把这份副作用同步到外面的世界"——依赖写的是同步所需的数据。
Hook用途关键点
useRef① 拿 DOM 引用 ② 存跨渲染可变值改 .current 不触发重渲染；界面要跟着变的数据用 state，只是"记着"的数据用 ref（timer id、上一次值）
useMemo缓存计算结果依赖不变不重算，近似 Vue 的 computed（对照 Vue computed 页）
useCallback缓存函数引用配合 React.memo 子组件：否则父每渲染都传"新函数"，memo 白做
自定义 Hook逻辑复用必须 use 开头，内部照常调其他 Hook；每个组件用它时状态相互独立
  • 两条规则及原因：① 只在顶层调用（不能放进 if/循环/嵌套函数）——React 靠调用顺序记录每个 Hook 的状态，顺序一乱状态就串位；② 只在函数组件或自定义 Hook 中调用——普通 JS 函数没有 Hook 的挂载环境。

二、考点说明

笔试选择输出题必考面试必问

  • 笔试：useEffect 三种依赖写法与清理时机、useRef 与 useState 区别、两条规则、useMemo/useCallback 区别。
  • 面试链路："setInterval 里 count 为什么不动"→ 闭包陷阱原理（函数组件每次渲染是独立闭包）→ 函数式更新为什么能解 → 依赖数组该怎么写 → useEffect 心智是不是生命周期。
  • 场景：组件卸载后还在 setState 的警告、定时器翻倍（effect 重复执行没清理）。

三、示例题目（点击选项即时判分）

单选1. useEffect(() => {...}, []) 的执行与清理时机，正确的是（  ）

A. 首次渲染后执行一次；清理函数在组件卸载时执行
B. 每次渲染后都执行，清理函数在每次渲染前执行
C. 挂载前同步执行，类似 getDerivedStateFromProps
D. 永远不会执行，因为依赖数组为空表示永不运行
答案 A。空依赖 = "同步逻辑不依赖任何会变的数据"，只挂载后跑一次，清理在卸载时。若有依赖 [a]，则每次 a 变化后先跑上一次的清理函数、再跑新 effect。补充：React 18 开发模式 StrictMode 会故意挂载-卸载-再挂载一次来暴露漏清理的副作用，生产环境不会。来源：牛客经典题。

单选2. 关于 useRef，正确的是（  ）

A. 修改 ref.current 会立即触发组件重渲染
B. 既能存 DOM 引用，也能存跨渲染的可变值；修改 .current 不触发重渲染
C. useRef 和 useState 可以随意互换，只是名字不同
D. useRef 的值在组件重新渲染后会被重置为初始值
答案 B。选型口诀：界面要跟着变的用 useState；只是"记住"（timer id、previous 值、是否已请求标记）且不想引发渲染的用 useRef。useRef 跨渲染保持同一对象，D 恰好说反。来源：面试高频改编。

多选3. 关于 Hooks 的规则与缓存 Hook，正确的有（  ）

A. Hooks 必须在函数组件顶层调用，不能包在 if/循环/普通函数里
B. 自定义 Hook 必须 use 开头，内部可以调用其他 Hook，实现逻辑复用
C. useMemo 缓存计算结果，useCallback 缓存函数引用
D. useCallback 返回的函数引用在每次渲染时都会变，所以没有缓存意义
答案 ABC。A 的原因：React 按调用顺序存储 Hook 状态，条件调用会顺序错乱。D 错：useCallback 依赖不变时返回同一个引用，正是为了让 React.memo 的子组件跳过重渲染。来源：JavaGuide 收录题型。

输出题4. 按知识点梳理里的 Timer 组件：初始 useState(0)，effect 依赖 []，setInterval 每秒执行 setCount(count + 1)。问：① 页面最终显示几？② 把回调改成 setCount(c => c + 1) 后呢？③ 解释①的现象。

先自己跑一遍脑子，再展开对答案① 永远显示 1：effect 只跑一次，interval 回调捕获的是第一帧渲染的 count=0，每秒执行的都是 setCount(0+1)，页面从 0 变 1 后再也不动。② 改函数式更新后每秒 +1，页面 1、2、3……持续增长——回调不再读闭包里的 count，而是把"上一个最新值"交给 React。③ 本质：函数组件每次渲染都是一次独立函数执行、各自持有当次的 state 闭包；依赖 [] 把 effect 和它的闭包冻在了第一帧。同类翻车：事件监听器里读旧 state、异步请求回调里读旧 state，解法一致（函数式更新/useRef/补全依赖）。来源：面试高频改编。

面试口述5. "什么是闭包陷阱？怎么解决？"以及一句带过 useEffect 该怎么理解。

参考回答现象：定时器/订阅/异步回调里 setState 读到的永远是旧的 state（计数器卡在 1 是标准例子）。原因：函数组件每次渲染生成独立闭包，effect 若依赖 [] 只执行一次，回调被冻结在第一次渲染的那份闭包里。解法：① 函数式更新 setCount(c => c + 1)，把"怎么算"交给 React、以最新值为基准；② 用 useRef 存一份最新值，回调读 ref.current；③ 从根上讲是依赖数组漏了 count——补全依赖让 effect 重建（定时器场景要配合清理函数避免 interval 叠加）。useEffect 理解：别硬套 componentDidMount/DidUpdate，把它当"渲染后同步副作用"，依赖数组声明的是这份同步用了哪些外部数据。来源：牛客经典题。

四、易错点小结

① setState 直接传值连调三次只 +1，函数式更新才连续生效；② effect 漏写清理函数：依赖一变旧定时器/订阅不销毁，越积越多（"定时器翻倍"）；③ 依赖数组"骗" React（故意漏依赖）是闭包陷阱的头号来源——要么补全依赖，要么用函数式更新/useRef 明确绕开；④ useMemo/useCallback 不是免费的，无 memo 子组件时白缓存，面试能说出"按需使用"是加分项；⑤ 把 useEffect 当生命周期逐个对号入座会写出依赖地狱——先问"我要同步什么"。
