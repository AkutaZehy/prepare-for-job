Vue Router 与 Pinia/Vuex

适用岗位：前端、通用软开 ｜ 形态：模式对比 + 守卫场景题 ｜ 更新：2026-09-30
要点速记：hash 模式 URL 带 #、# 后内容不发给服务器所以刷新永不 404；history 模式靠 pushState + popstate、刷新时路径作为真实请求发出，服务器必须配置 fallback 到 index.html。登录拦截标配：全局 beforeEach + 路由 meta.requiresAuth + 未登录 next('/login')。路由懒加载 () => import('...') 按路由切包。Pinia 对比 Vuex：去 mutation、天然模块化、完整 TS 推断、devtools 保留。

一、知识点梳理

维度hash 模式history 模式
URL 形态example.com/#/aboutexample.com/about（好看）
原理监听 hashchange；# 后内容不会随 HTTP 请求发出pushState/replaceState 切地址 + popstate 监听后退
直接刷新请求的还是根路径，无 404 问题请求 /about 本身，服务器没这资源且未配 fallback 就 404
部署要求任意静态服务器开箱即用需服务端配置：如 nginx try_files $uri $uri/ /index.html;
SEO# 后部分不进请求，不利收录相对友好
JS · 路由配置：动态段 / 传参 / 懒加载 / meta 
const routes = [
  { path: '/user/:id',                    // 动态路由：:id 是路径段
    name: 'user',
    component: () => import('../views/User.vue'),   // 懒加载：按路由切 chunk，首屏更快
    meta: { requiresAuth: true } },       // 元信息，守卫里读 to.meta
  { path: '/about', component: About }
];

// 跳转 + 传参两种姿势
router.push({ path: '/user/1', query: { tab: 'post' } });
//  → /user/1?tab=post   query 拼在 URL 上，刷新不丢，取：route.query.tab

router.push({ name: 'user', params: { id: '1' } });
//  → /user/1            params 必须配动态段 :id（按 name 跳），随路径走，刷新不丢
//  ✗ router.push({ path: '/user', params: { id: '1' } })
//    Vue Router 4 里 path + params 组合 params 会被忽略
JS · 导航守卫三层 + 登录拦截标准写法 
// 三层：全局（beforeEach / afterEach）> 路由独享（beforeEnter）> 组件内（beforeRouteEnter 等）
router.beforeEach((to, from, next) => {
  const isLogin = !!localStorage.getItem('token');
  if (to.meta.requiresAuth && !isLogin) {
    next({ path: '/login', query: { redirect: to.fullPath } });  // 未登录：去登录页并记录来路
  } else {
    next();                                   // 每个分支必须恰好调一次 next
  }
});
// Vue Router 4 也支持返回值风格：return false 取消 / return '/login' 重定向
  • 守卫记忆法：beforeEach 是"门口查票"（登录拦截主战场）；afterEach 不接收 next、不能取消导航，适合埋点改标题；组件内 beforeRouteEnter 里还没 this（实例未创建），要通过 next(vm => ...) 拿。
  • 路由懒加载：component: () => import('../views/Xxx.vue')，webpack/vite 会按这条路由单独分包，进哪个页面才加载哪个 chunk，首屏体积显著变小。
JS · Pinia：state / getters / actions 
export const useUserStore = defineStore('user', {
  state: () => ({ token: '', name: '' }),
  getters: {
    isLogin: (state) => !!state.token          // 派生值，带缓存
  },
  actions: {
    async login(form) {                        // 同步、异步都写在 actions
      this.token = await api.login(form);      // 直接改 this 上的 state
    }
  }
});
// 持久化：社区插件 pinia-plugin-persistedstate 一行接入，按 key 存 localStorage
Pinia vs Vuex说明
去掉 mutationactions 里直接改 state、支持异步；commit/mutation 那层样板代码取消
天然模块化每个 defineStore 就是独立模块，store 之间直接互相调用，无 modules 嵌套与命名空间
完整 TS 推断state/getters/actions 全链路类型推断，无需手写复杂泛型
devtools 保留时间旅行、state 快照调试照常可用

二、考点说明

笔试选择场景题面试必问

  • 笔试：hash 与 history 刷新行为差异、query 与 params 区别、beforeEach 参数、懒加载写法。
  • 面试链路："history 刷新 404 为什么"→ 服务器 fallback 配置 → hash 为什么没有这个问题 → 登录拦截怎么配 → 守卫层次 → Pinia 好在哪 → Vuex 迁移动机。
  • 场景：带 redirect 记录来路的登录流、按角色拦截、异步鉴权要等接口回来再 next。

三、示例题目（点击选项即时判分）

单选1. Vue Router history 模式的项目部署后，用户在 /about 直接刷新浏览器出现 404，正确的解释与解法是（  ）

A. 浏览器缓存了旧路由表，清缓存即可
B. history 模式刷新必定丢路由数据，属正常现象无法避免
C. 刷新把 /about 作为真实路径请求服务器，服务器无此资源；需配置所有路径 fallback 到 index.html（如 nginx try_files）
D. 应改回 hash 模式，history 模式已被废弃
答案 C。hash 模式 # 后内容不随请求发出所以刷新无此问题；history 模式的路径是真实请求，必须让服务器把未知路径都返回 index.html，由前端路由接管。两者都是官方支持的模式，按部署环境选。来源：面试高频改编。

单选2. 全局守卫 router.beforeEach((to, from, next) => {...}) 中，未登录用户访问需鉴权页面，正确的写法是（  ）

A. if (!isLogin) next(false)，然后手动 location.href 跳登录页
B. if (to.meta.requiresAuth && !isLogin) next('/login')，否则 next()
C. 只在需要拦截时调 next，放行时什么都不用调
D. next() 写不写都行，守卫函数返回后会自动放行
答案 B。标准模板：读 to.meta 判断 + 每个分支恰好调一次 next（next('/login') 重定向 / next() 放行）。漏调 next 会导致导航一直 pending、页面白屏卡死。加分点：Vue Router 4 还可用返回值风格 return '/login'。来源：牛客经典题。

多选3. 关于 Pinia 对比 Vuex，正确的有（  ）

A. 去掉了 mutation，actions 中直接改 state 且支持异步
B. 天然模块化：每个 store 独立平级，可互相引用，无 modules 嵌套和命名空间
C. 对 TypeScript 完整类型推断友好
D. Pinia 不支持 Vue devtools 调试，只能靠 console.log
答案 ABC。D 错：Pinia 保留完整 devtools 支持（state 快照、时间旅行）。反身考点：Vuex 的 mutation 必须同步，异步只能放 action 再 commit——Pinia 把这层约束整个取消。持久化用 pinia-plugin-persistedstate 插件。来源：JavaGuide 收录题型。

场景题4. 路由配置为 { path: '/user/:id', name: 'user' }。写出以下三次跳转各自的最终 URL，并说明刷新后哪个取不到值：(a) push({ path: '/user', params: { id: '1' } })；(b) push({ name: 'user', params: { id: '1' } })；(c) push({ path: '/user/1', query: { tab: 'post' } })。

先自己写 URL，再展开对答案(a) /user——Vue Router 4 中 path + params 组合里 params 被忽略，id 取不到（经典坑）；(b) /user/1——按 name 跳且配了动态段 :id，id 随路径持久，刷新后 route.params.id 仍是 '1'；(c) /user/1?tab=post——query 明文挂在 URL，刷新后 route.query.tab 还在。口诀：params 配动态段走路径、query 拼问号走 URL，都能扛刷新；扛不住刷新的是"不配动态段硬传 params"。来源：面试高频改编。

面试口述5. "后台管理系统的登录拦截你是怎么配的？"给出一套完整可讲的方案。

参考回答① 路由表给需要鉴权的页面标 meta: { requiresAuth: true }；② 全局 router.beforeEach((to, from, next) 里判断：命中 requiresAuth 且无 token → next({ path: '/login', query: { redirect: to.fullPath } })，登录成功后按 redirect 跳回原页；已登录访问 /login 反向拦截到首页；其余 next() 放行；③ 登录页等白名单页面不标 requiresAuth 自然放行；④ afterEach 里做埋点 / 动态改 document.title。加分点：异步鉴权（校验 token 有效性调接口）要先 await 再 next；Vue Router 4 可用返回值风格代替 next；token 存储与刷新方案衔接 Pinia 持久化。来源：牛客经典题。

四、易错点小结

① hash 刷新永不 404 的根因是"# 后不进 HTTP 请求"，能讲出这句才算懂；② beforeEach 里漏调 next = 导航挂起白屏，是最常见线上事故；③ path + params 在 Vue Router 4 中 params 被忽略，要按 name + 动态段；④ 懒加载是"按路由分包"，不是"不加载"——首访问该页会有一次网络请求，别在面试里说反；⑤ Pinia 持久化插件默认可全量落 localStorage，敏感 token 要控制持久化的 key 并配合过期策略，面试提 XSS 意识是加分项。
