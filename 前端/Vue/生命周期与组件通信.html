Vue 生命周期与组件通信

适用岗位：前端、通用软开 ｜ 形态：顺序输出题 + 通信选型 ｜ 更新：2026-09-30
要点速记：Vue3 挂载链 setup → beforeCreate → created → beforeMount → mounted；父子首次渲染：父 created 先于子 created，子 mounted 先于父 mounted（父先初始化才有子、子先挂完父才算挂完）；请求无 DOM 依赖放 created 更早、要操作 DOM 放 mounted；通信选型一句话：父子 props/$emit、跨层 provide/inject、任意组件复杂共享状态 Pinia；Vue3 已移除内置事件总线（$on/$off），用社区 mitt。

一、知识点梳理

Vue3 选项式 · 完整顺序 
setup()            // 组合式专属入口，先于一切选项式钩子执行
  ↓
beforeCreate       // 实例刚初始化，data/methods 还不可用
  ↓
created            // 实例初始化完成：能访问 data/methods、能发请求；仍不能碰 DOM
  ↓
beforeMount  →  mounted          // mounted 后真实 DOM 可用（this.$refs / 操作节点）
  ↓
beforeUpdate →  updated          // 数据变 → 视图更新，这一对可循环多次
  ↓
beforeUnmount →  unmounted       // 卸载，在这里清理定时器/订阅/事件监听
Vue3 · 父子首次渲染的打印顺序（输出题母题） 
父 beforeCreate → 父 created → 父 beforeMount
  → 子 beforeCreate → 子 created → 子 beforeMount → 子 mounted
→ 父 mounted

记忆：created 阶段父先（父不初始化完，子没地方挂）；
      mounted 阶段子先（渲染是自底向上完成的）。
  • keep-alive 一句：被 <keep-alive> 包裹的组件切换时不销毁，用 activated / deactivated 代替重新走 mounted/unmounted——回到页面想刷新数据就写 activated。
  • 请求放 created 还是 mounted：created 更早发出请求（不等挂载）、且 SSR 中只有 created 一侧会在服务端执行；mounted 的优势是能拿到 DOM/refs。纯客户端 SPA 里没有 DOM 依赖的请求，放 created 或组合式 setup 顶层即可；需要"挂载后量尺寸再请求"这类才必须 mounted。
  • 通信全家桶选型：
方式适用关系要点
props / $emit父子单向数据流：子组件不应直接改 prop，要 emit 让父改
v-model父子语法糖：:modelValue + @update:modelValue（Vue2 是 value + input）
ref父 → 子父持 ref 拿子组件实例直接调方法；Vue3 子组件需 defineExpose 显式暴露
provide / inject祖先 → 任意后代跨层免逐级透传（主题、当前用户等）
事件总线任意Vue3 不再内置 $on/$off，用社区库 mitt
Pinia跨组件复杂状态全局共享、可 devtools 调试，见 Router 与 Pinia/Vuex 页
Vue3 · v-model 本质 
<!-- 父组件里这两种写法完全等价 -->
<Child v-model="msg" />
<Child :modelValue="msg" @update:modelValue="msg = $event" />

<!-- 子组件：接 modelValue prop，改值时 emit update:modelValue -->
props: ['modelValue'],
emits: ['update:modelValue'],
methods: { close() { this.$emit('update:modelValue', false) } }

// 版本结论：Vue2 的 v-model 默认是 value prop + input 事件，
//          Vue3 改为 modelValue + update:modelValue，且支持多个 v-model。
//          背 Vue2 写法前先确认版本。

二、考点说明

笔试选择输出题必考面试必问

  • 笔试：钩子顺序（尤其 setup 与 beforeCreate 谁先）、父子挂载顺序输出、keep-alive 用哪个钩子、请求放哪个阶段。
  • 面试链路："说说生命周期"→ 全序列 → 父子顺序 → 请求放哪 → keep-alive → 通信方式选型 → 为什么事件总线不推荐（难维护、数据流向不可追）→ Pinia。
  • 场景：兄弟组件通信怎么办（提升状态到共同父级 / 事件总线 / Pinia）、深层透传怎么办（provide/inject 或 Pinia）。

三、示例题目（点击选项即时判分）

单选1. Vue3 中组件初始化阶段，最先执行的函数是（  ）

A. beforeCreate
B. created
C. setup
D. beforeMount
答案 C。setup 是组合式 API 的入口，先于 beforeCreate 执行——所以 setup 里还拿不到 this 和 data/methods。选项式的 data/methods 初始化发生在 beforeCreate → created 之间。版本结论：这是 Vue3 新增行为，Vue2 没有 setup。来源：面试高频改编。

单选2. 关于"首页数据请求应该放在 created 还是 mounted"，说法正确的是（  ）

A. 必须放 mounted，因为请求需要等真实 DOM 生成
B. 无 DOM 依赖的请求放 created 更早发出；SSR 场景只有 created 会在服务端执行，mounted 不会
C. 放 beforeCreate 最快，是最佳实践
D. 两者完全等价，区别只是写法不同
答案 B。created 时实例已初始化完成，可以发请求且比 mounted 更早；数据请求本身不依赖 DOM。需要拿到 $refs / 测量尺寸后再请求的，才放 mounted。SSR 中 mounted 只在客户端执行，这是"请求放 created"最硬的理由。来源：牛客经典题。

多选3. 关于 Vue3 组件通信，正确的有（  ）

A. props 单向数据流：子组件不应直接修改 prop，应 emit 事件让父组件改
B. v-model 本质是 modelValue prop 与 update:modelValue 事件的语法糖
C. Vue3 内置了 $on/$off 事件总线，可像 Vue2 一样直接用于任意组件通信
D. provide/inject 适合祖先组件向任意深度的后代传数据，免逐级透传
答案 ABD。C 错：Vue3 移除了实例上的 $on/$off/$once，官方推荐复杂状态用 Pinia、事件型通信用社区库 mitt。B 的版本结论：Vue2 是 value + input。来源：JavaGuide 收录题型。

输出题4. 父组件模板中包含 <Child />。父组件 created 打印 father created、mounted 打印 father mounted；子组件 created 打印 child created、mounted 打印 child mounted。写出首次渲染时控制台的输出顺序。

先自己排，再展开对答案顺序：father created → child created → child mounted → father mounted。原因：初始化（created 阶段）父先完成，才能开始渲染子组件；挂载（mounted 阶段）自底向上，子组件先挂载完成并回调，父组件的挂载才算完成。加分点：补上 beforeMount 同样是父先子后、mounted 是子先父后；若子组件是异步组件，父 mounted 可能先于子。来源：面试高频改编。

面试口述5. 两条链各一分钟：① Vue3 生命周期全顺序 + 请求放哪；② 父子/跨层/全局组件分别怎么通信、怎么选。

参考回答① 链背：setup → beforeCreate → created → beforeMount → mounted →（更新）beforeUpdate → updated →（卸载）beforeUnmount → unmounted；keep-alive 组件切换走 activated/deactivated 不销毁。请求：无 DOM 依赖放 created（更早、SSR 只有它执行），要操作 DOM 放 mounted。② 选型：父子 props/$emit 单向数据流；表单双向用 v-model（modelValue + update:modelValue 语法糖）；父要调子方法用 ref（Vue3 配 defineExpose）；跨层 provide/inject；Vue3 无内置事件总线用 mitt；兄弟/全局复杂共享状态直接 Pinia。加分点：点出"事件总线数据流向不可追踪、难维护"体现选型判断力。来源：牛客经典题。

四、易错点小结

① setup 里没有 this，选项式钩子里才有 this——混写时先想清楚在哪个环境；② updated 钩子里再改自身依赖的数据可能触发无限更新循环；③ keep-alive 反复切换的组件不会重新 mounted，"每次进入刷新数据"要写 activated；④ 子组件直接改 prop 只会警告不报错，但数据流向从此不可追——正确姿势是本地拷贝或 computed 包装后 emit；⑤ 请求放 created vs mounted 在纯 SPA 里差异只是"早一点点"，别背成"绝对不能放 mounted"。
