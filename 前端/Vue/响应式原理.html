Vue 响应式原理

适用岗位：前端、通用软开 ｜ 形态：原理对比 + 手写 mini 实现 ｜ 更新：2026-09-30
要点速记：Vue2 用 Object.defineProperty 递归劫持已有属性——新增/删除属性、数组按索引赋值与改 length 检测不到，所以要 $set/$delete、重写 7 个数组方法；Vue3 用 Proxy 拦截整个对象——新增/删除/索引全响应、惰性深层代理性能更好、但不支持 IE。依赖收集：Vue2 是 getter 里收 Watcher，Vue3 是 track/trigger + effect。

一、知识点梳理

维度Vue2（defineProperty）Vue3（Proxy）
监听粒度逐个属性 getter/setter，初始化时递归整个 data代理整个对象，访问到哪层才代理哪层（惰性）
新增/删除属性检测不到，需 $set/$delete原生拦截 set/deleteProperty，全响应
数组索引赋值/length 不响应；重写 push/pop/shift/unshift/splice/sort/reverse 七个方法索引、length、原型方法全拦截
Map/Set不支持支持
兼容性ES5，支持 IEES2015，不支持 IE11
  • 依赖收集闭环：渲染时读取数据 → 触发 getter → 把"当前正在渲染的 Watcher（Vue2）/ effect（Vue3）"记为该属性的依赖；数据变化 → setter / Proxy set → 通知依赖重新执行渲染。Vue3 对应 API：track(target, key) 收集、trigger(target, key) 派发。
  • 为什么 Proxy 能解决新增属性：defineProperty 只能给"已存在的属性"配 getter/setter，属性都不存在自然无劫持；Proxy 拦截的是对象操作本身（set 陷阱对任意新 key 都触发）。
  • Vue3 组合式 API 一句带过：reactive(obj) 返回 Proxy 代理（对象型）；ref(x) 给基本类型包一层 {value}（基本类型无法被 Proxy 代理）。
  • nextTick 定位：Vue 的 DOM 更新是异步批处理的（同一轮微任务合并），改完数据想拿到更新后的 DOM 要 await nextTick()。
JS · 手写 mini reactive（Vue3 思路，约 20 行） 
const targetMap = new WeakMap();      // target -> key -> Set(effect)
let activeEffect = null;

function reactive(obj) {
  return new Proxy(obj, {
    get(t, key) {                     // 依赖收集
      if (activeEffect) {
        const map = targetMap.get(t) || new Map();
        targetMap.set(t, map);
        const deps = map.get(key) || new Set();
        deps.add(activeEffect); map.set(key, deps);
      }
      return typeof t[key] === 'object' && t[key] !== null
        ? reactive(t[key]) : Reflect.get(t, key);   // 惰性深层
    },
    set(t, key, val) {                // 派发更新（新增属性也走这里）
      Reflect.set(t, key, val);
      (targetMap.get(t)?.get(key) || []).forEach(fn => fn());
      return true;
    }
  });
}

// 用法
const state = reactive({ count: 0 });
activeEffect = () => console.log('render:', state.count);
state.count++;                        // 自动打印 render: 1
state.newProp = 100;                  // 新增属性同样触发 —— Vue2 做不到
JS · Vue2 的两个经典坑 
data() { return { user: { name: 'A' }, list: [1, 2, 3] } }

// 坑1：新增属性 —— 视图不更新
this.user.age = 18;                    // ✗
this.$set(this.user, 'age', 18);       // ✓

// 坑2：数组索引 —— 视图不更新
this.list[0] = 99;                     // ✗
this.list.length = 0;                  // ✗
this.list.splice(0, 1, 99);            // ✓（重写过的7个方法）
Vue.set(this.list, 0, 99);             // ✓

三、示例题目（点击选项即时判分）

单选1. Vue2 中执行 this.list[0] = 99（list 是 data 中的数组）视图不更新，根本原因是（  ）

A. 数组是引用类型，无法被监听
B. 赋值发生在异步队列中，需要 nextTick
C. Object.defineProperty 无法劫持数组索引的赋值操作，Vue2 选择重写数组原型方法来解决
D. Vue2 的虚拟 DOM diff 忽略数组变化
答案 C。defineProperty 只能对已有属性定义 getter/setter，对数组索引逐一劫持性能差，Vue2 放弃索引劫持、改为重写 push/pop/shift/unshift/splice/sort/reverse 七个方法派发更新。来源：前端笔试高频经典题。

多选2. 相比 Object.defineProperty，Proxy 的优势包括（  ）

A. 可拦截属性新增与删除
B. 可拦截数组索引赋值与 length 修改
C. 支持 Map、Set 的代理
D. 惰性深层代理，初始化无需递归整棵对象树
答案 ABCD。四个都是 Vue3 换 Proxy 的理由。反向考点：Proxy 不支持 IE11，所以 Vue2/3 长期并行存在。来源：前端面试高频（Vue 官方迁移指南考点）。

单选3. Vue2 中以下哪种写法不能让视图正确更新？（data 中有 obj: {a: 1}）

A. this.$set(this.obj, 'b', 2)
B. this.obj.b = 2
C. this.obj = { ...this.obj, b: 2 }
D. Vue.set(this.obj, 'b', 2)
答案 B。直接给响应式对象加新属性绕过了劫持；A/D 是官方 API；C 整体替换对象引用，新对象会被重新 observe，也能更新。"替换引用也能行"是常见误区外的高分点。来源：牛客前端专项高频题。

面试口述4. 一条链讲完：数据变 → 视图变，Vue3 中间发生了什么？

参考回答组件渲染时运行 render 函数产生 effect；render 中读取响应式数据触发 Proxy 的 get 陷阱 → track 把当前 effect 记入该属性的依赖集合；随后修改数据触发 set 陷阱 → trigger 取出依赖集合里的 effect 重新调度执行（加入微任务队列批量更新，所以拿最新 DOM 要 nextTick）→ 虚拟 DOM 重新 diff、打补丁。加分点：WeakMap 做 targetMap 的内存回收优势、组件卸载时清理依赖。

四、易错点小结

① "Vue2 数组完全不响应"是错的——通过重写过的 7 个方法操作数组是响应的，不响应的只是索引赋值和改 length；② Proxy 优势别漏"惰性深层"，初始化不递归是性能卖点；③ ref vs reactive 一句话：基本类型必须 ref（Proxy 拦不住原始值），reactive 解构会失去响应（要 toRefs）；④ Vue3 的响应式针对的是数据代理，template 里 .value 漏写是新手高频 bug，面试提一嘴显细心。
