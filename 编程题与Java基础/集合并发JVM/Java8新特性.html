Java 8 新特性

适用岗位：测开(Java)、通用软开（笔试让手写 Stream 的越来越多） ｜ 形态：语法 + 手写 ｜ 更新：2026-09-30
要点速记：Lambda 只能用于函数式接口（单抽象方法，@FunctionalInterface）；捕获的局部变量必须 effectively final；Stream 流水线三段式：创建→中间操作（惰性）→终止操作，没有终止操作整条不执行；orElse 总会执行参数、orElseGet 惰性——高频输出陷阱；SimpleDateFormat 线程不安全，用 DateTimeFormatter。

一、知识点梳理

函数式接口与 Lambda：只有一个抽象方法的接口即可用 Lambda；四大内置：Function<T,R>（T 进 R 出）、Consumer<T>（消费无返回）、Supplier<T>（无参生产）、Predicate<T>（断言布尔）。Lambda 与匿名内部类的三点区别：①this 指向外部类实例（匿名类指向自身）；②只能捕获 effectively final 的局部变量（匿名类同样要求，但可写非 final 声明）；③编译产物不同（invokedynamic）。方法引用四种：静态引用 Integer::parseInt、实例方法引用 String::toUpperCase、对象方法引用 System.out::println、构造引用 ArrayList::new。

接口 default / static 方法：接口可以有方法实现，解决"接口演化"（加方法不破坏旧实现类）；多实现冲突时必须重写并可用 接口名.super.m() 指定。

Stream API（笔试手写重灾区）：三段式——

list.stream()                    // 创建流
    .filter(x -> x > 5)          // 中间操作（惰性，返回新流，可链多条）
    .map(x -> x * 2)
    .sorted()
    .distinct()
    .collect(Collectors.toList()); // 终止操作（触发整条执行）

// 面试高频：按部门分组统计 / 分组取值
Map<String, Long> cnt = emps.stream()
    .collect(Collectors.groupingBy(Emp::getDept, Collectors.counting()));
Map<String, List<Emp>> byDept = emps.stream()
    .collect(Collectors.groupingBy(Emp::getDept));
String names = emps.stream().map(Emp::getName)
    .collect(Collectors.joining(",", "[", "]"));
int total = emps.stream().mapToInt(Emp::getSalary).sum();  // 数值流避免装箱
  • 中间操作全部惰性：只有终止操作（forEach/collect/reduce/count/anyMatch…）出现才执行；无终止操作的流是"空跑"。
  • parallelStream 底层 ForkJoinPool 并行，数据小或操作有副作用时反而更慢（一句了解）。

Optional：容器对象防 NPE。of（null 直接抛异常）vs ofNullable（允许 null）；orElse(T) 的参数无论是否有值都会执行（适合常量），orElseGet(Supplier) 只在空时才调用（适合重计算）；map 链式取属性。笔试输出题常考 orElse 与 orElseGet 的副作用差异。

新时间 API（java.time）：LocalDate/LocalTime/LocalDateTime、Duration/Period、DateTimeFormatter。不可变设计线程安全——对比老 SimpleDateFormat 内部共享 Calendar，多线程并发 format 会错乱（老代码解法：ThreadLocal 包装或每次 new）。

Java 
// 经典输出陷阱：orElse 的参数照样执行
Optional<String> opt = Optional.of("java");
String r = opt.orElse(getName());      // getName() 会执行（打印1），但结果用不上
String r2 = opt.orElseGet(() -> getName()); // getName() 不执行（结果取 java）

// SimpleDateFormat 并发错乱演示（老 API）
SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd"); // 共享使用不安全
// 新 API：DateTimeFormatter 是不可变对象，随便共享
DateTimeFormatter fmt = DateTimeFormatter.ofPattern("yyyy-MM-dd");
String s = LocalDate.now().format(fmt);
Python 对照一句话：Lambda/函数式风格 Python 也有（lambda/map/filter），但 Java Stream 是强类型惰性流水线，Python 生成器是"拉"模型——两语言面试互问时用这句搭桥。

二、考点说明

笔试手写输出判断面试口述

  • 笔试手写题：用 Stream 完成过滤+映射+分组/求和（一行流），背熟 groupingBy 与 joining。
  • 输出判断：orElse vs orElseGet 副作用、Stream 无终止操作不执行。
  • Lambda 变量捕获（effectively final）与 this 指向。
  • SimpleDateFormat 并发问题与新时间 API（多选常客）。
  • 面试口述：Stream 惰性求值原理、并行流什么时候用。

三、示例题目（点击选项即时判分）

单选1. 关于 Lambda 表达式，正确的是（  ）

A. Lambda 可以替代任意接口的匿名实现
B. Lambda 表达式内部 this 指向 Lambda 自身
C. Lambda 只能用于只有一个抽象方法的函数式接口，且捕获的局部变量必须 effectively final
D. Lambda 捕获的局部变量可以直接修改
答案 C。A 缺"单抽象方法"前提；B 错——Lambda 的 this 是外层类实例（匿名内部类的 this 才是实现对象本身）；D 反了，捕获变量禁止再赋值（编译报错）。来源：牛客经典题。

单选2. list.stream().filter(x -> x > 5).peek(x -> System.out.print(x)); 执行后（  ）

A. 打印所有大于 5 的元素
B. 什么都不打印——没有终止操作，中间操作是惰性的
C. 打印一个 5
D. 编译错误
答案 B。流水线只有挂上终止操作（forEach/collect/count…）才触发整条执行；peek 属于中间操作，单独存在等于没跑。来源：牛客经典题。

单选3. Optional.of("java").orElse(getName()) 与 Optional.of("java").orElseGet(() -> getName()) 中 getName() 的执行情况是（  ）

A. 前者执行、后者不执行（Optional 已有值）
B. 都执行
C. 都不执行
D. 前者不执行、后者执行
答案 A。orElse 收的是"值"，实参在调用前就要算出来（永远执行）；orElseGet 收的是 Supplier，只在 Optional 为空时才调用——重计算场景必须用 orElseGet，这是笔试最爱的副作用陷阱。来源：面试高频改编。

多选4. 关于接口 default 方法与 Java 8 变化，正确的有（  ）

A. default 方法让接口可以在不破坏既有实现类的前提下增加方法
B. 一个类实现的两个接口含相同 default 方法时，编译器自动随机选一个
C. 实现类必须重写冲突的 default 方法，可用 接口名.super.方法名() 指定
D. 接口不能有 static 方法
答案 AC。冲突必须由实现类显式重写解决（B 错）；接口可以有 static 方法（D 错，Java 8 起支持）。来源：牛客经典题。

手写5. 给定员工列表 List<Emp>（字段 dept、salary、name），用 Stream 一行完成：按部门分组，统计每组人数。

先自己写，再展开对答案Map<String, Long> r = emps.stream().collect(Collectors.groupingBy(Emp::getDept, Collectors.counting()));。变体：分组取人 groupingBy(Emp::getDept) 得 Map<String,List<Emp>>；分组求和 Collectors.summingInt(Emp::getSalary) 或 groupingBy(d, TreeMap::new, counting()) 排序版。来源：面试高频改编。

单选6. 多线程共享同一个 SimpleDateFormat 实例并发 format，最可能出现的问题是（  ）

A. 没有任何问题，它线程安全
B. 只是速度变慢
C. 结果正确但顺序错乱
D. 日期结果错乱或抛 NumberFormatException（内部共享 Calendar 被并发写）
答案 D。SimpleDateFormat 非线程安全是老代码经典事故；Java 8 的 DateTimeFormatter 不可变、天然线程安全。老代码解法：每次 new 或 ThreadLocal 包装。来源：牛客经典题。

四、易错点小结

① Stream 三段式缺终止操作全空跑，peek 探针题就考这个；② orElse 与 orElseGet 的执行时机差是输出题常客；③ Lambda 捕获局部变量 effectively final——想在 Lambda 里改外面变量，用数组或 Atomic 包装绕（但别在面试里这么写）；④ 并行 stream 不是银弹：小数据/有 IO 副作用时更慢；⑤ 老 SimpleDateFormat 不安全、新 DateTimeFormatter 安全——Java 8 新时间 API 出题都围绕这一点。
