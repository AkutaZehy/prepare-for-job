类加载与双亲委派

适用岗位：测开(Java)、通用软开（"双亲委派"面试点名率极高） ｜ 形态：流程 + 代码 ｜ 更新：2026-09-30
要点速记：类生命周期七步，加载到初始化五步是 JVM 的事；准备阶段静态变量赋零值，static final 常量才在准备期直接赋真值；初始化即执行 <clinit>（静态变量赋值+静态块合并，JVM 保证线程安全）——被动引用不触发（数组定义、引用常量、经子类引用父类静态字段）；三层加载器 + 双亲委派（先交父亲，父亲不行才自己干）：防重复加载 + 防核心类被篡改；打破它：SPI 线程上下文加载器、Tomcat 隔离、自定义加载器重写 findClass。

一、知识点梳理

类生命周期：加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载。前五步是类加载机制考点。

阶段干什么高频考点
加载读 .class 字节流 → 方法区类元信息 + 堆中 Class 对象Class 对象是反射入口
验证格式/元数据/字节码/符号引用校验防恶意字节码
准备为静态变量分配内存并赋零值static int a=1 此刻 a=0；static final int A=1 是常量，准备期即 1（ConstantValue）
解析常量池符号引用 → 直接引用—
初始化执行 <clinit>：静态变量真赋值 + static 块，按源码顺序JVM 保证 clinit 加锁线程安全（单例-静态内部类版利用它）

何时触发初始化（主动引用六场景）：new / 读写静态字段（非 final 常量）/ 调用静态方法 / 反射 Class.forName / 初始化子类连带父类 / main 所在主类。被动引用不触发：ClassName[] arr 定义数组、引用 final 常量（编译期入池）、通过子类名访问父类静态字段（只初始化父类）。

类加载器三层（JDK8 口径，JDK9 扩展→平台）：Bootstrap（核心库，C++ 实现，无 Java 对象）→ Extension（JDK9 后 Platform）→ Application（classpath，默认加载器）→ 自定义。判定相等：同加载器 + 同类全限定名，缺一不可。

双亲委派：收到加载请求先委托父加载器，父辈全部失败才自己尝试。两个价值：①防止重复加载（父辈加载过就用父辈的）；②安全——java.lang.String 永远由 Bootstrap 加载，用户自写同名的 java.lang.X 会被拒绝，核心 API 不可能被篡改。

打破双亲委派（面试三连）：

  • SPI（JDBC DriverManager）：核心库要加载厂商实现（在 classpath），Bootstrap 反过来求 Application 加载——用线程上下文类加载器逆向委托；
  • Tomcat：每个 webapp 独立 ClassLoader 实现应用隔离（不同应用可用不同版本依赖），自身优先（WebAppClassLoader 先自己找）——破坏"先委托"；
  • 热部署/热替换：重新加载修改过的类。
Java 
// 自定义类加载器：重写 findClass（loadClass 里的委派逻辑保持不变）
public class MyLoader extends ClassLoader {
    private final String dir;
    public MyLoader(String dir, ClassLoader parent) { super(parent); this.dir = dir; }

    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        byte[] data = loadBytes(name);            // 自定义来源：文件/网络/加密类...
        if (data == null) throw new ClassNotFoundException(name);
        return defineClass(name, data, 0, data.length);  // 字节 → Class 对象
    }
    private byte[] loadBytes(String name) { /* 读 dir/name.class，略 */ return null; }
}

继承要点：重写 findClass 保住双亲委派；重写 loadClass 才是真正打破委派。

二、考点说明

笔试选择面试必问

  • 准备阶段变量值判断（选择题常客：a=0 还是 1）。
  • 主动/被动引用的初始化触发判断（多选）。
  • 双亲委派流程、两个价值、谁加载了什么（String → Bootstrap）。
  • 打破双亲委派的场景与原因（SPI/Tomcat）。
  • 面试：手写自定义类加载器思路、静态内部类单例为什么线程安全（clinit 加锁）——与设计模式页联动。

三、示例题目（点击选项即时判分 / 口述题先自答）

单选1. 类中有 static int a = 1; 与 static final int B = 2;，则准备阶段结束后 a 与 B 的值分别是（  ）

A. 1 和 2
B. 0 和 2
C. 0 和 0
D. 1 和 0
答案 B。准备阶段普通静态变量只赋零值（a=0），真正的赋值 1 在初始化的 <clinit> 里执行；static final 修饰的编译期常量有 ConstantValue 属性，准备期就直接赋真值 2。来源：牛客经典题。

多选2. 下列情形中，会触发类初始化的有（  ）

A. new 一个该类的实例
B. 访问该类的静态非 final 字段
C. 定义该类的数组：ClassName[] arr = new ClassName[10]
D. 初始化该类的子类
答案 ABD。C 是被动引用——数组定义只触发数组类型（[LClassName;）相关初始化，不触发元素类；另一类被动引用是访问编译期常量（static final）。来源：408 外 Java 笔试高频（牛客经典题）。

单选3. 用户代码里自己写了一个 java.lang.String 类并放入 classpath，运行时实际使用的是（  ）

A. 应用类加载器加载的用户版 String
B. 编译时随机选择一个版本
C. Bootstrap 加载的 rt.jar 里的核心 String（双亲委派 + 核心类保护）
D. 运行直接报错，程序无法启动
答案 C。应用类加载器一路向上委托，Bootstrap 一定能加载核心 String，用户的同名类永远没机会加载；这正是双亲委派"防核心 API 被篡改"价值的具象化。来源：面试高频改编。

多选4. 关于打破双亲委派，正确的有（  ）

A. JDBC 的 DriverManager 通过线程上下文类加载器加载厂商的驱动实现
B. Tomcat 各 webapp 共用一个类加载器以保证依赖一致
C. 自定义加载器重写 loadClass（而非 findClass）才能真正绕过委派流程
D. 双亲委派是 JVM 强制规范，任何框架都不能打破
答案 AC。B 反了——Tomcat 恰恰每个 webapp 独立加载器做应用隔离；双亲委派只是推荐模型（Java 规范建议），SPI/Tomcat/热部署都是现实中的打破者。来源：面试高频改编。

面试口述5. 什么是双亲委派？它解决了什么问题？怎么打破？

参考回答流程：类加载请求先交给父加载器处理，逐级上抛到 Bootstrap，父辈都加载不到才由当前加载器自己 findClass。解决两个问题：①同一类只会被加载一次（父辈有就用父辈的），保证类的唯一性；②核心类永远由 Bootstrap 加载，用户伪造 java.lang.X 会被拒绝，保证安全。打破方式：重写 loadClass 绕过委派逻辑；现实动因——SPI 里核心库需要反向加载 classpath 的实现（线程上下文类加载器）、Tomcat 需要 webapp 隔离与版本共存、热部署需要重复加载。答完主动补一句"自定义加载器重写 findClass 保持委派、重写 loadClass 才打破"，层次立现。

四、易错点小结

① 准备 vs 初始化：普通静态变量准备期是零值，final 常量准备期即真值——选择题最爱；② clinit 由 JVM 加锁执行，两个线程同时初始化一个类会阻塞——静态内部类单例的线程安全就靠它；③ 触发初始化的是"主动引用"，数组定义与 final 常量是被动引用；④ 判断类相等 = 同一加载器 + 同一全限定名，双亲委派保证核心类唯一；⑤ findClass 与 loadClass 的分工是自定义加载器的面试陷阱题。
