集合框架总览与 ArrayList / LinkedList

适用岗位：测开(Java)、通用软开（集合选型与扩容是笔试常客） ｜ 形态：结构 + 对比大表 + 代码 ｜ 更新：2026-09-30
要点速记：两棵树——Collection（List/Set/Queue）与 Map；ArrayList = Object[]，默认容量 10（懒初始化）、扩容 1.5 倍（oldCap + (oldCap >> 1)），随机访问 O(1)、中间插删 O(n)；LinkedList = 双向链表兼 Deque，头尾插删 O(1)、访问 O(n)；HashSet 内部就是 HashMap；TreeSet 红黑树排序；遍历删除只用 iterator.remove() / removeIf；Arrays.asList 是定长列表，add/remove 直接抛异常。

一、知识点梳理

两棵继承树（文字版）。其中 HashMap 原理详见 HashMap 全解，并发集合详见 ConcurrentHashMap 与线程安全集合。

Iterable
   └─ Collection
        ├─ List（有序、可重复）
        │    ├─ ArrayList   ：Object[] 动态数组，随机访问快
        │    ├─ LinkedList  ：双向链表，另实现了 Deque（兼作队列/栈）
        │    └─ Vector      ：古老线程安全版（方法 synchronized），已过时
        ├─ Set（不可重复）
        │    ├─ HashSet           ：哈希表（内部就是一个 HashMap）
        │    │    └─ LinkedHashSet：哈希表 + 双向链表，保持插入序
        │    └─ TreeSet           ：红黑树（内部 TreeMap），按 key 排序
        └─ Queue（队列）
             ├─ Deque（双端队列） ：ArrayDeque / LinkedList
             └─ PriorityQueue    ：二叉堆，出队按优先级

Map（独立接口，不继承 Collection）
   ├─ HashMap            ：数组+链表+红黑树，无序
   │    └─ LinkedHashMap ：哈希表+双向链表，保插入序/访问序（可做 LRU）
   ├─ TreeMap            ：红黑树，key 有序
   ├─ Hashtable          ：古老线程安全版，已过时
   └─ ConcurrentHashMap  ：并发首选

ArrayList：底层 Object[]；JDK8 中默认构造是空数组，默认容量 10 懒初始化——首次 add 才分配；扩容公式 newCap = oldCap + (oldCap >> 1)（1.5 倍，整数右移取整），容量轨迹 10→15→22→33→49；get/set 随机访问 O(1)（实现了 RandomAccess 标记接口）；中间插删要 System.arraycopy 搬移元素 O(n)，尾部添加均摊 O(1)。

LinkedList：双向链表，同时实现 List 与 Deque；头尾插删 O(1)；按下标访问 O(n)（会从较近一端折半方向遍历，但复杂度量级不变）。当队列/栈用，工程上更推荐 ArrayDeque（性能更好——面试加分句）。

Vector：方法级 synchronized 的古老线程安全 List，开销大、迭代仍需外部同步，官方已不推荐；现代替代：读多写少用 CopyOnWriteArrayList，一般并发用 Collections.synchronizedList 或并发包。

Set 三兄弟：HashSet 底层就是一个 HashMap，元素作 key 存入（value 是共享的 PRESENT 哑对象），去重靠 hashCode 定桶 + equals 判等，允许一个 null；LinkedHashSet 在其上加了双向链表维持插入序；TreeSet 内部是 TreeMap，元素按 key 排序（默认自然序下插入 null 抛 NPE，因为要比较）。

Comparable vs Comparator：Comparable（java.lang）= 自然序，类自身实现 compareTo，一个类只有一种、一锤定音；Comparator（java.util）= 定制序，外部比较器，可以准备多个、用 lambda 现写，类不用改（String 是 final 改不了，就靠它）。TreeSet/TreeMap/PriorityQueue/Arrays.sort 都接受 Comparator 重载。

遍历删除的正确姿势：for-each 中直接 list.remove 会触发 fail-fast 抛 ConcurrentModificationException（modCount 校验，机制与 HashMap 全解 中讲的完全同源）；正解是 iterator.remove() 或 JDK8 的 removeIf。按下标普通 for 循环删除另有漏删坑（删除后元素前移，i 不回退会跳元素），需倒序删或 i--。

Arrays.asList 的定长陷阱：返回的是 Arrays 的内部类 java.util.Arrays$ArrayList（不是 java.util.ArrayList）——①定长：add/remove 抛 UnsupportedOperationException，set 可以；②写透：set 会改到底层原数组；③基本类型数组整型数组 int[] 传入会被当成"一个元素"得到 List<int[]>。要可变列表用 new ArrayList<>(Arrays.asList(...)) 拷贝一份；JDK9 的 List.of(...) 则是完全不可变。

Java 
// 扩容观察（JDK8）：默认构造是空数组，容量 10 懒初始化
List<Integer> list = new ArrayList<>();
for (int i = 1; i <= 11; i++) {
    list.add(i);                        // 第 11 个触发扩容：10 + (10 >> 1) = 15
}
// 容量轨迹：10 → 15 → 22 → 33 → 49（1.5 倍，整数右移取整）

// 遍历删除的正确姿势
List<String> l = new ArrayList<>(Arrays.asList("a", "b", "c", "d"));
l.removeIf(s -> s.equals("b"));         // JDK8 推荐：内部就是迭代器安全删除
Iterator<String> it = l.iterator();
while (it.hasNext()) {
    if (it.next().equals("a")) it.remove();   // 唯一安全的"边遍历边删"
}
Java 
// Arrays.asList 三连坑
String[] arr = {"a", "b", "c"};
List<String> fixed = Arrays.asList(arr);  // Arrays$ArrayList：定长包装
fixed.set(0, "x");                        // OK，且写透：arr[0] 也变成 "x"
fixed.add("d");                           // 运行时抛 UnsupportedOperationException

int[] nums = {1, 2, 3};
List<int[]> wrong = Arrays.asList(nums);  // 整个数组被当成 1 个元素！
List<Integer> right = Arrays.stream(nums)
        .boxed().collect(Collectors.toList());   // 正确：先装箱再收集
Python 
# Python list 是动态数组（定位同 ArrayList），扩容按超额分配增长（不是固定 1.5 倍）
lst = [1, 2, 3]
lst.append(4)              # 尾部均摊 O(1)，同 ArrayList.add
lst.pop(0)                 # 头部删除 O(n) 要整体搬移 —— 头部操作选 deque
from collections import deque

dq.appendleft(0); dq.pop() # 双端 O(1)，对应 Java 的 ArrayDeque / LinkedList(Deque)
# set/dict 基于哈希表；dict 从 3.7 起语言级保证插入序（Java 对应 LinkedHashMap）

三、示例题目（点击选项即时判分）

计算1. JDK8 中 new ArrayList<>() 默认构造后依次 add 元素：加到第 11 个元素后、再继续加到第 16 个元素后，内部数组容量分别是多少？写出计算过程。

先自己算，再展开对答案默认构造时数组为空（懒初始化），首次 add 按默认容量 10 分配——前 10 个元素容量一直是 10。加第 11 个时数组已满，触发扩容：newCap = 10 + (10 >> 1) = 10 + 5 = 15。加第 16 个时（前 15 个已装满容量 15 的数组）：newCap = 15 + (15 >> 1) = 15 + 7 = 22。完整轨迹：10 → 15 → 22 → 33 → 49。考点就两句话：容量 10 懒初始化 + 1.5 倍整数右移取整。来源：牛客经典题。

多选2. 下列集合类中，属于线程安全的有（  ）

A. Vector
B. ArrayList
C. CopyOnWriteArrayList
D. Hashtable
答案 ACD。Vector/Hashtable 是方法级 synchronized 的古老安全版；CopyOnWriteArrayList 靠写时复制实现读无锁的安全。ArrayList/LinkedList/HashMap/HashSet/TreeMap 全家线程不安全，并发场景分别对应 CopyOnWriteArrayList 与 ConcurrentHashMap（详见 ConcurrentHashMap 与线程安全集合）。来源：牛客经典题。

单选3. 业务场景：绝大多数操作是按下标随机读取和尾部追加，偶尔中间插入。最合适的实现是（  ）

A. LinkedList，头尾插删 O(1)
B. ArrayList，随机访问 O(1)、尾部均摊 O(1)
C. Vector，线程安全优先
D. PriorityQueue，出队有序
答案 B。ArrayList 的 get/set 是 O(1) 数组寻址；LinkedList 随机访问要从头/尾遍历 O(n)，"插删快"只对已定位位置的头尾成立，按位插删要先 O(n) 找位置。Vector 有同步开销且已过时。选型口诀：查多用 ArrayList，头尾插删多/当队列才想 LinkedList。来源：面试高频改编。

单选4. 需要 TreeSet<String> 按字符串长度排序，而 String 是 final 类、内部 compareTo 固定为字典序。最合适的做法是（  ）

A. 修改 String 类，让它重新实现 Comparable
B. new TreeSet<>((a, b) -> a.length() - b.length()) 传入 Comparator
C. 改用 HashSet，去重后自然有序
D. 把字符串逐个插入 ArrayList，HashMap 会自动排序
答案 B。类改不了（final）或需要多种排序规则时，用外部 Comparator 定制序，TreeSet 构造器直接接收；Comparable 是类内的自然序，只此一种。C 错——HashSet 无序；D 错——HashMap 更不排序。来源：面试高频改编。

输出判断5. 以下代码的运行结果是（  ）

String[] arr = {"a", "b", "c"};
List<String> list = Arrays.asList(arr);
list.set(0, "x");
System.out.println(list.get(0) + "/" + arr[0]);
list.add("d");
A. 打印 x/a，随后正常结束
B. 打印 x/x，随后抛 UnsupportedOperationException
C. 打印 x/x，随后抛 ConcurrentModificationException
D. 第一行就编译错误
答案 B。Arrays.asList 返回定长的 Arrays$ArrayList：set 允许，且写透到底层数组——arr[0] 被一起改成 "x"，所以打印 x/x；add/remove 才是定长列表的禁区，抛 UnsupportedOperationException。C 的 ConcurrentModificationException 是迭代中结构性修改才触发的，这里没有迭代。来源：牛客经典题。

面试口述6. HashSet 是怎么保证元素不重复的？为什么重写 equals 必须重写 hashCode？

参考回答HashSet 底层就是一个 HashMap：元素作为 key 存入，value 是共享的哑对象。添加时先调 hashCode 定位桶，再在桶内用 equals 逐个判等，两者都"相同"才认定为重复、拒绝插入。如果只重写 equals 不重写 hashCode，两个"相等"对象的 hashCode 不同，会被散到不同桶， equals 根本没机会执行——于是去重失效，HashMap 也会"放进去取不出来"。加分点：LinkedHashSet 保插入序、TreeSet 走 compareTo 排序判重。来源：JavaGuide 收录题型。

四、易错点小结

① 扩容 1.5 倍 = oldCap + (oldCap >> 1)，轨迹 10→15→22→33，别和 HashMap 的 2 倍搞混；② 默认构造是空数组，容量 10 首次 add 才分配（懒初始化，与 HashMap 延迟建表同思想）；③ Arrays.asList 三坑：定长、写透原数组、基本类型数组变单元素；④ for-each 中 remove 抛 CME（fail-fast，见 HashMap 全解），正解 iterator.remove()/removeIf；⑤ Vector/Hashtable 只在"线程安全归类"题里出场，工程一律并发包替代。
