HashMap 全解

适用岗位：测开(Java)、通用软开（面试问到源码级的头号热门） ｜ 形态：原理 + 代码 ｜ 更新：2026-09-30
要点速记：JDK8 = 数组 + 链表 + 红黑树；容量永远是 2 的幂，定位用 (n−1) & hash；默认容量 16、负载因子 0.75（放第 13 个元素后扩容一倍）；树化 = 链表长度 8 且数组容量 ≥ 64，退化阈值 6；hash 扰动 (h ^ (h >>> 16)) 让高位参与运算；JDK7 头插并发扩容成环死循环，JDK8 改尾插；允许一个 null 键，线程不安全（并发用 ConcurrentHashMap）。

一、知识点梳理

put 全流程（JDK8，面试背诵版）：①计算 key 的 hash（高 16 位异或低 16 位扰动）→ ②若 table 为空，延迟到首次 put 才分配数组（resize）→ ③(n−1)&hash 定位桶，桶空直接放 → ④桶首节点 key 相同（hash 相等且 equals 真）则覆盖 → ⑤否则遍历链表尾插，长度达 8 且容量 ≥ 64 转红黑树 → ⑥插入后 size 超过阈值（容量×0.75）触发 resize 扩容一倍 → ⑦旧表元素按"hash & oldCap 是否为 0"拆成 lo/hi 两条链，分别留在原位或移到"原位+oldCap"，无需重算 hash。

高频数字值为什么
默认容量 / 负载因子16 / 0.750.75 是空间利用率与碰撞概率的折中（泊松分布下桶内超过 8 个的概率约千万分之一）
树化 / 退化阈值8 / 68 对应泊松分布的极小概率事件；6 留缓冲防止 8↔7 反复树化拆化
树化最低容量64表太小时优先扩容而不是树化（扩容就能拆短链表）
扩容容量×2保持 2 的幂，使 (n−1)&hash 等价于取模且迁移位固定

为什么容量必须是 2 的幂：①(n−1)&hash 在 n=2 的幂时等价于 hash % n，位运算远快于取模；②n−1 的二进制全 1（如 16−1=1111），与运算能均匀散列；③扩容时元素新位置 = 原位置 或 原位置+旧容量，由 hash & oldCap 一位判定，迁移极快。

为什么 hash 要扰动：若只用 hashCode 低几位与 (n−1) 相与，高位信息全被丢弃，碰撞集中；(h ^ (h>>>16)) 把高 16 位异或进低 16 位，让高位也参与定位。

JDK7 vs JDK8 对比表：

维度JDK7JDK8
结构数组 + 链表数组 + 链表 + 红黑树
插入方式头插（并发扩容可能成环→死循环）尾插（并发扩容仍可能丢数据，只是不成环）
扩容时机先扩容后插入先插入后判断扩容
hash 计算4 次扰动1 次高低位异或

线程不安全的表现：JDK7 并发扩容链表成环（get 时 CPU 100%）；JDK8 并发 put 仍会覆盖丢失数据。所以并发场景用 ConcurrentHashMap（详见「线程基础与 synchronized」所属子类的并发主题页，此处不展开）。

其他要点：允许 1 个 null 键、多个 null 值（null 的 hash 恒为 0）；fail-fast——迭代期间结构性修改抛 ConcurrentModificationException（modCount 校验），遍历删除用 iterator.remove()；equals 相等的两个 key 必须有相同 hashCode（否则 HashMap 定位错乱——重写 equals 必须重写 hashCode 的原因）。

Java 
// 简版实现（数组+单链表），覆盖核心考点：hash 定位、覆盖、拉链
class SimpleMap<K, V> {
    private static final int CAP = 16;
    private Node<K, V>[] table = new Node[CAP];

    static class Node<K, V> { K k; V v; Node<K, V> next;
        Node(K k, V v, Node<K, V> n) { this.k = k; this.v = v; next = n; } }

    public void put(K k, V v) {
        int i = (CAP - 1) & hash(k);          // 定位桶：等价于取模
        for (Node<K, V> n = table[i]; n != null; n = n.next) {
            if (n.k.equals(k)) { n.v = v; return; }   // 覆盖
        }
        table[i] = new Node<>(k, v, table[i]);        // 拉链
    }
    public V get(K k) {
        for (Node<K, V> n = table[(CAP - 1) & hash(k)]; n != null; n = n.next)
            if (n.k.equals(k)) return n.v;
        return null;
    }
    private int hash(K k) { return k == null ? 0 : k.hashCode() ^ (k.hashCode() >>> 16); }
}

二、考点说明

笔试选择面试必问口述 put 流程

  • 笔试：树化两个条件、阈值数字、容量 2 的幂、负载因子、null 键、fail-fast。
  • 面试："讲讲 put 流程"（按七步背）、"为什么容量是 2 的幂"、"1.7 和 1.8 区别"、"什么时候退化成 O(n)"（链表退化/哈希不均，树化后 O(logn)）。
  • 追问链：HashMap 线程不安全 → ConcurrentHashMap → 锁的粒度（CAS+synchronized 锁桶头），一环扣一环要接得住。

三、示例题目（点击选项即时判分）

多选1. JDK8 中 HashMap 链表转红黑树的条件包括（  ）

A. 链表长度达到 6
B. 链表长度达到 8
C. 数组容量达到 64
D. 数组容量不足 64 时优先扩容而不是树化
答案 BCD。两个条件缺一不可：链表 ≥ 8 且 数组容量 ≥ 64；容量不足 64 时走 resize 拆链。A 把退化阈值 6 当树化阈值。来源：牛客经典题。

单选2. HashMap 容量必须是 2 的幂，最主要的原因是（  ）

A. (n−1)&hash 在此时等价于取模运算，且扩容时元素迁移只需判断一位
B. 2 的幂能让红黑树更快平衡
C. 这是 JVM 内存对齐的强制要求
D. 2 的幂能避免 null 键冲突
答案 A。两个红利都在位运算上：定位快（与代替模）、迁移快（hash & oldCap 判断 0/1 决定原地或原位+oldCap）。来源：面试高频改编。

单选3. new HashMap<>(19) 后首次 put 完成时，table 数组的容量是（  ）

A. 19
B. 38
C. 32
D. 16
答案 C。构造器只把阈值算成 tableSizeFor(19)=32，数组要等首次 put 才分配；tableSizeFor 找"≥ 给定值的最小 2 的幂"，19 → 32。注意两点结合考：延迟初始化 + 向上取 2 的幂。来源：牛客经典题。

单选4. JDK7 中并发使用 HashMap 扩容可能导致链表成环的根因是（  ）

A. 红黑树退化成链表
B. 头插法在两个线程同时迁移链表时改变指针指向，形成环形引用
C. 负载因子 0.75 太大
D. modCount 没有加锁
答案 B。头插让新节点插到链表头，两线程交错迁移会把 e→next 反转两次指向彼此成环，之后 get 该桶就死循环 CPU 100%。JDK8 改尾插解决成环，但并发 put 仍会丢数据——HashMap 从来不是线程安全的。来源：面试高频改编。

面试口述5. 背一遍 JDK8 的 put 流程（不看资料）。

参考回答①算 key 的 hash（高低 16 位异或扰动）；②table 空则 resize 延迟初始化；③(n−1)&hash 找桶，空则直接放；④桶首节点 hash 相同且 equals 真则覆盖；⑤否则遍历链表尾插，长度到 8 且容量 ≥64 树化；⑥插入后 size 超过 容量×0.75 就扩容一倍，元素按 hash&oldCap 拆两条链迁移；⑦扩容后重新检查树化/退化。加分点：说出"先插入后判断扩容（1.8）"、null 键恒放 0 号桶、覆盖时返回旧值。

单选6. 关于 HashMap 遍历中删除元素，正确的是（  ）

A. 用 for-each 直接 map.remove(k) 最简洁安全
B. HashMap 遍历顺序与插入顺序一致
C. fail-fast 机制保证并发修改时不丢数据
D. 应使用迭代器的 iterator.remove()，或 Java 8 的 map.entrySet().removeIf(...)
答案 D。for-each 中直接 remove 会触发 fail-fast 抛 ConcurrentModificationException（modCount 与 expectedModCount 不一致）；B 错——HashMap 遍历顺序由 hash 定位决定，不保证任何顺序（有序用 LinkedHashMap/TreeMap）；C 只抛异常预警，不保证数据安全。来源：牛客经典题。

四、易错点小结

① 数字三兄弟别混：树化 8、退化 6、最小树化容量 64；负载 0.75 是"容量×0.75"的阈值系数；② JDK8 默认构造不分配数组，首次 put 才建（容量按构造参数向上取 2 的幂）；③ "线程不安全"在 JDK8 的表现是数据覆盖丢失而不是死循环（成环是 1.7 头插专属）；④ 重写 equals 必须重写 hashCode——HashMap 定位先 hash 后 equals，hashCode 不一致会导致"放进去取不出来"；⑤ removeIf / iterator.remove 是遍历删除唯二正解。
