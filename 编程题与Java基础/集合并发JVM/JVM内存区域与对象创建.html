JVM 内存区域与对象创建

适用岗位：测开(Java)、通用软开（面试 JVM 第一问） ｜ 形态：概念 + 代码 ｜ 更新：2026-09-30
要点速记：五个运行时区域——程序计数器、虚拟机栈、本地方法栈线程私有；堆、方法区线程共享；JDK8 方法区由永久代改为元空间（用本地内存）；对象创建五步：类加载检查→分配内存（碰撞/空闲列表 + TLAB）→零值初始化→设对象头→执行构造；堆分代 Eden:S0:S1 = 8:1:1；内存泄漏=对象不再用却回收不掉，溢出=内存真不够。

一、知识点梳理

区域共享/私有存什么异常
程序计数器私有当前线程执行字节码的行号指示器（唯一不会 OOM 的区域）无
虚拟机栈私有栈帧：局部变量表、操作数栈、动态链接、方法出口StackOverflowError（深度超限）；OutOfMemoryError
本地方法栈私有native 方法服务同上
堆共享对象实例与数组；分代：新生代（Eden+S0+S1）+ 老年代OutOfMemoryError: Java heap space
方法区共享类元信息、运行时常量池、静态变量、JIT 代码缓存OutOfMemoryError: Metaspace（JDK8+）
  • JDK8 的关键变化：方法区的实现由永久代（PermGen，JVM 堆的一部分）改为元空间 Metaspace——使用本地内存，默认无上限（可 -XX:MaxMetaspaceSize 限制），动机是消除永久代 OOM 与调参困难；字符串常量池早在 JDK7 就已移入堆。
  • 对象创建五步：①遇到 new，先检查类是否已加载（没有则先执行类加载，见类加载与双亲委派页）；②分配内存——指针碰撞（堆规整时）或空闲列表（堆不规整时），并发安全用 TLAB（每个线程在 Eden 预分配一小块私有缓冲，先在自己 TLAB 里分配，用尽才加锁分配新 TLAB）；③零值初始化（字段设默认值，所以字段不初始化也能读到 0/null）；④设置对象头（GC 分代年龄、哈希码、锁标志——锁升级的载体）；⑤执行 <init> 构造方法。
  • 对象内存布局：对象头（Mark Word + 类型指针）+ 实例数据 + 对齐填充（8 字节整数倍）。
  • 逃逸分析：对象不逃出方法/线程时可以栈上分配（标量替换消除堆分配）、锁消除——是"Java 对象不一定在堆上"的理论依据（HotSpot 实际以标量替换形式体现）。
  • 泄漏 vs 溢出：溢出（OutOfMemoryError）= 内存不足以装下新对象；泄漏（Memory Leak）= 失效对象被 GC Roots 强引用拽着回收不掉（静态集合、ThreadLocal 不 remove、监听器未注销），泄漏持续累积最终表现成溢出。
  • 常用参数：-Xms/-Xmx（堆初值/最大）、-Xss（栈）、-XX:MaxMetaspaceSize、-XX:SurvivorRatio=8。
Java 
// ① 栈溢出：递归无出口，默认栈深约几百~几千层就抛
public class StackOverflowDemo {
    static int depth = 0;
    public static void recurse() { depth++; recurse(); }
    public static void main(String[] args) {
        try { recurse(); } catch (StackOverflowError e) {
            System.out.println("栈深度：" + depth);   // -Xss 可调栈大小
        }
    }
}

// ② 堆 OOM：往活着的集合里无限塞对象（强引用不可回收）
// 启动参数加 -Xmx32m 更快看到 OutOfMemoryError: Java heap space
List<byte[]> leak = new ArrayList<>();
while (true) {
    leak.add(new byte[1024 * 1024]);   // 每轮 1MB，被 leak 强引用拽住
}

二、考点说明

笔试选择面试必问

  • 区域归属判断：程序计数器/栈私有，堆/方法区共享（多选重灾区）。
  • JDK8 元空间变化（为什么改、存在哪）、字符串常量池位置（堆）。
  • 各类 OOM/StackOverflowError 对应哪个区域、怎么排查（详见 JVM 调优页，jmap/jstack）。
  • 对象创建流程与 TLAB；Eden:Survivor 比例。
  • 面试追问链：内存区域 → 新对象先分到哪（Eden，大对象直入老年代）→ 怎么判断回收（可达性分析，见 GC 页）。

三、示例题目（点击选项即时判分）

多选1. 下列区域中，线程共享的有（  ）

A. 虚拟机栈
B. 堆
C. 程序计数器
D. 方法区
答案 BD。堆与方法区线程共享，虚拟机栈/本地方法栈/程序计数器线程私有——私有区域的生命周期与线程相同，不需要 GC。来源：牛客经典题。

单选2. 关于 JDK8 的方法区，正确的是（  ）

A. 仍由永久代实现，位于 JVM 堆内
B. 改为元空间实现，使用 JVM 堆内存
C. 改为元空间实现，使用本地内存，字符串常量池则位于堆中
D. 方法区被彻底移除，类信息不再存储
答案 C。JDK8 用元空间（本地内存）取代永久代，两个动机：永久代大小难调、易 OOM；字符串常量池 JDK7 起已在堆里。方法区是"规范"，元空间是实现——概念与实现分离是标准答题话术。来源：面试高频改编。

单选3. HotSpot 中新生代默认 Eden : Survivor0 : Survivor1 的比例是（  ）

A. 1:1:1
B. 8:1:1
C. 4:1:1
D. 2:1:1
答案 B。Eden 占新生代 8/10（-XX:SurvivorRatio=8）；绝大多数对象朝生夕死，大 Eden 减少 Minor GC 频率，两个 Survivor 供复制算法轮换。大对象（如大数组）会绕过 Eden 直接进老年代。来源：牛客经典题。

单选4. 递归调用过深时最先出现的问题是（  ）

A. 虚拟机栈抛 StackOverflowError
B. 堆抛 OutOfMemoryError
C. 方法区抛 OutOfMemoryError: Metaspace
D. 程序计数器溢出
答案 A。每次方法调用压入一个栈帧，深度超 -Xss 限制即 StackOverflowError；方法区溢出对应"动态生成大量类"（如 CGLIB 滥用）；程序计数器唯一不会 OOM。来源：牛客经典题。

多选5. 关于对象创建与分配，正确的有（  ）

A. new 一个对象前会先检查对应类是否已加载，未加载先触发类加载
B. 对象的字段必须手动初始化，否则编译报错
C. TLAB 让每个线程在 Eden 里有一块私有分配缓冲，减少同步开销
D. 分配内存的方式有指针碰撞与空闲列表两种，取决于堆是否规整
答案 ACD。B 错：分配内存后先把字段赋零值（int=0、引用=null），这就是成员字段有默认值的原因（局部变量才必须手动初始化）。来源：面试高频改编。

面试口述6. 什么是内存泄漏？Java 里常见的泄漏场景有哪些？和内存溢出什么关系？

参考回答泄漏=已经无用的对象仍被 GC Roots 强引用链拽住、无法回收；溢出=内存确实不够分配新对象。关系：泄漏持续累积会演变成溢出。Java 常见泄漏：①静态集合长期持有对象引用；②ThreadLocal 在线程池场景不 remove（弱引用 key 被回收后 value 挂在长活线程上）；③监听器/回调注册后不注销；④连接/流未关闭。排查思路：jmap 抓堆转储 + MAT 看支配树找大对象引用链（详见 JVM 调优页）。加分点：能说出"弱引用做 key 正是为了缓解泄漏，但没有 remove 铁律救不了 value"。

四、易错点小结

① 程序计数器是唯一不会 OOM 的区域；② "方法区被移除了"是错误说法——移除的只是永久代这个实现，方法区作为规范仍在（元空间实现）；③ 字段有默认零值、局部变量没有——两者的初始化规则不同；④ 堆不规整（CMS 标记清除后）用空闲列表，规整（复制/整理后）用指针碰撞；⑤ 泄漏与溢出是因果不是同义词，面试先分定义再讲场景。
