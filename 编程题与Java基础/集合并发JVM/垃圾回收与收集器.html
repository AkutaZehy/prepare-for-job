垃圾回收与收集器

适用岗位：测开(Java)、通用软开（面试 JVM 必问） ｜ 形态：原理 + 对比 ｜ 更新：2026-09-30
要点速记：判断存活用可达性分析（Java 不用引用计数——循环引用救不了），GC Roots 包括栈引用/静态变量/常量/JNI；四种引用强软弱虚；三大算法：标记清除（碎片）、复制（新生代，无碎片费空间）、标记整理（老年代）；CMS 并发标记清除：低停顿但有碎片与浮动垃圾，已废弃；G1：Region 分区+按停顿目标优先回收价值最高的区；ZGC 一句话：着色指针、停顿亚毫秒。

一、知识点梳理

对象存活判定：引用计数法（每对象计数器，循环引用会死锁泄漏，JVM 不采用）；可达性分析——从 GC Roots 出发能摸到的就是活的。GC Roots 常考清单：虚拟机栈中引用的对象（局部变量）、方法区静态变量与常量引用的对象、本地方法栈 JNI 引用、被 synchronized 持有的对象。注意"堆内两个对象互相引用但无 Roots 可达"＝垃圾（引用计数的死穴恰是可达性分析的常规操作）。对象真正死亡前有"两次标记 + finalize() 自救一次"的机制（概念级，实际别用）。

引用类型回收时机典型用途
强引用永不回收（宁可 OOM）普通 new
软引用 SoftReference内存不足时回收缓存
弱引用 WeakReference下次 GC 必回收ThreadLocalMap 的 key、WeakHashMap
虚引用 PhantomReference形同虚设，只为回收通知堆外内存回收管理（DirectByteBuffer）

三大回收算法：

算法过程优点缺点用在
标记-清除标记活对象→直接清除简单空间碎片；效率不稳CMS
标记-复制内存分两块，活对象整体搬到另一块无碎片、分配快（指针碰撞）浪费一半空间（Survivor 优化为 10% 浪费）新生代（存活率低才划算）
标记-整理标记→活对象向一端移动→清理边界外无碎片移动对象成本高（STW 长）老年代

分代收集：新生代对象朝生夕死→复制算法（Eden+S0 存活对象复制到 S1，年龄 +1，默认 15 岁晋升老年代，或动态年龄判断：同年龄对象总和超 Survivor 一半；大对象直接进老年代避免反复复制）。GC 分类：Minor GC（新生代，频繁、快）、Full GC/Major GC（整堆或老年代，慢、应尽量避免）；Full GC 触发线索：老年代空间不足、元空间不足、System.gc() 建议、空间分配担保失败。

收集器谱系（重点 CMS 与 G1）：

收集器区域/算法特点
Serial / Serial Old单线程，STW客户端模式、小内存
ParNew / Parallel Scavenge+Old多线程并行，STW吞吐量优先（Parallel 系可设吞吐目标）
CMS（已废弃，JDK14 移除）老年代，标记-清除四阶段：初始标记(STW)→并发标记→重新标记(STW)→并发清除；优点停顿短；缺点：CPU 敏感、浮动垃圾（并发清除期新垃圾留到下次）、碎片导致提前 Full GC、并发失败退化 Serial Old
G1（JDK9 起默认）Region 分区（每区可代际角色动态变化），整体标记-整理+局部复制可预测停顿（-XX:MaxGCPauseMillis），优先回收"垃圾最多"的 Region（名字由来 Garbage First）；跨 Region 引用用 Remembered Set 记忆集；SATB 记录并发期对象变化（概念）
ZGC / Shenandoah着色指针/转发指针停顿亚毫秒级、TB 级堆（概念即可）

面试串词模板：内存区域（见 JVM 内存页）→ 怎么判定垃圾（可达性）→ 怎么收（三算法+分代）→ 谁来收（收集器演进：吞吐优先 Parallel → 停顿优先 CMS → 可控+均衡 G1 → 极致停顿 ZGC）——一条线讲下来就是满分结构。

二、考点说明

笔试选择面试必问

  • GC Roots 判断（多选：堆内对象互引不能当 Roots）。
  • 四种引用的回收时机与用途匹配。
  • 三算法优缺点与"新生代为什么用复制"。
  • CMS 四阶段与三大缺点、G1 与 CMS 的区别（多选/口述）。
  • Minor/Full GC 触发条件；对象晋升老年代的途径。

三、示例题目（点击选项即时判分 / 口述题先自答）

单选1. 下列关于垃圾判定的说法，正确的是（  ）

A. JVM 采用引用计数法，对象被引用次数为 0 即回收
B. 堆中两个对象互相引用但没有任何 GC Roots 可达，仍会被回收
C. 被静态变量引用的对象随时可能被回收
D. finalize() 方法可靠地阻止对象被回收
答案 B。可达性分析从 GC Roots 出发，互引孤岛照样回收——这正是引用计数法做不到的（计数永远 >0），也是 JVM 弃用引用计数的主因。C 反了，静态变量是 GC Roots；D 的 finalize 只能自救一次且不可靠。来源：牛客经典题。

多选2. 关于 CMS 收集器，正确的有（  ）

A. 采用标记-清除算法，会产生内存碎片
B. 并发标记与并发清除阶段用户线程仍在运行，会产生浮动垃圾
C. 因为是并发收集，全程不需要 STW
D. 并发阶段老年代分配失败可能"并发失败"退化为 Serial Old 单线程 Full GC
答案 ABD。CMS 有两段短 STW（初始标记、重新标记），C 错。碎片导致大对象放不下、预留空间跟不上浮动垃圾，都会触发退化。来源：面试高频改编。

单选3. 新生代采用复制算法收集垃圾，主要原因是（  ）

A. 新生代对象存活率高
B. 复制算法不需要额外内存空间
C. 新生代对象"朝生夕死"存活率低，复制少量存活对象成本远低于整理
D. 复制算法不会产生任何内存碎片且不浪费空间
答案 C。复制算法的成本与存活对象成正比——存活率越低越划算；D 自相矛盾（要留 Survivor 空间，牺牲 10%）。老年代存活率高，才用标记-清除/整理。来源：408 外 Java 笔试高频（牛客经典题）。

单选4. 下列哪种情况不会直接导致对象进入老年代？（  ）

A. 对象在 Survivor 区 年龄达到阈值（默认 15）
B. 新创建的大数组超过大对象阈值
C. 动态年龄判断：Survivor 中某年龄以下对象总和超过其一半
D. 对象在 Eden 区首次分配
答案 D。对象通常在 Eden 出生；进老年代的三条路：年龄达标、大对象直入、动态年龄判断提前晋升。来源：面试高频改编。

面试口述5. CMS 和 G1 的核心区别？什么场景选 G1？

参考回答①内存布局：CMS 基于连续分代，G1 把堆切成等大 Region，每个 Region 动态扮演 Eden/Survivor/Old；②算法：CMS 标记-清除（碎片），G1 整体标记-整理+Region 间复制（无碎片）；③停顿：CMS 尽力而为，G1 可以设定停顿目标（MaxGCPauseMillis），按"每个 Region 回收价值/成本"排序优先收垃圾最多的区（Garbage First 得名）；④适用：堆大（6GB+）、要求可预测低停顿选 G1。CMS 的问题（碎片/并发失败/浮动垃圾）正好是 G1 的改进点；再往新是 ZGC 停顿亚毫秒。加分：G1 跨 Region 引用靠 Remembered Set，避免全堆扫描。

四、易错点小结

① 年龄阈值默认 15 不是 16（对象头 Mark Word 里分代年龄只有 4 位）；② "Minor GC 必触发 Full GC"是错的，两者独立；③ 复制算法浪费的是 Survivor 的 10% 而不是一半（两 Survivor 轮换+Eden 占 8）；④ CMS 是"并发"，但初始/重新标记仍要 STW——"全程不停顿"是经典错误项；⑤ 强引用宁可 OOM 也不回收，软引用才是缓存首选。
