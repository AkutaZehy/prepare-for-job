设计模式与手写单例

适用岗位：测开(Java)、通用软开（单例手写是白板必考） ｜ 形态：手写代码 + 模式对照 ｜ 更新：2026-09-30
要点速记：单例五种——饿汉、懒汉加锁、双检锁（必须 volatile：防 new 三步重排序出现"半成品对象"）、静态内部类（利用类加载 clinit 线程安全，推荐）、枚举（Effective Java 首选：防反射防反序列化）；面试答模式的标准姿势是说出 Spring 里谁在用：工厂=BeanFactory、代理=AOP、模板=JdbcTemplate、观察者=事件监听、策略=Resource 加载、责任链=Filter 链。

一、手写单例五种（背到能默写）

Java 
// ① 饿汉：类加载即创建。简单线程安全；缺点：不管用不用都占内存、不能延迟加载
class Singleton1 { private static final Singleton1 I = new Singleton1();
    private Singleton1() {} public static Singleton1 get() { return I; } }

// ② 懒汉+同步方法：延迟加载，但每次 get 都抢锁，性能差
class Singleton2 { private static Singleton2 i;
    private Singleton2() {}
    public static synchronized Singleton2 get() { if (i == null) i = new Singleton2(); return i; } }

// ③ 双检锁 DCL：两次判空 + 锁类对象。volatile 必不可少！
class Singleton3 {
    private static volatile Singleton3 i;            // volatile：禁止 new 的重排序
    private Singleton3() {}
    public static Singleton3 get() {
        if (i == null) {                             // 第一次判空：多数情况免抢锁
            synchronized (Singleton3.class) {
                if (i == null) i = new Singleton3(); // 第二次判空：锁内再确认
            }
        }
        return i;
    }
}
// new 并非原子：①分配内存 ②调用构造初始化 ③引用指向内存。
// 无 volatile 时 ②③ 可能重排——另一线程在第一次判空时拿到"已赋引用但未初始化"的半成品。
// ④ 静态内部类：加载 Singleton4 时不加载 Holder，首次 get 才触发 Holder 类初始化——
// JVM 的 <clinit> 自带加锁，天然线程安全 + 懒加载（利用类加载机制，推荐）
class Singleton4 {
    private Singleton4() {}
    private static class Holder { static final Singleton4 I = new Singleton4(); }
    public static Singleton4 get() { return Holder.I; }
}

// ⑤ 枚举：Effective Java 首选。防反射（构造反射直接抛异常）、防反序列化破坏、写法最短
enum Singleton5 { INSTANCE;
    public void doWork() { }
}
// 使用：Singleton5.INSTANCE.doWork();
五种横评：饿汉最简单 / DCL 展示并发功底（面试手写它要主动讲 volatile）/ 静态内部类是"工程正确答案" / 枚举是"理论完备答案"。被问"双检锁为什么加 volatile"答出 new 三步重排序即可封神。

二、常用设计模式 × Spring 场景对照

模式一句话Spring / JDK 里的原型
工厂方法/抽象工厂把"new 什么"交给工厂决定BeanFactory/ApplicationContext、FactoryBean
单例全局唯一实例Bean 默认作用域 singleton
代理增强目标而不改其代码AOP（JDK 接口代理/CGLIB 子类代理）
模板方法骨架固定，步骤留给子类填JdbcTemplate、HttpServlet.service、RestTemplate
观察者一对多状态联动ApplicationEvent/ApplicationListener、GUI 监听器
策略同一接口多实现可切换，消 if-elseResource 加载策略、线程池拒绝策略（本身就是）
责任链请求沿处理器链依次传递Servlet Filter、Spring Interceptor、Netty Pipeline
适配器转换接口使其可用SpringMVC 的 HandlerAdapter

六大设计原则（一句版）：开闭（对扩展开放对修改关闭）、单一职责、里氏替换（子类可无缝替换父类）、依赖倒置（依赖抽象不依赖具体）、接口隔离（接口小而专）、迪米特（少交朋友、只和直接朋友说话）。开闭原则是灵魂，其余都是它的实现路径。

策略模式消 if-else 模板（面试常要求白板）：

Java 
interface Pay { void pay(int amount); }
@Component("wx")  class WxPay implements Pay { public void pay(int a) { /*...*/ } }
@Component("ali") class AliPay implements Pay { public void pay(int a) { /*...*/ } }

@Service
public class PayService {
    private final Map<String, Pay> pays;             // Spring 注入 key=Bean 名
    public PayService(Map<String, Pay> pays) { this.pays = pays; }
    public void pay(String channel, int amount) {    // "wx"/"ali" 直达实现
        Pay p = pays.get(channel);
        if (p == null) throw new IllegalArgumentException("渠道不支持");
        p.pay(amount);
    }
}

Python 对照：单例常用模块级实例或 __new__ 重写，策略用"函数字典"直接映射——面试 Python 岗说"我不用类也能消 if-else"即可。

三、示例题目（点击选项即时判分 / 口述题先自答）

单选1. 双检锁单例中，实例引用必须用 volatile 修饰的原因是（  ）

A. 保证可见性的同时保证原子性
B. 禁止 new 的"分配内存→初始化→赋引用"三步重排序，防止其他线程拿到未初始化的半成品对象
C. 让单例对象不进入老年代
D. 为了让第二次判空更快
答案 B。new 三步可能重排成"分配→赋引用→初始化"，另一线程恰好在第一次判空时读到非空引用，直接使用未初始化字段。volatile 禁重排（同时保证可见性，但"防半成品"是本题主因）。A 错——volatile 不保证原子性。来源：牛客经典题。

多选2. 关于各种单例写法，正确的有（  ）

A. 饿汉式依赖类加载机制，天然线程安全
B. 静态内部类式在外部类加载时就会创建单例实例
C. 枚举单例可以防止反射攻击与反序列化破坏
D. 双检锁的两次判空分别为了减少抢锁与锁内兜底
答案 ACD。B 错——静态内部类的价值就是懒加载：外部类加载不触发内部类初始化，首次调用 get() 才创建。枚举由 JVM 保证实例唯一，反射 new 与反序列化都被禁止。来源：面试高频改编。

单选3. Spring 的 AOP 通知、Servlet 的 Filter 链、Netty 的 Pipeline，共同体现的设计模式是（  ）

A. 责任链模式
B. 观察者模式
C. 工厂模式
D. 模板方法模式
答案 A。三者都是"请求沿处理器链依次传递、每个节点决定放行或拦截"。观察者是多对多状态联动、模板方法是骨架+填空——对照表是答题钥匙。来源：面试高频改编。

单选4. 一个支付接口有微信/支付宝/银联三种实现，业务代码里大段 if-else 判断渠道，最合适消除它的模式是（  ）

A. 单例模式
B. 观察者模式
C. 装饰器模式
D. 策略模式（Spring 中注入 Map<渠道, 实现> 直达实现）
答案 D。策略+Map 注入让"新增渠道"只加一个实现类（符合开闭原则），不碰老代码。来源：面试高频改编。

面试口述5. 白板手写双检锁单例，并解释每一行的作用。

参考回答按第四节代码 ③ 默写：私有构造器（防外部 new）、volatile 静态引用（防 new 三步重排序）、两次判空（外层判空让大多数请求免抢锁、内层判空防止两个线程同时通过外层判空重复创建）、synchronized 锁类对象。写完主动补：工程上更推荐静态内部类或枚举（懒加载/防反射），DCL 的价值主要是考并发理解。这一句"自降一档"反而加分。

单选6. "对扩展开放、对修改关闭"，新增一种功能时优先加新代码而不是改老代码——这是哪个原则？（  ）

A. 单一职责原则
B. 开闭原则
C. 迪米特法则
D. 接口隔离原则
答案 B。开闭是六大原则的灵魂，策略模式、工厂模式、插件化都是它的落地。单一职责管"一个类只干一件事"、迪米特管"少和陌生人说话"。来源：牛客经典题。

四、易错点小结

① 双检锁没有 volatile 就是错的，面试手写漏写直接扣分；② 静态内部类单例"懒加载"来自"内部类不随外部类加载"，别答成"类加载就创建"；③ 单例构造器必须 private——忘写 private 全盘作废；④ Spring 的 singleton 是"容器内唯一"不是"JVM 全局唯一"（同 JVM 多容器/同容器 prototype 都会有多实例）；⑤ 讲设计模式必带"Spring 里谁在用"，只背 UML 图是减分项。
