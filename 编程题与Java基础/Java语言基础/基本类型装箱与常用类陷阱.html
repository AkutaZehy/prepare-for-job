基本类型、装箱与常用类陷阱

适用岗位：测开(Java)、通用软开 ｜ 形态：概念 + 输出判断（== 陷阱重灾区） ｜ 更新：2026-09-30
要点速记：自动装箱走 valueOf，Integer 缓存 -128~127——范围内 == 同对象、范围外各自新建，包装类型比较一律 equals；包装类型与基本类型混算会拆箱，null 拆箱即 NPE（三元两边类型不一致是隐藏触发点）；StringBuilder 不安全快、StringBuffer synchronized 安全慢；BigDecimal 只用字符串构造或 valueOf，divide 除不尽必须指定精度与 RoundingMode。

一、知识点梳理

boolean 的存储未在规范中定义：HotSpot 里数组元素按 1 字节、其余场合按 int 处理，面试报"规范未规定、实现通常当 1 字节/int"即可。

自动装箱与缓存：装箱 = Integer.valueOf(int)，拆箱 = intValue()（JDK5 起支持）。Integer 对 -128~127 返回 IntegerCache 预建对象（上界可用 -XX:AutoBoxCacheMax 调整，下界固定）；Long 同为 -128~127，Character 缓存 0~127，Boolean 缓存 true/false；new Integer() 每次新对象，JDK9 起该构造器已 @Deprecated。

== 与 equals：== 对基本类型比值、对引用比地址；Integer 与 int 混合比较时 Integer 自动拆箱成 int 再比值（不受缓存影响）；两个 Integer 用 == 在缓存范围内 true、范围外 false——包装类型比较一律 equals。

拆箱 NPE：包装类型为 null 时，任何触发拆箱的操作都抛 NPE——算术运算、赋给基本类型、三元运算符两边类型不一致导致的类型提升、HashMap.get 结果直接赋给 int、两个 Long 对象相减等。

String 三兄弟：String 不可变（详见同目录 String 不可变与常量池 一页）；StringBuilder 可变、非线程安全、单线程首选；StringBuffer 的方法带 synchronized、线程安全但慢。循环拼接必须用 StringBuilder。

BigDecimal 三坑：① double 是二进制浮点，0.1 本来就存不准；new BigDecimal(0.1) 把这个不精确的 double 原样放大成超长小数，必须用字符串构造 new BigDecimal("0.1") 或 BigDecimal.valueOf(0.1)（内部走 Double.toString）；② divide 除不尽且未指定精度时抛 ArithmeticException，必须写 divide(b, scale, RoundingMode)；③ 比较大小用 compareTo——equals 连 scale 一起比（2.0 与 2.00 不 equals）。

Java 
public class IntegerCacheDemo {
    public static void main(String[] args) {
        Integer a = 127, b = 127;
        Integer c = 128, d = 128;
        int e = 128;

        System.out.println(a == b);      // true ：valueOf 命中缓存，同一个对象
        System.out.println(c == d);      // false：128 超出缓存，各自新对象
        System.out.println(c.equals(d)); // true ：内容比较，不受缓存影响
        System.out.println(c == e);      // true ：c 自动拆箱成 int 再比值
    }
}
Java 
import java.math.BigDecimal;
import java.math.RoundingMode;

public class BigDecimalDemo {
    public static void main(String[] args) {
        BigDecimal x = new BigDecimal(0.1);    // 坑：double 的 0.1 本身不精确
        System.out.println(x);
        // 0.1000000000000000055511151231257827021181583404541015625

        BigDecimal y = new BigDecimal("0.1");  // 对：字符串构造
        System.out.println(y);                 // 0.1
        System.out.println(BigDecimal.valueOf(0.1)); // 0.1（内部 Double.toString）

        BigDecimal one = new BigDecimal("1");
        BigDecimal three = new BigDecimal("3");
        // System.out.println(one.divide(three));
        // 运行抛 ArithmeticException：Non-terminating decimal expansion（除不尽且未指定精度）
        System.out.println(one.divide(three, 2, RoundingMode.HALF_UP)); // 0.33

        System.out.println(new BigDecimal("2.0").equals(new BigDecimal("2.00")));    // false（scale 不同）
        System.out.println(new BigDecimal("2.0").compareTo(new BigDecimal("2.00"))); // 0（数值相等）
    }
}

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println(a == b);
System.out.println(c == d);
A. true / false
B. true / true
C. false / true
D. false / false
答案 A。装箱走 Integer.valueOf，-128~127 命中缓存返回同一对象，127 相等；128 超出缓存各自新建对象，== 比地址为 false。包装类型一律用 equals 比内容。来源：牛客经典题。

单选2. 以下代码的运行结果是（  ）

Integer cnt = null;
int flag = 1;
int r = flag > 0 ? cnt : 0;
System.out.println(r);
A. 输出 null
B. 输出 0
C. 抛 NullPointerException
D. 编译错误
答案 C。三元一边 Integer 一边 int，表达式类型被提升为 int，被选中的 cnt 分支必须自动拆箱（调 intValue()），null 拆箱即 NPE。若两边都是包装类型，表达式类型是 Integer，能赋出 null 而不报错——真正稳妥的做法是先判空。来源：面试高频改编。

单选3. 关于 new BigDecimal(0.1)，说法正确的是（  ）

A. 得到精确的 0.1，与字符串构造等价
B. 得到 0.1000000000000000055511151231257827…；应改用 new BigDecimal("0.1") 或 BigDecimal.valueOf(0.1)，且 divide 除不尽时必须指定 scale 与 RoundingMode
C. 得到 0.1；运算有误差时换成 double 就能解决
D. 编译错误，BigDecimal 的构造器不接受 double
答案 B。double 是二进制浮点，0.1 存不准，构造器把它原样放大成超长小数；字符串构造与 valueOf 才精确。金额计算口诀：字符串构造、divide 给 RoundingMode、比较用 compareTo（equals 连 scale 一起比）。来源：牛客经典题。

多选4. 设计一个不可变类（如 String），需要做到（  ）

A. 类声明为 final，防止子类破坏不可变性
B. 所有字段 private final，只在构造时赋值
C. 为每个字段提供 setter，方便按需修改副本
D. 持有可变对象（数组、集合）时不暴露引用：getter 返回拷贝或做防御性复制
答案 ABD。C 反了——不可变类不允许任何修改入口，setter 一加就破功。不可变的好处回看 String 页：常量池共享、hashCode 可缓存、安全、天然线程安全。来源：JavaGuide 收录题型。

面试口述5. 口述 int 与 Integer 的区别，以及 Integer 缓存的边界和注意事项。

参考回答int 是基本类型、默认 0、存栈上值本身；Integer 是包装类、是对象、默认 null，可入集合可判空，比较用 equals。自动装箱走 valueOf：Integer 对 -128~127 返回 IntegerCache 预建对象（JDK5 起提供，上界可用 -XX:AutoBoxCacheMax 调整，下界固定），超出范围每次新建对象——所以 == 在缓存内碰巧为 true、缓存外为 false，包装类型比较必须 equals。包装类型与基本类型混算会自动拆箱，null 拆箱抛 NPE。加分点：Long 缓存同范围、Character 缓存 0~127、Boolean 缓存 true/false；new Integer JDK9 起 @Deprecated。来源：面试高频改编。

四、易错点小结

① 包装类型 == 一律换成 equals，除非题目刻意考缓存；② 缓存范围 -128~127（JDK5 起），上界可调下界固定，Long/Short/Byte 同范围；③ 三元或算术里混入 null 包装类型就是 NPE 定时炸弹，先判空；④ BigDecimal 只走字符串构造或 valueOf，divide 必给 scale 与 RoundingMode，比较用 compareTo；⑤ 局部变量没有默认值，成员变量才有——"int 默认 0"只对字段成立。
