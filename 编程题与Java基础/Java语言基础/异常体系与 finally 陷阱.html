异常体系与 finally 陷阱

适用岗位：测开(Java)、通用软开 ｜ 形态：概念 + 输出判断（finally 是笔试重灾区） ｜ 更新：2026-09-30
要点速记：Throwable 分 Error（OOM、StackOverflow，程序不捕获）与 Exception；Exception 分 checked（编译器强制处理）与 unchecked（RuntimeException 及子类）；catch 自上而下匹配，子类在前父类在后，反了编译错；finally 在 return 表达式求值后、真正返回前执行——改局部变量不影响返回值，finally 里 return 会覆盖；JDK7 起 try-with-resources 自动关闭资源、close 的异常被抑制。

一、知识点梳理

异常家族树（口述按这个层次报）

  • Throwable → Error：OutOfMemoryError、StackOverflowError、NoClassDefFoundError——JVM 级严重问题，程序不应捕获处理。
  • Throwable → Exception，按编译器态度分两派：
    • checked 受检异常：编译器强制 try-catch 或 throws，否则编译不过——IOException、SQLException、ClassNotFoundException、InterruptedException，多为外部资源意外。
    • unchecked 非受检异常：RuntimeException 及其子类，编译器不强制——NullPointerException、ArrayIndexOutOfBoundsException、ClassCastException、ArithmeticException、IllegalArgumentException，多为程序 bug。
一句话区分：checked 是"外部世界的不确定"（文件、网络、数据库），unchecked 是"自己代码的 bug"（空指针、越界）。

try-catch 匹配规则：自上而下逐个匹配，命中即止，后面的不再看；子类异常必须写在父类前面，父类在前会把子类分支变成不可达代码，编译器报 "has already been caught"；catch 与 finally 至少有其一。

finally 执行时机（笔试核心）：只要进了 try，finally 一定执行——例外：System.exit()、JVM 崩溃/断电、try 里死循环出不来。时机 = try/catch 里 return 的表达式先求值并暂存，然后执行 finally，最后才真正返回。三条推论：

  • finally 改局部变量（含基本类型与引用变量本身）→ 返回值不变；
  • finally 改引用指向的对象内容 → 生效（同一对象）；
  • finally 里写 return → 覆盖 try/catch 已暂存的返回值，还可能吞掉异常（严禁）；finally 里抛异常 → 顶掉原异常。
Java 
public class FinallyDemo {
    static int f1() {
        int x = 1;
        try {
            return x;              // ① 返回值 1 已求值暂存
        } finally {
            x = 99;                // ② 改的是局部变量，动不了暂存的返回值
        }
    }

    static int f2() {
        try {
            return 1;
        } finally {
            return 99;             // finally 里的 return 直接覆盖 try 的返回值
        }
    }

    static StringBuilder f3() {
        StringBuilder sb = new StringBuilder("a");
        try {
            return sb;             // 引用已暂存，指向同一对象
        } finally {
            sb.append("b");        // 改对象内容 → 生效
        }
    }

    public static void main(String[] args) {
        System.out.println(f1());  // 1
        System.out.println(f2());  // 99
        System.out.println(f3());  // ab
    }
}

try-with-resources（JDK7 引入）：try 后跟括号声明资源，资源类必须实现 AutoCloseable，语句块结束（含异常退出）时自动调用 close，多个资源按声明逆序关闭。close 抛出的异常会被抑制（suppressed）、挂在主异常上（getSuppressed() 可取），主异常不被顶掉——比手写嵌套 try-finally 干净且安全。JDK9 起括号里可直接用 effectively final 的资源变量。

Python 
def f():
    try:
        return 1
    finally:
        print("finally 先执行，再真正返回")

# with 语句 ≈ Java try-with-resources
with open("a.txt", encoding="utf-8") as fp:
    data = fp.read()   # 块正常结束或异常退出都会自动 close

二、考点说明

笔试选择输出判断面试口述

  • 输出判断：finally + return 组合是绝对主力——改值、改对象、finally 里 return 三种套路要一眼分清。
  • 概念选择：checked/unchecked 归类、catch 顺序编译错、Error 与 Exception 的边界。
  • 面试口述：finally 执行时机与陷阱、try-with-resources 相比手写 try-finally 的好处（带上 suppressed 异常是加分项）。

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

static int test() {
    int x = 10;
    try {
        return x;
    } finally {
        x = 20;
    }
}
// main 中：System.out.println(test());
A. 10
B. 20
C. 0
D. 编译报错：finally 中不能修改变量
答案 A。执行到 return x 时先把 10 求值暂存，再执行 finally，x=20 只改了局部变量，动不了暂存的返回值。若 finally 里写 return 20 才会输出 20（覆盖式写法，严禁）。来源：牛客经典题。

单选2. 以下代码的编译运行结果是（  ）

try {
    int[] a = new int[3];
    a[3] = 1;
} catch (Exception e) {
    System.out.println("E");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("AIOOBE");
}
A. 输出 E
B. 输出 AIOOBE
C. 编译错误：子类异常分支永远捕获不到，已被父类捕获
D. 先输出 E 再输出 AIOOBE
答案 C。catch 自上而下匹配，Exception 在前会把 ArrayIndexOutOfBoundsException 的分支变成不可达代码，编译器报 "already been caught"。正确顺序是子类在前、父类在后。来源：牛客经典题。

多选3. 下列异常中属于 unchecked（RuntimeException 体系）的有（  ）

A. NullPointerException
B. IOException
C. ClassCastException
D. ArithmeticException
答案 ACD。B 的 IOException 是 checked 异常，编译器强制处理。unchecked 全在 RuntimeException 体系下，常见还有 ArrayIndexOutOfBoundsException、IllegalArgumentException、NumberFormatException。来源：面试高频改编。

面试口述4. 什么是 try-with-resources？相比手写 try-finally 好在哪？

参考回答JDK7 引入的语法糖：try 后跟括号声明资源，资源类必须实现 AutoCloseable，语句块结束（含异常退出）时自动调用 close，多个资源按声明逆序关闭。三个好处：① 代码短——不用手写"嵌套 finally、先判空、再置 null"三件套；② 安全——手写 finally 里 close 再抛异常会把业务异常"顶掉"，try-with-resources 把 close 的异常作为 suppressed 异常挂在主异常上（getSuppressed() 可取），主异常不被吞；③ JDK9 起括号里可以直接复用 effectively final 的资源变量。来源：JavaGuide 收录题型。

面试口述5. finally 一定执行吗？什么时候执行？finally 里写 return 会发生什么？

参考回答① 几乎一定执行，例外只有 System.exit()、JVM 崩溃/断电、try 里死循环出不来这类极端情况。② 时机：try 或 catch 里执行到 return 时，先把返回表达式求值并暂存，然后执行 finally，最后才真正返回——所以 finally 改局部变量不影响返回值（基本类型和引用变量都一样），但改引用指向的对象内容会生效。③ finally 里写 return 会直接覆盖 try/catch 已暂存的返回值，此时若还有未处理异常还会把异常吞掉，IDE 会警告——严禁这样写。加分点：报出"return 求值暂存 → finally → 真正返回"三段式，并举改值不变、改对象内容生效两个例子。来源：面试高频改编。

四、易错点小结

① finally 改不动"值"、改得动"对象内容"——记住返回值在 finally 之前已暂存；② finally 里 return 或抛异常是一票否决写法（覆盖返回值/顶掉原异常）；③ catch 顺序从小到大，子类在前；④ Error 不是给业务 catch 的，catch (Throwable) 连 OOM 都吞是反面教材；⑤ 口述 try-with-resources 时带上 AutoCloseable、逆序关闭、suppressed 三个词。
