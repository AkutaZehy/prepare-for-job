String 不可变与常量池

适用岗位：测开(Java)、通用软开 ｜ 形态：概念 + 输出判断题（笔试选择重灾区） ｜ 更新：2026-09-30
要点速记：String 不可变（8 里是 final byte[]）；常量池里的字面量在编译期折叠，"a"+"b" 直接成 "ab"；引用变量拼接发生在运行期产生新对象；intern() 把串放入并返回池中引用（JDK7 起池在堆里，可存堆中引用）。所有 == 输出题先问一句：两边是不是同一个池里的引用。

一、知识点梳理

  • 不可变（immutable）：String 类 final（不可继承），内部数组 private final 且不提供修改方法，任何"修改"（concat/replace/substring…）都返回新对象。JDK8 内部是 final char[]，JDK9 起改为 byte[]+编码标记省内存。
  • 为什么设计成不可变（面试四连）：① 字符串常量池共享同一实例成为可能；② hashCode 可以缓存（String 的 hash 惰性计算并缓存，适合做 HashMap 的 key）；③ 安全性（网络地址/文件路径/类名等若可变会被篡改）；④ 天然线程安全。
  • 三级池概念：class 文件常量池 → 运行时常量池（方法区/元空间）→ 字符串常量池（JDK7 起移到堆中）。"字面量" 与 intern() 都指向池。
  • intern()：JDK6 池在永久代，拷贝字面量入池；JDK7 起池在堆，池中已存在等值串就返回它，不存在则把堆中该引用存入池（不再拷贝）——所以 new String("ab").intern() 与 "ab" 恒等值同引用。
  • 拼接三规则：① 两个都是编译期常量（字面量、final 常量）→ 编译期折叠进池；② 任一含运行期变量 → StringBuilder.append，新对象在堆，不在池；③ new String("ab") 造 1~2 个对象（池里没有"ab"时先在池造一个，堆里再 new 一个）。
  • 三兄弟对比：String 不可变；StringBuilder 可变不安全（单线程首选）；StringBuffer 可变、方法 synchronized（安全但慢）。循环拼接务必用 StringBuilder，否则每轮产生新对象 O(n²)。
  • Python 对照：str 同样不可变；小字符串/标识符有驻留（intern）机制，id() 可观察；拼接产生新对象；没有显式常量池 API，面试 Python 岗讲"不可变+驻留"即可。
Java 
String a = "ab";                 // 指向池中 "ab"
String b = "a" + "b";            // 编译期折叠 → 池中 "ab"，同一引用
String x = "a";
String c = x + "b";              // 运行期 StringBuilder → 堆上新对象
final String fx = "a";
String d = fx + "b";             // fx 是常量 → 折叠 → 池中 "ab"
String e = new String("ab");     // 堆上新对象

System.out.println(a == b);      // true  （池内同引用）
System.out.println(a == c);      // false （堆 vs 池）
System.out.println(a == d);      // true  （final 折叠）
System.out.println(a == e);      // false
System.out.println(a == e.intern()); // true （intern 返回池引用）
Python 
a = "ab"
b = "a" + "b"          # CPython 常量折叠，同一对象
c = "".join(["a", "b"])  # 运行期构造，不保证驻留

print(a == b)          # True（值相等）
print(a is b)          # True（字面量折叠，同一对象）
print(a is c)          # 通常 False（join 产生新对象）
# 结论：Python 同样"值比较用 ==，身份比较 is"，笔试陷阱与 Java 同构

二、考点说明

笔试选择/输出判断面试口述

  • 输出判断题是绝对主力：给 3~6 行拼接代码问 == 结果，考的全是"编译期折叠 vs 运行期拼接 vs new/intern"。
  • 概念选择：不可变的原因、三兄弟线程安全与性能、常量池位置（JDK7 前后变化）。
  • 面试追问：为什么把字符串设计成不可变、HashMap 的 key 为什么常用 String、循环拼接有什么问题。

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

String a = "hello";
String b = "hel" + "lo";
System.out.println(a == b);
A. true，"hel"+"lo" 在编译期折叠为池中 "hello"
B. false，拼接会产生新对象
C. true，因为 String 是不可变的
D. false，两个 "hello" 存在不同位置
答案 A。两个操作数都是编译期常量，"hel"+"lo" 编译期折叠成 "hello" 入池，a、b 同引用。注意"不可变"只是让池共享可行，这里直接原因是常量折叠。来源：牛客 Java 专项经典题。

输出判断2. 以下代码输出（  ）

String s1 = "ab";
String s2 = new String("ab");
String s3 = s2.intern();
System.out.println(s1 == s2);
System.out.println(s1 == s3);
A. true / true
B. false / false
C. false / true
D. true / false
答案 C。new String("ab") 在堆上新造对象，与池中 s1 不同引用 → false；intern() 返回池中 "ab" 的引用 → 与 s1 同引用 → true。JDK7+ 行为（池中已有等值串时直接返回）。来源：牛客/面经高频经典题。

输出判断3. 以下代码输出（  ）

String base = "a";
final String f = "a";
String r1 = base + "b";
String r2 = f + "b";
System.out.println(r1 == "ab");
System.out.println(r2 == "ab");
A. true / true
B. false / true
C. true / false
D. false / false
答案 B。base 是运行期变量 → StringBuilder 拼接 → 堆上新对象 → false；f 被 final 修饰是编译期常量 → 折叠进池 → true。"变量是否有 final"是这类题唯一要盯的点。来源：408 外 Java 笔试常考（改编经典题）。

多选4. String 被设计为不可变的好处包括（  ）

A. 可以安全地共享字符串常量池中的同一实例
B. hashCode 可以缓存，适合做 HashMap 的 key
C. 频繁拼接字符串效率更高
D. 天然线程安全，且网络地址、文件路径等关键值不会被篡改
答案 ABD。C 反了——不可变导致每次"修改"都产生新对象，频繁拼接应用 StringBuilder。不可变四好处：池共享、hash 缓存、安全、线程安全。来源：面试高频（JavaGuide 收录题型）。

单选5. 关于 String、StringBuilder、StringBuffer，说法正确的是（  ）

A. StringBuffer 性能最高，推荐单线程使用
B. StringBuilder 是线程安全的
C. StringBuffer 的方法带 synchronized，线程安全但开销大；单线程拼接用 StringBuilder
D. 三者都可以被继承扩展
答案 C。单线程 StringBuilder 最快，多线程才 StringBuffer；String 是 final 类不可继承，StringBuilder/StringBuffer 也是 final 的，D 错。来源：牛客 Java 专项高频题。

四、易错点小结

① == 判引用、equals 判内容，笔试先分清问的是哪个；② 判 == 三步走：有没有 new？有没有运行期变量拼接？有没有 intern？；③ "new String("ab") 创建几个对象"标准答案：池里没有 "ab" 时 2 个（池 1+堆 1），已有则 1 个；④ JDK7 起字符串常量池在堆，不在永久代/元空间——老八股答案要更新。
