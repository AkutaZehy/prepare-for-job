泛型、反射与枚举

适用岗位：测开(Java)、通用软开 ｜ 形态：概念 + 输出判断 + 面试口述 ｜ 更新：2026-09-30
要点速记：泛型只在编译期——擦除后运行时无泛型，List<String> 与 List<Integer> 是同一个 Class，不能 new T[]、instanceof 只能判原始类型；通配符记 PECS：生产者（只读）用 ? extends、消费者（只写）用 ? super；反射三种拿 Class：getClass()、X.class、Class.forName；枚举单例天然防反射防序列化破坏——Constructor.newInstance 对枚举直接抛异常，反序列化由 JVM 特殊处理。

一、知识点梳理

  • 泛型是编译期检查：编译器用泛型做类型检查并自动插入强转，编译后擦除为原始类型（List<String> → List），运行时对象不携带泛型信息。后果三连：不能 new T[]、不能 new T()、instanceof List<String> 直接编译错（只能 instanceof List）。
  • 擦除的两个补充：同一泛型类的所有实例共享同一个 Class 对象；编译器会为重写泛型方法生成"桥接方法（Bridge method）"来维持擦除后的多态——一句话了解即可。用原始类型引用可绕过编译检查混入其他类型（堆污染），错误在取值时才以 ClassCastException 暴露。
  • 通配符与 PECS：? extends T 上界——生产者（只往外读），读出按 T 处理，不能 add 任何元素（除 null）；? super T 下界——消费者（只往里写），可写 T 及其子类，读出只能当 Object。经典应用：Collections.copy(List<? super T> dest, List<? extends T> src)。
  • 反射三种获取 Class：对象.getClass()、类字面量 Xxx.class、Class.forName("全限定名")。getDeclaredMethod / getDeclaredField 可拿到私有成员，setAccessible(true) 绕过访问检查。
  • 反射的应用与代价：Spring 实例化 Bean、MyBatis/Jackson 字段映射、JDBC 加载驱动、动态代理都靠它；代价是比直接调用慢（JIT 能优化一部分）、绕过编译期检查有风险；JDK9+ 模块化后对非导出包 setAccessible 受限（可能抛 InaccessibleObjectException）。
  • 枚举本质：enum 是继承 java.lang.Enum 的 final 类（不能再继承别的类，可实现接口），实例隐式 public static final、构造器隐式 private；常用方法 values()（全部实例，每次返回新数组）、valueOf("名字")（不存在则抛 IllegalArgumentException）、name()、ordinal()（序号从 0 起）。
  • 枚举单例：JVM 保证枚举实例唯一——反射创建枚举对象会被 Constructor.newInstance 拒绝（直接抛 IllegalArgumentException，"Cannot reflectively create enum objects"）；序列化/反序列化由 JVM 特殊处理、返回同一实例，不需要像普通单例那样手写 readResolve。《Effective Java》推荐的写法。
Java 
import java.lang.reflect.Method;

class Secret {
    private String greet(String name) {
        return "hi, " + name;
    }
}

public class ReflectDemo {
    public static void main(String[] args) throws Exception {
        Secret s = new Secret();
        Method m = Secret.class.getDeclaredMethod("greet", String.class);
        m.setAccessible(true);           // 绕过 private 访问检查
        Object r = m.invoke(s, "tom");
        System.out.println(r);           // hi, tom
    }
}
Java 
import java.util.HashMap;
import java.util.Map;

public enum ConfigHolder {
    INSTANCE;                            // 枚举实例由 JVM 保证唯一

    private final Map<String, String> cfg = new HashMap<>();

    public String get(String key) {
        return cfg.get(key);
    }
}
// 使用：ConfigHolder.INSTANCE.get("key")
// 反射破坏：Constructor.newInstance() 对枚举直接抛 IllegalArgumentException
// 序列化破坏：JVM 特殊处理，反序列化返回同一实例
Java 
List<Integer> list = new ArrayList<>();
list.add(1);
List raw = list;                 // 原始类型引用：编译期泛型检查被绕过
raw.add("混进来的字符串");        // 只报 unchecked 警告，运行期不检查
System.out.println(list.get(1)); // 打印"混进来的字符串"（println 收 Object）
// 若写 int v = list.get(1); 取值拆箱时才抛 ClassCastException
Python 
import enum

class Color(enum.Enum):
    RED = 1

print(Color.RED.value, Color.RED.name)  # 1 RED
# 反射等价物：getattr(obj, "greet")("tom") 按字符串名取函数再调用

二、考点说明

笔试选择输出判断面试口述

  • 输出判断：擦除后 getClass() 相同、instanceof 原始类型恒真——给几行泛型代码问 true/false。
  • 概念选择：List<String> 与 List<Integer> 的运行时关系、反射应用场景、枚举单例防破坏原理。
  • 面试口述：PECS 怎么选、为什么枚举单例最安全、泛型擦除带来哪些限制。

三、示例题目（点击选项即时判分）

输出判断1. 以下代码输出（  ）

List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a instanceof List);
System.out.println(a.getClass() == b.getClass());
A. true / true
B. true / false
C. false / true
D. false / false
答案 A。泛型擦除后 a、b 运行时都是 ArrayList，getClass() 相同；instanceof 只能针对原始类型 List 判断（写 instanceof List<String> 直接编译错），恒为 true。来源：牛客经典题。

单选2. 运行时的 List<String> 与 List<Integer>，说法正确的是（  ）

A. 二者是同一个 Class 对象；运行时对象不携带泛型信息，声明处的泛型签名只能通过反射（如 getGenericType）读到
B. 二者是不同的 Class，泛型信息保存在每个对象里
C. 泛型信息在运行时完整保留，可随时取出
D. 向 List<String> 塞入 Integer 会立即抛 ClassCastException
答案 A。擦除后所有参数化的 ArrayList 都是同一个 Class；塞入时不检查（编译期检查被绕过/擦除），错误在取值赋给 String 时才以 CCE 暴露。想拿泛型信息只能读字段/方法签名上的元数据（getGenericType）。来源：面试高频改编。

多选3. 反射的典型应用场景有（  ）

A. Spring 按全类名字符串实例化 Bean 并完成依赖注入
B. MyBatis / Jackson 把数据库行、JSON 按名字映射到实体对象字段
C. JDBC 按配置的类名 Class.forName 加载驱动
D. 编译器借助反射在运行期完成泛型类型检查
答案 ABC。D 反了——泛型检查发生在编译期，擦除后运行期没有泛型信息可查。反射的本质是"运行时看类的内容再操作"，一切按字符串配置驱动的框架都离不开它。来源：JavaGuide 收录题型。

单选4. 枚举单例天然防反射与防序列化破坏的原因是（  ）

A. enum 是 final 类，反射 API 访问不到它
B. Constructor.newInstance 创建枚举对象时直接抛 IllegalArgumentException；序列化/反序列化由 JVM 特殊处理，返回同一实例
C. 枚举实例存在方法区，靠类加载锁保证只创建一次
D. 枚举自动实现了 readResolve 方法
答案 B。final 只防继承不防反射；真正拦下反射的是 JDK 对枚举的特判（Cannot reflectively create enum objects）；反序列化也不走普通对象流程，不需要手写 readResolve。这正是 Effective Java 推荐枚举单例的原因。来源：面试高频改编。

面试口述5. 什么是 PECS 原则？? extends 和 ? super 各怎么选，为什么？

参考回答PECS = Producer Extends, Consumer Super。① 参数是"生产者"——你主要从中读数据——用 ? extends T：如 int sum(List<? extends Number> list)，读出来按 Number 用；因为编译器只知道元素是"某种 Number 的子类型"，不知道具体是哪种，往里 add 任何对象都可能破坏类型安全，所以除 null 外禁止写入。② 参数是"消费者"——你主要往里写数据——用 ? super T：如 Collections.copy 的目标参数 List<? super T>，写入 T 及其子类一定满足下界声明；但读出来只能保证是 Object。③ 既读又写就不用通配符，直接精确类型。加分点：举 Collections.copy 一读一写的双通配签名。来源：牛客经典题。

四、易错点小结

① 擦除题三步走：泛型编译期检查 → 运行时只剩原始类型 → 同一泛型类一个 Class；② List<? extends Number> 只读不写（连 Object 都塞不进去），? super 只写读出来是 Object；③ 反射拿私有成员用 getDeclaredXxx + setAccessible(true)，getXxx 只拿公有；④ 枚举 values() 每次返回新数组，valueOf 查不到抛 IllegalArgumentException；⑤ 普通单例靠私有构造 + readResolve 也可能被攻破，枚举单例一劳永逸。
