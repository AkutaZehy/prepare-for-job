TCP 可靠传输与拥塞控制

适用岗位：全部（窗口变化计算是笔试高频，四算法是面试必问） ｜ 形态：概念 + 计算 ｜ 更新：2026-09-30
要点速记：可靠 = 序号 + 确认（累积确认）+ 超时重传；超时定时器 RTO 依据加权平均 RTTs = (1−α)×RTTs + α×新样本；发送窗口 = min(拥塞窗口 cwnd, 接收窗口 rwnd)；慢启动每轮翻倍、到 ssthresh 转拥塞避免每轮 +1；超时：ssthresh = cwnd/2，cwnd 重置为 1；快重传 = 收到 3 个重复 ACK 立即重传，快恢复 = ssthresh 减半后 cwnd 直接从新 ssthresh 开始线性。

一、知识点梳理

可靠传输三件套：①序号——每个字节编号，SYN/FIN 各耗一个序号；②确认——累积确认，ACK n 表示"n 之前全部收到，期望收 n"；③重传——超时重传（RTO 由 RTT 估计）与快重传。校验和伪首部另计。

加权平均 RTT（RFC 常取 α=1/8）：RTTs = (1−α)×旧RTTs + α×新RTT样本；RTO 略大于 RTTs，超时未确认就重传。

停等 / GBN / SR 对比（408 数据链路层同样考这套窗口公式，n 位编号）：

协议发送窗口接收窗口要点
停等11信道利用率最低；可靠但慢
GBN 回退 N≤ 2ⁿ−11接收方只按序收，失序一律丢弃；出错从出错处整批重传
SR 选择重传≤ 2ⁿ⁻¹≤ 2ⁿ⁻¹接收方缓存失序帧，只重传真正丢的；窗口超半数会序号歧义

TCP 流量控制：接收方通过 rwnd 字段通告剩余缓冲；发送窗口 = min(cwnd, rwnd)。rwnd=0 时发送方停发但启动零窗口探测计时器，防止"再打-notch 唤醒报文丢失"造成双向死等。

拥塞控制四算法（发送方维护 cwnd 与慢启动门限 ssthresh）：

阶段动作增长形态
慢启动cwnd 从 1 起，每收到一轮确认 cwnd 翻倍（指数）；到 ssthresh 就切换1→2→4→8…
拥塞避免cwnd ≥ ssthresh 后每轮只加 1 MSS8→9→10…线性
超时（网络严重拥塞）ssthresh = cwnd/2，cwnd = 1，重新慢启动打回起点
快重传+快恢复（轻度丢包）收到 3 个重复 ACK 立即重传丢失报文；ssthresh = cwnd/2，cwnd = 新 ssthresh，直接进入拥塞避免减半续跑，不打回 1

经典演化表（初始 cwnd=1，ssthresh=8，单位 MSS）：

轮次12345678
cwnd12489101112
说明第 4 轮到达 ssthresh=8 转入拥塞避免（有的教材当轮即按线性加 1，轮次口径以题为准）；若第 6 轮超时：ssthresh=5，cwnd=1 重来

面试引申：拥塞控制是全局保护网络，流量控制是点对点匹配接收方；TCP 拥塞控制在传输层靠丢包/延迟推断拥塞（没有路由器显式通知，ECN 是补充）。

二、考点说明

计算题笔试选择面试必问

  • cwnd 演化计算：给初始值和 ssthresh，问第几轮达到某值 / 超时或三重复 ACK 后的 cwnd 与 ssthresh——注意区分"超时"与"快恢复"两条不同支路。
  • RTTs 加权平均的计算（一个公式代入）。
  • GBN/SR 窗口大小公式与序号位数（m 位编号）计算。
  • 发送窗口 = min(cwnd, rwnd) 的取值判断。
  • 面试口述：四算法串讲、为什么快重传要等 3 个重复 ACK（区分乱序与丢包）、拥塞控制与流量控制区别。

三、示例题目（点击选项即时判分 / 计算题先自算）

计算1. TCP 连接初始 cwnd = 1 MSS，ssthresh = 8。第几轮传输结束时 cwnd 首次达到 12？若第 5 轮发生超时，ssthresh 与 cwnd 各变为多少？

先自己算，再展开对答案慢启动 1→2→4→8（第 4 轮到达 ssthresh），之后拥塞避免每轮 +1：9、10、11、12 → 第 7 轮首次达到 12。第 5 轮超时（此时 cwnd=9）：ssthresh = ⌊9/2⌋ = 4（教材口径直接取 cwnd/2），cwnd = 1 重新慢启动。来源：408 统考高频题型（公开真题常考形式）。

单选2. 快重传的触发条件是（  ）

A. RTO 计时器超时仍未收到确认
B. 接收方发来 1 个重复 ACK
C. 连续收到 3 个重复 ACK，立即重传对应的报文段
D. 收到 ACK 后 cwnd 减半
答案 C。3 个重复 ACK 才基本排除"报文乱序到达"的偶然，判定为真丢包；随后走快恢复（cwnd 减半继续）而不是超时（打回 1）——这正是快重传+快恢复比超时"温和"的原因。来源：408 统考高频题型（公开真题常考形式）。

计算3. 某 TCP 连接旧 RTTs = 100ms，新测得 RTT 样本 = 80ms，α = 1/8。求新 RTTs（保留一位小数）。

先自己算，再展开对答案RTTs = (1−1/8)×100 + (1/8)×80 = 87.5 + 10 = 97.5ms。若新样本大于旧值结果会变大，公式本质是指数加权滑动平均。来源：408 统考高频题型（公开真题常考形式）。

单选4. 使用 3 比特对帧编号的 GBN 协议，发送窗口的最大值为（  ）

A. 8
B. 7
C. 4
D. 15
答案 B。GBN 发送窗口 ≤ 2ⁿ−1 = 7：若取满 8，0~7 号帧全部发出后，全部确认丢失时接收方无法区分"新 0 号帧"与"重传的旧 0 号帧"。SR 则两边都 ≤ 2ⁿ⁻¹ = 4。来源：408 统考高频题型（公开真题常考形式）。

多选5. 关于拥塞控制与流量控制，正确的有（  ）

A. 拥塞控制防止注满整个网络，流量控制防止压垮接收方
B. 发送窗口恒等于拥塞窗口 cwnd
C. rwnd = 0 后发送方仍会周期性发送探测报文
D. 慢启动"慢"指的是起点低增长快，不是增速慢
答案 ACD。发送窗口 = min(cwnd, rwnd)，B 错在只取其一；C 是零窗口探测，防止"恢复窗口的通知丢失"导致双向死等；D 是字面陷阱——慢启动指数增长其实很猛。来源：面试高频改编。

四、易错点小结

① 超时与快恢复是两条支路：超时 cwnd=1 重来，快恢复 cwnd=新 ssthresh 续跑——题目只说"丢包"时要看丢包判定方式；② cwnd 计数的"轮次"口径各教材有出入（到达 ssthresh 当轮算线性还是下轮起），以题面给的表格口径为准；③ GBN 是 2ⁿ−1、SR 是 2ⁿ⁻¹，背反是最高频失分点；④ 累积确认下"收到 ACK 200"不代表"200 号包刚到"，只代表 200 之前全部到齐；⑤ 发送窗口取 min 时别忘 rwnd 也可能成为瓶颈。
