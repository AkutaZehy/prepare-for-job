应用层：HTTP、HTTPS 与 DNS

适用岗位：全部（HTTPS 握手与 DNS 查询是面试必问） ｜ 形态：概念 + 时序图 ｜ 更新：2026-09-30
要点速记：HTTP 无状态（Cookie/Session 补状态）且明文（HTTPS 补安全）；1.1 默认长连接，2 用多路复用解决队头阻塞（HTTP 层面）；HTTPS = HTTP + TLS：非对称加密交换"会话密钥"，之后对称加密通信；DNS 解析：主机→本地服务器递归，本地→根/顶级/权威迭代，DNS 跑 UDP 53（区域传送用 TCP）。

一、知识点梳理

HTTP 特点：基于 TCP（80 端口）、无状态（服务器不记客户——用 Cookie 在客户端存状态、Session 在服务端存状态，Cookie 存 SessionID）、灵活传输任意类型数据（Content-Type 标注）、明文传输。GET 获取（幂等、参数在 URL）、POST 提交（不幂等、参数在报文体）。

常见状态码：

类别代表含义
2xx 成功200请求成功
3xx 重定向301 / 302 / 304永久移动 / 临时移动 / 未修改（走缓存）
4xx 客户端错403 / 404禁止访问 / 资源不存在
5xx 服务端错500 / 502 / 504服务器内部错误 / 网关收到无效响应 / 网关超时

版本演化：

版本核心改进
HTTP/1.0每个请求一个 TCP 连接（短连接，开销大）
HTTP/1.1默认长连接（keep-alive，一连接多请求串行）+ 管线化（串行应答，仍有队头阻塞）+ Host 头（虚拟主机）+ 分块传输
HTTP/2二进制分帧 + 多路复用（一连接并发多流，解决 HTTP 层队头阻塞）+ 头压缩 HPACK + 服务器推送
HTTP/3改跑 QUIC（UDP），解决 TCP 层队头阻塞（概念）

HTTPS = HTTP + TLS（443）。为什么混合加密：非对称（RSA）安全可公开但慢，对称（AES）快但密钥难分发——用非对称把对称密钥安全送到对端，再用对称加密通信。TLS 握手（简化四步）：

客户端                          服务端
  │ ① ClientHello: 支持的TLS版本/套件, 随机数1 │
  │ ————————————————————————————————————→ │
  │ ② ServerHello + 证书(含公钥) + 随机数2     │
  │ ←———————————————————————————————————— │
  │ ③ 验证证书 → 用公钥加密"预主密钥"发送       │
  │ ————————————————————————————————————→ │
  │ ④ 双方用 随机数1+2+预主密钥 生成会话密钥     │
  │ ←——————————— 之后对称加密通信 ——————————→ │
sequenceDiagram
    autonumber
    participant C as 客户端
    participant S as 服务端
    C->>S: ClientHello（TLS 版本/加密套件/随机数1）
    S-->>C: ServerHello + 证书（含公钥）+ 随机数2

    C-->>S: 之后改用对称加密通信

证书的作用：由 CA 签名证明"公钥确实属于该域名"，防中间人替换公钥。

DNS 域名解析：层次 = 根域名服务器 → 顶级域名（.com 等）→ 权威域名服务器；本地域名服务器（ISP 给的）代你跑腿。查询方式：主机→本地服务器用递归查询（你必须给我答案）；本地→根/顶级/权威用迭代查询（你问我，我告诉你下一个该问谁）。DNS 跑在 UDP 53（快、一次往返；区域传送主从同步用 TCP 53）。缓存：主机/本地服务器各级都有 TTL 缓存。CDN 一句话：按就近节点缓存内容，DNS 调度（CNAME）把用户引到边缘节点。

Cookie vs Session：

维度CookieSession
存放位置客户端浏览器服务端
安全性低（可见可改）较高（只暴露 SessionID）
容量/生命周期小（4KB 级）、可设长期服务端资源、默认会话级

二、考点说明

笔试选择面试必问

  • HTTPS 握手步骤排序与"为什么混合加密"——面试出现率极高。
  • DNS 递归/迭代的判断题（谁对谁递归、谁对谁迭代）。
  • HTTP 版本演化的核心改进词（长连接/多路复用）。
  • 状态码匹配、Cookie/Session 对比（多选）。
  • 引申追问：HTTP/2 的队头阻塞解决了吗（HTTP 层解决了，TCP 层还有——HTTP/3/QUIC 才根治）。

三、示例题目（点击选项即时判分 / 口述题先自答）

单选1. HTTPS 使用混合加密的原因是（  ）

A. 对称加密算法已经被淘汰
B. 非对称加密速度快，适合传大文件
C. 非对称加密安全但性能差，用它交换对称会话密钥后改用对称加密通信，兼顾安全与性能
D. 对称加密无法传输密钥
答案 C。标准答案就两句话：非对称解决"密钥怎么安全送到对端"，对称解决"大量数据的加密性能"。D 是反向干扰——对称密钥恰恰是靠非对称加密传输的。来源：面试高频改编。

单选2. 主机向本地域名服务器发起查询、本地域名服务器向根域名服务器发起查询，两者的方式依次是（  ）

A. 迭代查询 / 递归查询
B. 递归查询 / 迭代查询
C. 都是递归查询
D. 都是迭代查询
答案 B。主机对本地服务器："你必须替我查到最终结果"（递归）；本地服务器对根/顶级/权威："你不知道就告诉我下一个该问谁"（迭代，减轻根服务器负担）。来源：408 统考高频题型（公开真题常考形式）。

多选3. 关于 HTTP 各版本，正确的有（  ）

A. HTTP/1.1 默认使用长连接（keep-alive）
B. HTTP/2 通过二进制分帧实现一条连接上的多路复用
C. HTTP/2 彻底解决了 TCP 层的队头阻塞
D. HTTP/3 改用基于 UDP 的 QUIC 协议
答案 ABD。C 错——HTTP/2 只解决了 HTTP 层队头阻塞，底层 TCP 丢包时所有流还得一起等重传，TCP 层队头阻塞由 HTTP/3（QUIC）解决。来源：面试高频改编。

单选4. 用户在浏览器地址栏访问某网站，浏览器返回"404 Not Found"，其含义是（  ）

A. 服务器内部代码出错
B. 客户端没有权限访问该资源
C. 服务器找不到请求路径对应的资源
D. 网关等待上游服务器超时
答案 C。404=资源不存在；A 是 500；B 是 403；D 是 504。状态码按首位分五类：1 信息、2 成功、3 重定向、4 客户端错、5 服务端错。来源：牛客经典题。

面试口述5. 完整说出一次 HTTPS 建立连接的握手过程，并说明证书防住了什么。

参考回答①客户端发 ClientHello：支持的 TLS 版本与加密套件、随机数 1；②服务端回 ServerHello：选定套件、随机数 2、以及 CA 签发的证书（含公钥）；③客户端验证证书（用内置 CA 公钥验签，确认域名与有效期），生成预主密钥，用证书公钥加密后发送；④双方用 随机数1+随机数2+预主密钥 派生相同的会话密钥，Finished 互相验证后改用对称加密通信。证书防的是中间人替换公钥——没有 CA 背书，攻击者可以伪装服务器劫持密钥交换。加分点：提到会话密钥每次连接随机生成、抓包看到的密文走对称加密。

单选6. DNS 协议进行普通域名查询时使用的传输层协议与端口是（  ）

A. TCP 53
B. UDP 53
C. UDP 67
D. TCP 80
答案 B。普通查询一问一答，UDP 53 足够且快；主从服务器之间的区域传送（大文件级）才用 TCP 53。C 的 67/68 是 DHCP。来源：408 统考高频题型（公开真题常考形式）。

四、易错点小结

① "HTTPS 用非对称加密传输数据"是错误说法——非对称只用在握手阶段换密钥；② DNS 普通查询 UDP、区域传送 TCP，别只记一半；③ Session 比 Cookie 安全但耗服务端资源，两者常配合（Cookie 存 SessionID）；④ HTTP 无状态指"协议层不记忆"，不是"服务器完全不认识你"；⑤ 301 与 302 的区别（永久/临时）会影响 SEO 与缓存，面试偶尔追问。
