散列查找与冲突处理

适用岗位：全部（计算题：逐个插入 + ASL 手算；概念题：堆积、装填因子） ｜ 形态：散列表手算 + 方法对比 ｜ 更新：2026-09-30
要点速记：除留余数 H(key) = key % p，p 取不超过表长的最大素数。线性探测：简单但易堆积（非同义词争夺连续地址）；删除必须打标记，不能置空。平方探测 ±k²：缓解聚集，表长取 4k+3 素数可探满。链地址法：无堆积、删除方便、α 可超 1。装填因子 α = 元素数/表长，ASL 只跟 α 和探测方法挂钩，与存了哪些数、多少个无直接关系。

一、知识点梳理

散列思想：用函数 H(key) 直接把关键码算成地址，理想 O(1)。但定义域往往大于地址空间，不同 key 映到同一地址叫冲突（这两个 key 互为同义词）；不同散列值的 key 落到同一批地址也会撞——冲突不可避免，只能选好的散列函数 + 好的处理办法。

除留余数法：H(key) = key mod p，p 取不超过表长 m 的最大素数——质数让余数分布最均匀、冲突最少。表长 m=10 → p=7；m=13 → p=13；m=16 → p=13？注意 16 以内最大素数是 13，别顺手写 15（合数）。

开放定址法：冲突就按探测序列在表内另找空位。线性探测 d = 0, 1, 2, …：实现最简单，但冲突的元素连成一片，把别人（哪怕是不同散列值的 key）的初始地址也占掉，越滚越大——这就是堆积（一次聚集）；删除不能把单元置空，否则截断了后面元素的探测链，必须放"已删除"标记，查找遇到标记要继续往下走。平方探测 d = 0, 1, −1, 4, −4, …（±k²）：跳着放、显著缓解聚集；表长取 4k+3 型素数时能探测到全部位置（考选择会拿这句出判断）。

链地址法：每个地址挂一条同义词链（Java 里就是数组套链表 / HashMap 的原理）。没有堆积（不同散列值互不干扰）、删除方便（真删结点）、装填因子可以超过 1；代价是指针占空间、结点动态申请释放、缓存局部性不如连续数组。

示例（p=7，插入 8、15、22、30、7）：H(8)=H(15)=H(22)=1，同义词 8→15→22 串一条链：

桶1 ─→ 8 ─→ 15 ─→ 22 ─→ 空     (H(8)=H(15)=H(22)=1)
桶2 ─→ 30 ─→ 空

装填因子与 ASL：α = 表中元素个数 / 表长。开放定址要求 α ≤ 1，链地址无此限制。ASL（平均查找长度）取决于 α 和冲突处理方法：α 越大越挤、期望比较越多；与具体存了哪些数、元素绝对个数没有直接关系——两张 α 相同的表，规模差一倍，期望 ASL 也一样。

static final int M = 10, P = 7;    // 表长 10, 除数取不超过 10 的最大素数 7
static int[] table = new int[M];
static int[] st = new int[M];      // 0 空 / 1 占用 / 2 已删(删除标记)

static int h(int key) { return key % P; }

static boolean insert(int key) {
    int i = h(key);
    while (st[i] == 1) {                    // 被占: 线性探测下一格
        if (table[i] == key) return false;  // 已存在
        i = (i + 1) % M;
    }
    table[i] = key;
    st[i] = 1;
    return true;
}

static int search(int key) {                // 返回比较次数, -1 表示不存在
    int i = h(key), cnt = 1;
    while (st[i] != 0) {                    // 遇到真"空"才停; 遇"已删"要继续走
        if (st[i] == 1 && table[i] == key) return cnt;
        i = (i + 1) % M;
        cnt++;
        if (cnt > M) break;                 // 绕一圈没找到
    }
    return -1;
}
from collections import defaultdict

buckets = defaultdict(list)          # 链地址法: 每个桶挂一条同义词链

def h(key):
    return key % 7

def insert(key):
    if key not in buckets[h(key)]:
        buckets[h(key)].append(key)  # 冲突就往链尾挂, 无堆积

def search(key):
    for i, k in enumerate(buckets[h(key)], 1):
        if k == key:
            return i                 # 返回比较次数
    return -1

二、考点说明

笔试选择计算大题面试口述

  • 计算：给 key 序列逐个插入画散列表（写每个 key 的比较次数）、求成功/失败 ASL、算装填因子。

三、示例题目（选择题点击选项即时判分）

计算2. 表 A 长 16、已存 12 个元素；表 B 长 32、已存 24 个元素，两表都用同样的散列函数和冲突处理方法。① 求两表的装填因子；② 两表的期望平均查找长度谁大？为什么？

先自己算，再展开对答案① α(A) = 12/16 = 0.75；α(B) = 24/32 = 0.75。② 一样大。ASL 的期望只由 α 和冲突处理方法决定，α 相同则"挤的程度"相同——B 表元素多一倍但格子也多一倍，冲突概率分布不变。这正是"ASL 与 α 有关、与元素绝对个数无直接关系"的考点；考选择时若问"想让 ASL 变小最直接的手段"，答扩大表长降低 α。来源：面试高频改编。

多选3. 关于散列冲突的处理方法，下列说法正确的有（  ）

A. 线性探测法实现简单，但容易产生堆积（一次聚集）
B. 平方探测能缓解堆积；表长取 4k+3 型素数时能探测到整个表
C. 链地址法插入删除方便，装填因子可以超过 1
D. 开放定址法删除元素时，直接把该单元置空即可
答案 ABC。D 错：中间置空会截断探测链——后来查找落在链尾的元素会提前撞到"空"、误判不存在；必须放"已删除"标记，查找遇到标记得继续走，插入遇到标记可复用。A、B、C 是三种方法的标准画像：线性简单易聚、平方跳着放、链地址彻底隔离冲突。来源：牛客经典题。

单选4. 线性探测法中的"堆积（聚集）现象"指的是（  ）

A. 散列函数的计算太慢
B. 同义词之间发生冲突
C. 表中装填因子必然超过 1
D. 非同义词争夺同一批连续地址，冲突簇越滚越大
答案 D。堆积的本质：不同散列值的 key 被迫共用同一段探测序列——哪怕 H(key) 互不相同，只要初始地址落进那条"连续被占带"，就得一路探到底。B 只是普通冲突，同义词冲突不可避免、不叫堆积；堆积是线性探测特有的病，平方探测、链地址法就是冲着它去的。来源：408 统考高频题型（公开真题常考形式）。

面试口述5. 链地址法有什么优缺点？Java 的 HashMap 为什么选它而不是开放定址？

参考回答优点：① 无堆积——非同义词各挂各的链，互不干扰；② 删除方便，真删结点，不用删除标记；③ 动态性好，装填因子可以超过 1，元素数量不设上限；④ 增删频繁的场景依然稳定。缺点：① 指针占额外空间，存储密度低；② 结点动态申请释放有开销；③ 同义词全撞一条链时仍退化为 O(n) 顺序查找；④ 链式结构缓存局部性不如连续数组。HashMap 选它：删除频繁且真实、扩容 rehash 时链表/树迁移逻辑清晰，且 Java 8 起链长超阈值转红黑树，把"同义词全撞一起退化成 O(n)"的缺点也堵上了。来源：面试高频改编。

四、易错点小结

① p 是"不超过表长的最大素数"，不是表长本身（m=16 → p=13）；② 线性探测删除必须打标记，查找遇标记继续走、插入可复用标记位；③ ASL 只跟 α 和探测方法挂钩，"元素多一倍 ASL 变大一倍"是典型错误选项；④ 平方探测不保证探满全表，除非表长是 4k+3 型素数；⑤ 成功 ASL 的比较次数 = 从初始哈希地址数到实际位置（含初始那次），别从 0 数起；⑥ 堆积说的是"非同义词抢地盘"，同义词冲突本身不算堆积。
